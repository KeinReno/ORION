# Контекст агента: модуль home

Сначала прочитайте `MODULE.md` рядом. Дом: квартира, дом, дача, машина как объекты, их счётчики и показания; задачи, списки, вещи, платежи и контакты остаются в своих модулях и лишь привязываются к дому.

Каждый метод сервиса начинается с проверки членства и идёт через `PrismaService.withUser`; ссылки на другие записи проверяются на принадлежность тому же пространству; ответы собираются `toDto`, а входы валидируются zod-схемами из `shared-types`.

Межмодульные операции выполняются через публичные SDK владельцев; полные доменные модули ради ссылки/команды не импортируются. [Контракты и правила](../../../../docs/platform-api/MODULE_BOUNDARY_SDKS.md).

## Для агента (генерируется)

Блок собирается `pnpm module-docs`; руками не править.

- Точки входа: API `workspaces/:workspaceId/homes` (за `@RequireModule("home")`); панель веба `home`; код `apps/api/src/home/`.
- Права: `home.item.read`, `home.item.create`, `home.item.update`, `home.item.delete`.
- Модуль владеет: Дома (объекты), счётчики и их показания. Контакты, задачи, списки, вещи и платежи остаются в своих модулях и лишь привязываются к дому.
- Соседи: жёсткие: —; мягкие: `tasks`, `lists`, `inventory`, `finance`; чужие данные читать только через их публичный контракт, мягких соседей спрашивать через `isEnabled`.
- Расширения: плагины: `home-utilities`.
- Выключение модуля не удаляет данные; новые таблицы — только с ENABLE + FORCE RLS и записью в реестре снапшота.
