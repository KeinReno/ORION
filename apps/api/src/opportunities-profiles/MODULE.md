# Opportunities Profiles — R0.2

Optional plugin `opportunities-profiles`, default-off, extends `opportunities`. Owns people/team profiles, preferences, factual statements with explicit owner confirmation, tracks and immutable text material versions. Disable preserves all data.

Public schemas: `@orion/shared-types` opportunity-profile.ts. REST: `/workspaces/:workspaceId/opportunity-profiles`. `@orion/core` exposes typed client methods. Read allowed to permitted workspace members; write/confirm/archive owner-only. Creation requires acknowledgement of workspace-wide visibility. No per-profile private ACL in this slice.

Import integration: `public.ts` and `PROFILE_IMPORT_PORT.v1`; import checks membership, enabled Base/plugin and active profile in the caller's transaction. Profiles identified by complete relative candidate folder path, not by name matching. Import appends content-hashed materials, never updates preferences/name or confirms facts automatically. Track fact IDs and material track IDs must belong to the same workspace/profile.

FORCE RLS on four tables; composite workspace/profile foreign keys. CAS revisions for profile changes and fact state. Materials cannot be updated/deleted through this API. Profiles/materials paginated (50); manual facts bounded at 500. Snapshot includes profiles → facts/tracks → materials. Tests: opportunity-extensions.integration.test.ts, opportunity-active-resume.integration.test.ts and shared input contracts. No HH execution, LLM or automatic active-resume choice.

Explicit selection: POST `/:id/active-resume` takes `{expectedRevision, materialId: UUID | null}`. Owner-only, active profile, same-workspace/profile immutable material of type resume. Selection/clear increments profile revision atomically. Persisted inside the profile preferences JSON as reserved `_activeResumeMaterialId`, exposed separately as `activeResumeMaterialId` in public DTO; public preference inputs reject reserved keys. Updating ordinary preferences preserves reserved settings. No schema migration is needed and existing snapshots preserve the selection. Profile detail includes activeResume metadata even if the selected material is outside the first 50 versions. Import never changes selection. This setting is not send authorization or proof of factual accuracy.

Facts and tracks lifecycle (migration `20261015210000_opportunity_facts_tracks_lifecycle`): `PATCH /:id/facts/:factId/content` edits statement/category/source with CAS and **resets the fact to `unverified`** (the owner's confirmation applied to the old wording); `POST /:id/facts/:factId/archive` and `POST /:id/tracks/:trackId/archive` take `{expectedRevision, archived}` — soft archive, nothing is deleted, restore is `archived: false`; `PATCH /:id/tracks/:trackId` edits name and fact links with CAS (`OpportunityTrack.revision`). Archived facts cannot change state, be edited or be attached to new tracks; archived tracks accept no new materials. New facts/links must belong to the same profile and workspace. Materials imported from `Cover_Letters` are stored as type `proposal`, from `Портфолио` as `portfolio`; only `resume` can become the active resume.
