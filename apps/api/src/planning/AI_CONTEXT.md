# Контекст агента: модуль planning

Сначала прочитайте `MODULE.md` рядом. Тайм-блоки, Гантт с критическим путём и матрица «важно/срочно» — представления существующих задач.

Каждый метод сервиса начинается с проверки членства и идёт через `PrismaService.withUser`; ссылки на другие записи проверяются на принадлежность тому же пространству; ответы собираются `toDto`, а входы валидируются zod-схемами из `shared-types`.

## Для агента (генерируется)

Блок собирается `pnpm module-docs`; руками не править.

- Точки входа: API `workspaces/:workspaceId/planning` (за `@RequireModule("planning")`); панель веба `planning`; код `apps/api/src/planning/`.
- Права: `planning.block.read`, `planning.block.create`, `planning.block.update`, `planning.block.delete`, `planning.view.read`, `planning.preset.manage`.
- Модуль владеет: Только собственные тайм-блоки (окна фокуса и встреч), пресеты осей матрицы и недельный план времени. Задачи, проекты, вехи и события не копируются: планирование читает их через публичные контракты владельцев.
- Соседи: жёсткие: —; мягкие: `tasks`, `projects`, `calendar`, `time`; чужие данные читать только через их публичный контракт, мягких соседей спрашивать через `isEnabled`.
- Расширения: плагины: —.
- Выключение модуля не удаляет данные; новые таблицы — только с ENABLE + FORCE RLS и записью в реестре снапшота.
