# 02 — Tasks 2.0 (backend)

**Зона ответственности:** `apps/api/src/tasks/**`, Prisma-блок `BEGIN 02`,
миграции, тесты tasks. **Волна:** 2. **Никакого фронтенда.**
Локальные документы: `docs/AI_REFACTOR_MIGRATION_MAP.md` (раздел 5),
`docs/platform-api/TASK_PLANNING_LINKS.md`, `docs/extensions/AGENT_TASK_ASSIGNMENT.md`.

## Контекст

План (раздел 4.2 переписки) требует полноценную объектную модель задач.
Уже есть: `Task` (приоритет, дедлайн, assigneeId), `TaskDependency`,
`SavedTaskView`, `TaskComment`, `TaskActivity`, `AgentTaskAssignment`,
публикация правил `PublicationRule`. Модель рекуррентности у задач отсутствует
(есть только у Finance). Пользовательских полей и статусов нет.

## Задачи

### 2.1. Рекуррентные задачи

- `TaskRecurrence` (владелец — задача-шаблон): подмножество правил повторения
  (daily/weekly/monthly/weekdays + интервал + конец: после N раз / по дату /
  бесконечно). Без полного RRULE — только явный список, расширение отдельным
  этапом.
- Материализация: при завершении экземпляра рекуррентной задачи создаётся
  следующий экземпляр со сдвигом даты; логика — идемпотентна (повторное
  завершение не плодит дубли); пропущенные периоды не генерируются ретроспективно
  пачкой — только один следующий.
- Исключения: отмена отдельного будущего экземпляра (skip), перенос даты
  конкретного экземпляра не ломает цепочку.
- События: `task.recurrence.instance_completed`, `task.recurrence.skipped`.

### 2.2. Массовые операции

- Endpoint массовых операций: complete / set-status / set-priority / move-to-
  project / delete / archive / change-dates по списку id (лимит размера —
  защита от случайного «выделил всё»).
- Обязательный `dryRun`: предварительный ответ содержит per-item результат
  (ok / причина отказа: нет прав, задача в публикации, заблокирована) и сводный
  effects-отчёт; без `confirm: true` изменений не происходит.
- Транзакционность: частичное применение недопустимо без явного флага
  `allowPartial`; события на каждую изменённую задачу.

### 2.3. Пользовательские поля и статусы

- `TaskFieldDefinition` (workspace): имя, тип (text/number/date/select/multi/
  checkbox/url), опции для select, обязательность, применимость (все задачи /
  проект). `TaskFieldValue` — значения. Индексация значений для поиска.
- `TaskStatusDefinition` (workspace, ordered): имя, категория (open | in_progress
  | done | cancelled), цвет-метка (строка, не UI), isDefault, запрет удаления
  статуса, если на нём висят задачи (переназначение в дефолтный — отдельным
  подтверждением).
- Миграция: существующий enum-статус отображается в дефолтный набор статусов
  пространства; существующие данные не теряются.

### 2.4. Плановые свойства задачи

- Добавить поля: `importance`, `urgency` (0–3 или enum), `estimateMinutes`,
  `complexity` (enum low/medium/high). Отдельные от `priority` — все
  редактируются независимо. Используются матрицей (задание 04) — но таблицы
  здесь, в задачах.
- Исполнитель: человек ИЛИ ИИ-агент (уже есть assigneeId + AgentTaskAssignment).
  Добавить валидацию «одновременно нельзя» (см. AGENT_TASK_ASSIGNMENT.md) и
  поле источника исполнения для аналитики.

### 2.5. API и контракты

- Новые endpoints под общим префиксом `/api/tasks` по существующим конвенциям
  (controller/service/module); OpenAPI/типы генерируются штатно.
- **Plugin contract tasks 1.5.0 не ломать**: `plugin-contract-check` зелёный;
  новые возможности добавлять новыми слотами/версией по регламенту, а не
  изменением существующих слотов.
- Все мутации — domain events (`task.updated`, `task.status_changed`,
  `task.bulk_applied` с подробным payload).

## Критерии приёмки

1. Рекуррентная задача: завершение → ровно один новый экземпляр (интеграционный
   тест, проверка идемпотентности двойного завершения).
2. Bulk dryRun не меняет данные; confirm применяет атомарно; без прав — позиции
   отклонены с причинами.
3. Пользовательские статусы: удаление занятого статуса требует подтверждения
   переноса; дефолтный набор создаётся для существующего workspace миграцией.
4. Проверки из `00-README.md` зелёные; миграции с нуля на временной БД PASS.
5. Отчёт-блок в `docs/STATUS.md`.
