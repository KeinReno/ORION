## Задачи

### 10.1. Orion Tables (backend)

- `TableDefinition` (workspace): имя, схема колонок jsonb [{id, name, type:
  text|number|date|select|checkbox|url|formula, options?, formula?}], RLS.
- `TableRow`: значения jsonb по схеме, порядок (position), валидация типов
  сервером.
- Связанные таблицы: колонка типа `link` — ссылка на задачи/ресурсы через
  публичные контракты (task id с проверкой существования через Task SDK-контракт,
  не прямым Prisma-запросом).
- Формулы: вычисление простых формул серверно (sum/avg/count/min/max по
  колонке, ссылки на ячейки строки) при read; валидация формулы при записи
  схемы (отклонение неизвестных функций — 422).
- Импорт/экспорт: CSV (импорт в новую таблицу с маппингом колонок, экспорт);
  XLSX-экспорт — только если в проекте уже есть рантайм-зависимость, иначе
  явно отложить (не добавлять зависимости).
- События: `table.row_changed` для индексации/журнала.

### 10.2. Global Search

- Реестр провайдеров: интерфейс `SearchProvider` (модули регистрируют
  searchable entities с маппингом в единый результат: {type, id, title,
  snippet, workspaceId, updatedAt, deepLink-контракт}); адаптеры для
  существующих модулей: tasks, notes, knowledge (tsvector — задание 06),
  projects, documents.
- `GET /api/search?q=&types=&workspaceId=&from=&to=&limit=` — единый вход,
  типы фильтров, агрегированные результаты с меткой модуля-источника;
  права: провайдер сам применяет RLS/scope (инфраструктура не подменяет права).
- Контракт стабильный: модули подключаются декларативно; документация
  интерфейса — в `docs/platform-api/` (новый md, регистрация в platform-map).

### 10.3. Command Palette / реестр команд

- `commands` реестр: модули регистрируют команды {id, title, module, keywords[],
  context?, handler-контракт (route/operation)}; endpoint `GET /api/commands`
  (для включённых модулей), `POST /api/commands/:id/execute` — серверные
  операции исполняются, UI-операции возвращают маршрут-инструкцию.
- Горячие клавиши: `KeyBinding` (per user): commandId, keys, scope (global |
  module:<id> | context:<id>); конфликт-детекция API: предупреждение при
  пересечении (не блокировка), список конфликтов пользователя.

## Критерии приёмки

1. Таблица: схема с формулой sum по колонке вычисляется верно на read (тест);
   невалидная формула при записи схемы → 422; импорт CSV создаёт таблицу
   с заявленными типами колонок (интеграционный тест).
2. Global search: один запрос находит задачу, заметку и материал с
   корректными сниппетами; провайдер скрытого модуля не возвращает данные
   выключенного модуля (тест с выключенным модулем).
3. Команды: выключенный модуль не регистрирует команды; конфликт клавиш
   возвращается в API (тест).
4. Проверки из `00-README.md` зелёные; миграции с нуля PASS.
5. Отчёт-блок в `docs/STATUS.md`.

## Out of scope

Фронтенд (Palette UI, табличный рендер, подсветка), синхронизация таблиц
между устройствами (поверх Sync Core), плагины-хранилища таблиц, SQL-режим,
мульти-пространственный поиск (CrossWorkspaceGrant semantics не менять).
