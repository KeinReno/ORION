# 08 — Созвездия: серверная раскладка, связи, автокомпоновка (backend)

**Зона ответственности:** `apps/api/src/goals/**`, Prisma-блок `BEGIN 08`,
миграции, тесты goals. **Волна:** 2. **Никакого фронтенда.**
Локальные документы: `docs/GOALS_CONSTELLATIONS.md`, `docs/GOAL_CANVAS_2026-10-26.md`,
`docs/GOALS_PROJECTS_ATLAS_2026-10-26.md`.

## Контекст

Goals 2.0 реализованы: мировые координаты, автоматические отступы, камера/
масштаб хранятся локально по пространству и корневой цели. План (раздел 5
переписки): бесконечный холст — представление существующих данных; нужны
серверное хранение раскладки, управление связями, автокомпоновка, поиск нод.
Модель: `Goal`, `GoalPlan` (этапы).

## Задачи

### 8.1. Серверная раскладка

- `GoalCanvasLayout`: workspaceId, goalId (root), entries jsonb: для каждой
  ноды {entityType: goal|project|task|milestone|material, entityId, x, y,
  width?, collapsed?, updatedAt}; viewport {x,y,zoom}; visual zones
  (группы нод): {name, color?, entityIds[]} — порядок сохраняется.
- API: `GET/PUT /api/goals/:id/canvas-layout`: PUT принимает полную или
  частичную раскладку (per-entry merge по updatedAt — последняя правка
  побеждает, конфликты возвращаются в ответе для ручного разрешения,
  данные не теряются); etag/If-Match для полной замены.
- Семантика: удаление сущности не удаляет чужие ноды; нода с битой ссылкой
  помечается broken при чтении (не храним флаг).

### 8.2. Связи нод

- Связи между целями/проектами/задачами — через EntityLinksService (задание 01)
  с типами `depends_on`, `continues`, `relates_to`; endpoint
  `GET /api/goals/:id/graph` собирает ноды и рёбра для обзорного режима
  (один запрос: цель + дочерние цели + привязанные проекты/задачи + связи).

### 8.3. Автокомпоновка

- Серверный алгоритм раскладки (детерминированный): слоистая компоновка
  по графу зависимостей (topological layers, внутри слоя — по порядку
  создания), отступы по числу листьев (по образцу существующей эвристики),
  без перекрытия. Endpoint `POST /api/goals/:id/canvas-layout/auto` —
  возвращает рассчитанную раскладку; применение — только по явному PUT.
- Якоря: ноды, вручную перемещённые пользователем (dirty flag), не двигаются
  авто-раскладкой (параметр `respectManual: true` по умолчанию).

### 8.4. Прогресс и поиск

- Агрегация прогресса: `GET /api/goals/:id/progress` — по этапам (GoalPlan),
  привязанным проектам (прогресс задач — через публичный контракт Projects,
  не через внутренности) и задачам; итог с весами (этап > проект > задача).
- Поиск нод: `GET /api/goals/:id/graph/search?q=` — по названиям сущностей
  на холсте с координатами для навигации.

## Критерии приёмки

1. Частичный PUT раскладки: свежая правка одной ноды переживает параллельную
   правку другой; конфликт одной и той же ноды возвращается, обе версии
   не теряются (интеграционный тест на двух клиентах).
2. Авто-раскладка: топологический порядок не нарушен ни одной связью
   depends_on (тест с эталонным графом); ручные ноды неподвижны.
3. Прогресс цели консистентен с прогрессом проектов (тест-фикстура).
4. Проверки из `00-README.md` зелёные; миграции с нуля PASS.
5. Отчёт-блок в `docs/STATUS.md`.

## Out of scope

Фронтенд-холст (рендеринг, DnD, мини-карта), смена предметной модели целей,
Canvas модуля (универсальный инструмент — задание 10), 3D.

## Примечание для будущей Rust-очереди

Оптимизация раскладки (минимизация длин рёбер + перекрытий при большом числе
нод) — кандидат на Rust-модуль: Simulated Annealing (паттерн из
`aryashah2k/metaheuRUSTics`, MIT). На текущем этапе — детерминированный
алгоритм выше; интерфейс автокомпоновки проектировать так, чтобы оптимизатор
был взаимозаменяем (strategy-параметр, default = deterministic).
