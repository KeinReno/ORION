# Протокол передачи Orion Send, версия 1

Слушатель — только HTTPS с сертификатом узла. Проверка имени хоста не используется: личность — отпечаток сертификата. Незашифрованный HTTP для файлов нет.

Публично без токена:

- `GET /send/v1/info` — версия, nodeId, имя, отпечаток.
- `POST /send/v1/pair/request` и `GET /send/v1/pair/status/:id` — сопряжение. Код считается из обоих nonce и отпечатка, отдельной меткой от Host/Client.
- `POST /send/v1/pair/reciprocate` — вторая сторона проверяет сертификат обратным подключением и только тогда записывает взаимное доверие.

Дальше нужен заголовок `x-orion-device` и `x-orion-send-version: 1`. У изменяющих запросов есть `x-orion-request-id`. Повтор того же идентификатора за 10 минут отклоняется. Версия не 1 — ошибка `protocol_mismatch`.

`POST /send/v1/transfers` принимает манифест: `transferId`, список `{ relativePath, size, sha256 }`. Путь проходит `safeRelativePath`: без `..`, абсолютного пути, обратного слэша и зарезервированных имён Windows. Пока человек не принял передачу, байты не пишутся.

`PUT /send/v1/transfers/:id/files/:index` с `x-orion-offset` дописывает блок не больше 1 МиБ. Повтор уже подтверждённого смещения не затирает файл. Чужое смещение возвращает 409 и текущее подтверждённое число байт. `POST .../finish` читает файл с диска, сверяет SHA-256 и переносит его в папку назначения. Несовпадение — 422, частичный файл удаляется, передача помечается ошибкой.

Состояние лежит в `send-sessions.json`. После перезапуска незавершённое становится паузой. Исходящие пути исходных файлов хранятся локально, чтобы отправку можно было продолжить.

LocalSend v2 (`/api/localsend/v2/prepare-upload`, `upload`, `cancel`) включён только флагом. У их протокола нет возобновления блоков: обрыв означает повтор файла. Ясный HTTP их download API не реализуется.
