## Этапы

Порядок учитывает зависимости: оконная модель → представления/виджеты → всё остальное на них. Каждый этап — вертикальные срезы с тестами и проверкой в живом UI.

### Э0. Закрыть начатое
Проверить `project-captures`: применить миграцию на чистой БД, RLS-тест, создание записи, «Сделать задачей», выключение плагина, удаление проекта, права. Только потом коммит. Решение о переходе к универсальному `Capture` — после этой проверки (сейчас якорь — проект).

### Э1. Window Manager и единая модель представлений (P0)
1. **Реестр представлений**: `ViewDescriptor { id, kind, moduleId, instanced, modes[] }` поверх `panel-registry.ts`; режимы: встроенный / закреплённый / плавающий (dockview floating) / внешнее окно / рядом.
2. Универсальное меню «⋯ → открыть рядом / плавающим / в окне / вернуть» для любого вида (замена точечных пунктов проекта); экземпляры для заметки (`note:<id>`), задачи (`task:<id>`), подвидов проекта (обзор, задачи, доступ) — завершает ADR-0003 шаги 3–6.
3. **Панель деталей задачи** (сейчас Sheet справа): изменяемая ширина, вынос рядом/в окно; Sheet остаётся для быстрых одиночных записей.
4. Перенос порядка проектов перетаскиванием внутри раздела; жест Ctrl+drag за заголовок (ADR-0003 шаг 4) — только с клавиатурной альтернативой.
5. Синхронизация между окнами: один API + react-query; для нескольких webview — `BroadcastChannel`/событие Tauri для инвалидации кэша. Проверка: правка в окне видна в основном без перезагрузки.
6. Именованные **рабочие раскладки** («Разработка», «Финансы», «Дом»): сохранение/восстановление набора панелей (`dock-layout-key.ts` расширить до именованных профилей).
Ограничение: жест «за край экрана» в Tauri v2 не гарантирован (см. CLAUDE.md) — обязательный путь это кнопка.

### Э2. Widget Surface (P0)
Новый тип вклада рядом со слотами: `surface = fullscreen | sidebarWidget | floating | popover`. Модуль/плагин регистрирует компактный вид (`CalendarMiniWidget`: месяц с точками задач/событий по оконному запросу `events?from&to`). Контракт в `contracts.ts`, места показа — в Sidebar через реестр (правок `packages/ui/sidebar.tsx` нет — по модульному контракту; виджеты рендерит `apps/web`). Далее: таймер, «сегодня», статус AI-агентов. Включение/порядок виджетов — в Настройках; плагин выключен → виджета нет.

### Э3. Задачи: дерево и граф (P1)
Новые виды `tree` и `graph` рядом со списком/доской/матрицей (слот `tasks.views`, `TasksViewMeta`). Иерархия (`parentId`) и блокировки (`TaskDependency`) рисуются разными линиями; чистая логика раскладки — в `apps/web/lib/task-graph.ts` с vitest (циклы, межпроектные связи, фильтр по проекту). Без новых UI-библиотек (SVG руками), если не будет явного разрешения.

### Э4. Глобальные цели и несколько планов (P1)
Модель: `Goal` (workspace-scoped) → `Plan` (несколько на проект и на цель; цель может объединять планы разных проектов) → существующие `Milestone` и `Task`. Миграция + RLS + запись в `SNAPSHOT_MODEL_REGISTRY` (иначе процесс упадёт при старте — это защита). Прогресс цели — чистая функция в `shared-types` с весами планов и вехами, не счётом закрытых задач; неизвестное = `null`, а не 0. Модуль/плагин `goals` с `@RequireModule`, ADR перед кодом (вопрос: `Plan` как новая сущность или обобщение текущего плана проекта).

### Э5. Дашборд-аналитика (P2)
Единый серверный источник агрегатов (контракт `shared-types`, ADR-0002 уже задаёт аналитику проектов), режимы Личный / Проекты / Цели / ИИ, графики SVG, переход из графика в отфильтрованный список. Зависит от Э4 и Э6 (данные).

### Э6. AI Bridge (P0, независим от Э1–Э5)
1. Версионированный REST `/ai/v1` поверх существующих сервисов (никакого прямого доступа к БД): агентская идентичность (`AgentIdentity`: имя, владелец, ограниченный токен, список разрешений по модулям/пространствам, срок), аудит каждой операции (в общий журнал активности).
2. Опасные действия (удаление, массовые правки, доступ) — двухшаговые: preview → подтверждение человеком в ORION.
3. **MCP-сервер** (stdio для локальных клиентов: Claude, Cursor и т. п.; HTTP — позже) — тонкий адаптер над `/ai/v1`; инструменты: поиск, чтение/создание/обновление задач, заметок, проектов, событий; ресурсы: обзор пространства.
4. Межагентная коммуникация: очередь заданий/результатов (`AgentTask`: от кого, кому, статус, результат), права не обходятся — получатель действует под своими правами. Внутренняя шина — таблица + опрос/SSE, без брокера (ROADMAP §5: по измеренной потребности).
5. Режим `server`: агенты по умолчанию выключены, включение явное; ORION полностью работает без агентов.
Перед кодом — ADR (модель токенов, граница прав, формат аудита), пересмотр с владельцем.

### Э7. Единые связи и журнал активности
Универсальные связи уже есть (`entity_links`, `EntityLinksSection`); расширить типами `goal`, `capture`. Единый журнал: `TaskActivity` обобщить до `ActivityLog` (источник: человек/агент/система) — после Э6.

## Итог и что осталось (честно)
Живой проход в Chromium (Playwright, API + веб локально) выполнен 13 октября: дашборд и аналитика (все режимы), Идеи → «Сделать задачей», дерево и граф задач, ручка ширины панели (мышь и клавиатура), «Открыть панелью/окном» для задачи, правка в отдельном окне видна в основном, цели, вкладка «ИИ-агенты» (токен выпускается и работает в `/ai/v1`), мини-календарь, «Раскладки», плавающее окно, «Мой порядок» проектов, перетаскивание проекта из списка в рабочую область. По итогам исправлено: подвал сайдбара обрезался на невысоких окнах (теперь ссылки прокручиваются, подвал закреплён), календарь складывается в строку на низком окне, плавающим становится одна панель, а не вся группа, счётчик подзадач в дереве, цвет стрелок графа, единое понятие «просрочено».

Сделано сверх первого списка: задания между агентами (`agents:delegate`), подтверждение человеком удаления, предложенного агентом, Ctrl+перетаскивание проекта/заметки в рабочую область.

Не проверено вживую: окно Tauri (только браузер), мобильная ширина новых экранов, вынос во внешнее окно на второй монитор.
Универсальный `Capture` (идея / проблема / заметка с якорем `anchorType`+`anchorId` на проект, задачу, цель, дом, счёт, обязательство, контакт или без якоря; `workspaces/:id/captures`, блок `<CapturesSection>`, первый хост кроме проектов — «Дом»; старые роуты идей/проблем проекта остались обёртками) сделан; якоря вне проекта не каскадятся при удалении объекта. Осознанно не делалось: общий для команды порядок проектов (сейчас личный, без миграции), HTTP-транспорт MCP (нужен ADR про аутентификацию), ограничение частоты вызовов агента.

## Вкладки разделов как отдельные панели и окна (15 октября 2026)
Любая вкладка раздела (Финансы → «Счета», Дом → «Коммуналка», проект → «Идеи», Настройки → «Плагины», Рынки, Инбокс, режимы аналитики дашборда) открывается как вкладка дока и как окно ОС. Механика: `lib/section-views.ts` (id `view:<раздел>~<вкладка>[~<запись>]`), `components/section-tabs.tsx` (`SectionTabs`: меню «⧉» и Ctrl+перетаскивание; `useSectionView`: закреплённый режим без полосы вкладок), `panels/SectionViewPanel.tsx` (хост, проверяет модуль и плагин). Новый раздел с вкладками подключается так же, как `FinancePanel`. Не вкладки, а режимы отображения (список/доска, фильтры, сортировка) выносимыми не делались — аудит по всем панелям в отчёте агента.
Проверено вживую в Chromium: окна `/panel/view?instance=…` для Финансов, Дома, проекта, Настроек, Инбокса и Дашборда открываются с правильным заголовком; Рынки в пространстве с выключенным модулем показывают пояснение. Не проверено: Tauri-окно «⧉ → окном», перетаскивание вкладки Ctrl.
