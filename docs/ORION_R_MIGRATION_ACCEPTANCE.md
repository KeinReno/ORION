# ORION-R: критерии приемки полного переноса профиля

**Статус:** список требований к будущей приемке; перенос реального профиля не разрешён этим документом.
**Срез проверки:** 2026-11-09, `HEAD 5a56bd264e413fd182f9138c22c2c099cf6eae79`; в рабочем дереве есть незакоммиченные изменения.
**Связанный текущий статус:** [подготовка миграции runtime](ORION_R_RUNTIME_MIGRATION.md) и [снимок реализации](STATUS.md).

## Что сейчас подтверждено

- `createNodeBackup` и `restoreNodeBackup` покрыты обычным синтетическим интеграционным прогоном: 5 тестов прошли на отдельной временной PostgreSQL-кластерной установке после применения 153 миграций. Это проверяет обычный backup/restore, а не перенос реального профиля.
- На синтетической БД проходил один сценарий staging и восстановления в пустую цель. Проверка восстановленных строк сверяет столбцы и нормализованное PostgreSQL-представление. Это не подтверждает полноту политики по всем данным, права доступа или запуск восстановленного приложения.
- В текущем коде CLI намеренно отказывает на `stage-migration` до чтения источника. Rust-команды прямого запуска и восстановления также отказывают без изменения данных. Рабочий запуск `supervise` продолжает использовать JavaScript-лаунчер.
- Whole-node backup включает таблицы PostgreSQL и локальные файлы хранилища. Он сам по себе не включает WebDAV, Compass SQLite, `lan-devices.json` и браузерные настройки. Проверка целостности доказывает соответствие копии её манифесту, а не полноту данных исходного профиля.

**Итог:** нижеуказанные пункты остаются критериями приемки. Пройденные синтетические тесты не закрывают их автоматически.

## Инварианты до начала переноса

- [ ] **Classic остаётся независимым источником.** Не запускать миграции, санитизацию, API, фоновые задачи или восстановление на каталоге, портах, БД или файловом хранилище Classic. Источник только читается; staging, целевая БД и целевое хранилище находятся в отдельно созданной области ORION-R.
- [ ] **Отказ сохраняет источник.** При любой ошибке проверки, копирования, преобразования, миграции, восстановления, проверки связей, ACL или запуска исходная установка остаётся доступной и неизменённой. Записать контрольные суммы или независимые снимки до и после.
- [ ] **Сначала изоляция, потом обработка данных.** Восстановленная цель остаётся офлайн, без API и фоновых обработчиков, пока все проверки данных и полномочий не пройдут.
- [ ] **Неизвестная схема закрывает перенос.** Каждая таблица, колонка, файл и тип полномочия должны иметь явное правило: сохранить, преобразовать, сбросить или исключить. Неизвестные таблицы и поля нельзя молча переносить как безопасные.
- [ ] **Исключения видимы оператору.** Каждый пропущенный источник или компонент отражается в отчёте с причиной, объёмом и необходимым отдельным действием; отсутствие данных не интерпретируется как пустое значение.

## Обязательные тестовые сценарии

- Пустой профиль и полный профиль с данными во всех включённых модулях, расширениях и типах файлов.
- Источник с активными сессиями, токенами, приглашениями, внешними соединениями, grants, устройствами, очередями и lease; после staging ни одно полномочие или действие не должно незаметно активироваться.
- Неизвестная таблица/колонка и новая миграция: отказ до восстановления с понятным отчётом и без изменения источника.
- Повреждение, подмена и недоступность backup, staged copy, файла документа, каталога назначения и внешнего источника.
- Конфликт порта, занятой/непустой цели, неверных ACL, отсутствующего/повреждённого секрета и нехватки дискового пространства.
- Аварийное завершение после каждой фазы; повтор команды не должен портить источник или активировать частичную цель.
- Сравнение данных, файлов, ACL, RLS, секретной конфигурации и доменных связей после восстановления; отдельный запуск API и проверка health только после успешной сверки.
- Совместимость поддерживаемых исторических backup-форматов и отказ на неподдерживаемой версии. Успех текущего синтетического формата не означает совместимость со всеми сохранёнными архивами.

## Условия закрытия приемки

Приемка полного профиля закрывается только когда все обязательные строки таблицы имеют `PASS` с приложенными проверяемыми результатами, нет неизвестных таблиц или неучтённых источников, и реальная репетиция завершается без изменений Classic. Отдельно фиксируются `passed`, `failed`, `not run`, ОС, версии/SHA и ограничения проверки.

До этого момента `stage-migration`, `restore` и прямой Rust runtime остаются закрытыми для реальных данных. Unit-тест, синтетическая PostgreSQL-репетиция, успешный `verify` или наличие CLI-команды сами по себе не открывают перенос.
