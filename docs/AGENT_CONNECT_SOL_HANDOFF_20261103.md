# Передача Sol 6.1 — Agent Hub / Codex: автоматическое подключение и сроки доступа

Дата: 2026-11-03. Рабочая ветка: `feat/agent-connect-owner-control-20261103`.
**Это отдельная ветка от master, не часть ORION DEV PR #95. Не мерджить автоматически.**

## Причина

При попытке вручную сообщить Codex токен агента через чат Orion ответил HTTP 401. Секрет в чате не меняет переменные окружения уже запущенного MCP-процесса. В master уже существовал маршрут `POST /workspaces/:workspaceId/agent-connection/install`, но мастер выдавал токен на фиксированные 90 дней и не позволял задать роль admin; в server-mode сервер навязывал 30-дневный предел.

## Реализованный путь

1. В «Настройки → ИИ и агенты → Подключения» выбрать клиента, роль и срок (включая «Бессрочно» и произвольное число дней).
2. Если выбрана роль admin, показать отдельное подтверждение риска. Admin может выдавать только владелец рабочего пространства; после утраты этого статуса его admin-токен перестаёт действовать.
3. Для локального клиента Codex/Claude/Cursor: API создаёт новый токен и проверяет его реальным loopback-запросом `GET /ai/v1/me`. Запрос запрещено перенаправлять на нелокальный URL.
4. Положить секрет в приватный файл рядом с конфигурацией клиента, а в MCP-config записать **только путь** `ORION_AGENT_TOKEN_FILE` и `ORION_API_URL`. MCP-адаптер уже умеет читать токен из файла.
5. Сохранить существующие настройки других MCP-серверов и приватную резервную копию. Только после успешной записи отозвать более старые токены этого клиента в том же workspace. При ошибке отозвать новый токен и восстановить предыдущий credential-file.
6. Перезапустить Codex. Проверка HTTP — не доказательство, что MCP-процесс уже перечитал конфигурацию: подтвердить это отдельным вызовом `orion_get_context` внутри Codex.

**Ограничение среды:** локальный API-процесс должен работать под тем же пользователем ОС, что и Codex. Иначе файл попадёт в другой профиль. На Windows безопасность файла зависит от ACL профиля пользователя; отдельно проверить ACL на физической машине. Автоматическое подключение на удалённом сервере не поддерживается.

## Приёмка на Windows

- Выдача бессрочного admin-токена владельцем проходит без ограничения 30 дней; срок 7/30/365/произвольный можно выбрать.
- Участник с ролью member получает 403 при попытке выдать admin-токен в чужом пространстве.
- Изменение даты истечения существующего токена фиксируется в журнале; отзыв немедленно возвращает 401 при старом токене.
- Подключение Codex автоматически обновляет `%USERPROFILE%\\.codex\\config.toml` без изменения других MCP серверов.
- В конфигурации и API-ответе **нет** bearer-токена; секрет хранится в `.orion-codex-agent.token` в профиле.
- Если API отвергает новый токен (401) — установка не завершена и старые рабочие учётные данные не отозваны.
- Перезапуск Codex и реальный `orion_get_context` подтверждают связь; проверить поведение после перезагрузки Windows.
- Отдельно проверить сохранение файлов с CRLF, paths с пробелами, резервные копии, откат при ошибке записи, Windows ACL, параллельные установки.
- Проверить GitHub diff с актуальным локальным деревом Sol (ветка могла отстать); исключить PR #94 и PR #95 из случайного слияния.

## Ограничения текущего кода

Не запущены здесь ни typecheck, ни unit/integration-тесты, ни сборка. Не заявлять готовность к релизу без локальной приёмки. Внешний OAuth/HTTP-MCP, шифрование на базе DPAPI/Windows Credential Manager и cross-user установки не реализованы. Отозвать ранее опубликованный в чате токен вручную; в документации и логах его не сохранять.

После зелёных проверок Sol может интегрировать коммиты в локальную beta-ветку и собрать Windows beta. Merge master и публикация release — только с отдельного согласия владельца.
