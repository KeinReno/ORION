# ORION UI audit — 11 October 2026

This is a live UI review of the demo workspace at `localhost:3010` plus a code and test pass. It is a working checklist, not a claim that every editor command or external integration has been exercised. The established dark, compact visual language and the current module/plugin ownership in `AI_REFACTOR_MIGRATION_MAP.md` remain the baseline. Do not merge UI work with the architecture extraction or with the in-progress Compass integration.

## What was verified and fixed in this pass

| Area | Observed problem | Applied change | Live result |
| --- | --- | --- | --- |
| Browser | New tab put light text over a gray field: the translucent empty-state background was layered over the iframe's white backing. | The page container follows the ORION background; only an actual iframe has a white backing. | New tab now has readable contrast and matches the shell. |
| Inventory | `measure="prose"` squeezed 17 item cards into roughly half the workspace; long names were truncated despite ample room. | Use the bounded wide working area and responsive 2/3/4-column cards; keep the two totals compact. | At the normal viewport, cards show full names in three comfortable columns. At 720 px, they form two columns without document overflow. |
| Notes | A user-authored summary containing Markdown could bypass the cleaned list excerpt and show markup characters. | Run both summary and body fallback through `noteListPreview`; retain the two-line clamp. | List previews are plain readable text. |
| Overview | Quick task and expense defaulted to the first personal space even while the demo space was active; expense was disabled although the page showed accounts in the active space. | Prefer the active eligible space, and for expense prefer one with an account. Keep the destination visible and editable. | Both quick forms select “Демонстрационный 1”; the expense account is available. |
| Tasks | “Только мои” returned zero and displayed “Пока нет задач” even though the space had tasks. Resetting local filters also left the “без проекта” scope active. | Distinguish no assignments from no tasks, offer “Показать все задачи”, and reset search, project, and scope together. | The button reveals the existing team tasks. |
| Shell task badge | The sidebar's overdue total looked like the count of the currently selected “Только мои” task view. | Its accessible label now says the total is for the whole active space. | The count remains visible without implying it follows the personal filter. |
| Settings: modules and plugins | Every card showed technical ownership/disable details, creating a very long settings page; there was no way to find one module or plugin. | Add search and make technical details expandable per card; retain controls and defaults. | Search finds Markets by name and the project-plan plugin by “Ганта”; unmatched searches show a reset action. |
| Notes list and editor | `block` overrode `line-clamp-2`, so each preview occupied many lines; the 65-character editor measure was left-aligned in a wide pane. | Remove the conflicting display class, also in notification previews, and center the existing prose measure. | The list now shows about two preview lines per note; the editor has balanced margins without stretching the text. |
| Saved task views | A named view could store due/status/priority but the UI reapplied only search and project. “Просрочено” appeared active while showing unrelated tasks. | Complete the typed `tasks.views.bar` criteria contract, apply all stored filters in Base, add a visible due control and removable status/priority filters. ADR-0005 records the contract decision. | The live “Просрочено” view selects overdue and shows only matching open tasks; the filter unit tests pass. |
| Time dynamics | The demo has 17 hours of older records, but the 14-day chart said it would appear “after the first records”; a fetch failure used the same empty presentation. | Distinguish an empty recent window from no historical records and show a retry action on load failure. | The live panel now says the last 14 days have no records and points to the older entries below. |
| Calendar creation | The secondary `+` next to “Событие” hid the task/note creation affordance. | Give the dropdown a visible “Задача / заметка” label while keeping its icon and existing commands. | The live toolbar shows both creation paths; the dropdown exposes “Задачу со сроком…” and “Заметку на дату…”. |
| Plugin styles / Gantt | Tailwind's content paths omitted `apps/web/plugins`, so plugin-only utility classes were absent from the CSS. In Gantt, dependency paths had browser-default black fill and no stroke, producing dark wedges instead of arrows. | Scan the plugins directory in `apps/web/tailwind.config.js`. | Computed SVG style is now `fill: none` and a visible muted stroke; the live Gantt shows thin dependency arrows. Finance plugin tabs/quick entry and project plan were visually checked after regeneration. |
| Finance summary | At 720 px the two summary cards occupied only half the available panel because a four-column grid was forced once the container exceeded 576 px. | Use an auto-fitting grid that grows with the number of actual cards, including plugin contributions. | The two live cards now fill the 720 px panel evenly; transaction filters and list stay in the viewport. |

Validation after the first pass: workspace typecheck and 468 tests passed. After the second pass, full workspace typecheck passes, lint has no errors and the same two hook-dependency warnings in Calendar and Documents, and the unit suite passes 474/474 tests. The final web production build, including plugin CSS scanning, passes; the dev server was restarted and the live Notes screen loaded. The Impeccable detector reports no findings on the touched UI files. The root package has no separate `architecture-check` or `plugin-contract-check` scripts; add these to CI during the extraction rather than treating a generic typecheck as their substitute.

## Next acceptance slices

1. **Navigation and state clarity:** clarify the saved-view / “Только мои” intersection, Calendar action placement and Browser blocked-frame state. Test each state with data and without data.
2. **Content workspaces:** Notes collection/search and editor measure; Documents editor focus and DOCX/XLSX round trips. Verify split Dockview panels and a separate window.
3. **Planning and personal profile:** dense project plan/Gantt, optional Time/Habits navigation, cross-module links from Lists. Test both personal and team workspaces with the same module enabled but separate data.
4. **System pass:** settings and module controls, keyboard paths, 320–720 px layout, loading/error/empty states, visual snapshots, then the repository's full checks and a fresh production build.

Each slice should preserve the default-full UI parity required by `AGENTS.md`, keep base modules usable with optional plugins disabled, and leave persisted data intact.
