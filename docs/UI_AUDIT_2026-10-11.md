# ORION UI audit — 11 October 2026

This is a live UI review of the demo workspace at `localhost:3010` plus a code and test pass. It is a working checklist, not a claim that every editor command or external integration has been exercised. The established dark, compact visual language and the current module/plugin ownership in `AI_REFACTOR_MIGRATION_MAP.md` remain the baseline. Do not merge UI work with the architecture extraction or with the in-progress Compass integration.

## Stage 2 continuation — unsaved content navigation

An existing note's autosave can be dirty, in flight, failed or in conflict. Those states now participate in the workspace-switch draft guard. Opening another note, changing the notes view, dismissing the narrow Sheet or pressing the editor's Close button uses one in-app confirmation; cancelling keeps the editor mounted. Server-side search no longer unmounts the selected note just because it vanished from the filtered list. The list's current note is retained only as an editor snapshot, not inserted into search results. A newly created or duplicated note also stays open when it does not match the current search.

DOCX/XLSX dirty state already guarded navigation inside Documents and browser unload. It now also participates in the workspace-switch draft guard, so switching spaces cannot silently unmount an unsaved office editor. The shell now scopes unsaved drafts to their Dockview panel and intercepts the standard tab close control plus middle-click; closing the owning tab asks, closing another tab does not. The account/spaces/logout buttons also guard an unsaved draft. Native detach refuses an unsaved panel draft until saved. Other programmatic panel disposal, browser popout and non-shell navigation still need a separate end-to-end audit.

The owner-facing module and plugin switches now refuse to disable anything while an open editor has unsaved content, with a clear action to save or close the draft first. This deliberately protects all drafts rather than guessing which plugin owns an editor. A remote settings change by another owner and other programmatic panel-disposal paths remain outside this guard and need a separate end-to-end audit.

Live smoke in the demo workspace confirmed: an unsaved new note survives cancellation of a note switch and of shell logout; confirming the note switch discards only that unsaved draft; searching for a non-matching note retains the selected editor; the Dockview tab close opens the draft dialog, cancellation retains the tab and confirmation removes it. No test note was saved.

## 14 October — notification navigation

The notification bell previously treated any row with an entity ID as openable, but only tasks, notes and events actually opened. A project update therefore appeared clickable and silently stopped at the bell. It now routes all searchable record types through the existing `openEntity` entry point; budget and low-stock alerts still open their module panels. Rows without a supported destination no longer advertise an open action, while their read/delete controls remain available. A failed notification fetch has a visible retry action.

Focused verification: navigation target tests (3), web typecheck, targeted ESLint, architecture check and plugin contract check passed; the Impeccable detector found no mechanical issues in the changed UI files. The local web server was not running, so this change still needs a live click-through on a project-update notification and a narrow-width popover check. This is a navigation correction, not completion of the wider Stage 2 UI program.

The command palette also now separates quick actions from record results and rotates results among entity types. Previously, many matching local tasks could consume the 16 visible rows before a document or event search hit appeared; a task/note returned by both the local list and server appeared twice. Search results for a previous debounced query are hidden while the new query is being typed. Focused ranking tests (3), web typecheck and targeted ESLint passed. A live palette check with a workspace containing many similarly named records remains open.

Final local checks for this navigation slice: 558 unit tests, root lint (0 errors, the two pre-existing hook warnings in Calendar/Documents), web production build, architecture check, plugin contract check and targeted diff check passed. These checks do not replace the pending live click-through.
