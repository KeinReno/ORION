# Workbench — концепция агентной оркестрации (референс владельца, 2026-11-17)

Источник: концепт-экран владельца. Workbench — это НЕ существующий экран:
отдельной поверхности с таким названием в продукте нет. Ближайшая текущая
панель — `agent-hub` (скрыта в меню «Инструменты»). Концепция описывает целевую
поверхность оркестрации; этот файл фиксирует её состав и привязку к фактике кода.

## Состав концепции (с экрана)

- Левая навигация (целевая): Обзор · **Workbench (Агентная оркестрация)** ·
  Процессы · Агенты · Задачи · Данные · Знания · Интеграции · Наблюдение ·
  Журналы · Настройки.
- Шапка процесса: «Процесс: Разработка модуля», статус «В работе»,
  действия **Запустить / Остановить**, вкладки: Схема процесса · Параметры ·
  Агенты и роли · Артефакты · Метрики.
- **Схема процесса** (граф узлов): Задача (вход, REQ-427) → Агенты по ролям
  (Kimi — анализ требований DONE; Codex — разработка, в работе; Luna — ревью,
  в очереди) → Доказательства (анализ и план, 3 файла; реализация diff, 12
  файлов) → Решение (проверка качества PASS / требует доработки BLOCKED) →
  Результат (модуль готов к интеграции DONE). Легенда: активный маршрут,
  альтернативный путь, пульс агента, передача сигнала.
- **Трасса выполнения**: вертикальный таймлайн событий (процесс запущен →
  Kimi → Codex (в работе) → Luna (ожидание) → Решение (запланировано)) с
  статусами, файлами-артефактами, фильтром «Все события» и автобновлением.
- Правая колонка **Агенты**: ростер профилей (Luna, Kimi, Grok, Codex),
  лента сообщений («Вы» → распоряжение, ответы агентов, карточка прогресса
  «Процесс запущен, этап 2 из 3, 42 %»), поле «Сообщение агентам…».

## Что уже есть в коде (факт)

Бэкенд Agent Hub (`apps/api/src/modules-ext/agent-hub/`, ADR-0036/0037,
`MODULE.md`, `ROADMAP.md`) покрывает значительную часть фундамента:

- `AgentHubExecution` + журнал `AgentHubEvent` — попытки исполнения, статусы,
  отмена, CAS; `AgentHubTraceStep` — фактическая трасса (tool_call, result,
  delegation, approval_wait, note, error) с деревом шагов.
- Делегация и ветвление (`parentExecutionId`, `delegationChain`, approval gate,
  `resultSummary` — миграция `20261111200000_agent_hub_orchestration`).
- Профили агентов `AgentHubAgentProfile`, привязка credential'ов, назначение
  исполнителя на задачу, политики делегирования `AgentHubPolicy`.
- Память `AgentMemoryRecord` (scoped, версии), presence-сессии
  `AgentHubRuntimeSession` (recent/stale/closed).
- Панель `apps/web/modules-ext/agent-hub/AgentHubPanel.tsx`: очередь
  исполнений, runtime-сессии, события выбранного исполнения, отмена,
  reconcile, последние аудит-записи. Живёт в меню «Инструменты».

## Гэпы концепции (чего нет)

1. **Модель «процесса»** как схемы-графа (узлы-роли, рёбра-маршруты, этапы,
   параметры, метрики) — сущности `Process`/`ProcessRun`/`ProcessNode` нет;
   есть только плоские исполнения и их дерево делегаций.
2. **Графовая схема процесса** (2D-канвас узлов Задача→Агенты→Доказательства→
   Решение→Результат, легенда маршрутов) — UI отсутствует. Переиспользуемый
   опыт: react-flow уже используется в orion-dev ArchitectWorkbench.
3. **Единая трасса выполнения** на процесс (таймлайн по всем ветвям с
   фильтрами и автобновлением) — сейчас события показываются только по одному
   выбранному исполнению.
4. **Чат с агентами** («Сообщение агентам…», лента распоряжений и ответов) —
   нет; есть AI Bridge (сообщения/аудит) и почта агентов, но не поверхность
   оркестрации.
5. **Запустить/Остановить** на уровне процесса — автодиспетчер по роадмапу
   ещё не реализован (F2/F3); только ручная постановка исполнений.
6. **Навигация**: Workbench как верхнеуровневый раздел слева (Обзор ·
   Workbench · Процессы · Агенты · …) — отсутствует; Agent Hub спрятан в
   «Инструменты».

## Предлагаемые этапы (к сверке с владельцем)

- **W0 — видимость:** вывести Agent Hub в основную навигацию (по аналогии с
  ORION DEV); переименование панели в «Workbench» — отдельное решение.
- **W1 — трасса процесса:** сводный таймлайн событий по дереву исполнений
  (родитель + делегаты) с фильтром и автобновлением; без новых сущностей.
- **W2 — схема процесса:** read-only граф по фактическим данным исполнения
  (узлы — профили/шаги, рёбра — делегации и артефакты), не проектная схема.
- **W3 — процессы как сущность:** модель Process/ProcessRun, Запустить/
  Остановить, параметры и метрики — только после W0–W2 и отдельного ADR.
- **W4 — чат с агентами** поверх AI Bridge / почты агентов.

Правила: ничего не описывать как работающее до реализации (release rule
ROADMAP); каждый этап — отдельный срез с проверками parity; схема W2 — только
наблюдение за фактами, не «умный» граф будущего состояния.
