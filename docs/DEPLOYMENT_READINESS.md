# ORION: ворота закрытой беты и простой установки

Срез: 11 октября 2026 года. Это **чек-лист приёмки**, не утверждение, что релиз готов. Прежние CI/ручные прогоны привязаны к старым ревизиям; после последних изменений все ворота нужно проверить заново. План продукта — [ROADMAP.md](ROADMAP.md).

## Первый выпуск

Рекомендуется закрытая web-бета для доверенных пользователей на **одном сервере**: Next.js, NestJS, PostgreSQL 16, постоянное хранилище файлов, HTTPS и reverse proxy. Личное/семейное пространство и малая команда одинаково важны. Конкретная ОС и способ хостинга ещё не выбраны. GitHub Actions на Ubuntu не означает обязательный Linux-деплой. Локальный режим может сохраняться для одиночного использования; окончательная стратегия устройств описана в [SYNC.md](SYNC.md) как открытое решение.

Текущий desktop NSIS — клиентское окно; он не включает API и PostgreSQL. Выпускать его как автономный ORION нельзя, пока комплект установки не обеспечивает backend и БД или явно не подключается к уже установленному серверу.

## Блокирующие ворота

| Ворота | Критерий принятия | Проверка на релизном commit |
| --- | --- | --- |
| Чистая сборка | CI проходит install, миграции на новой БД, typecheck, lint, unit, integration, production web build и desktop export; необходимые проверки обязательны для релизной ветки | **Не подтверждено заново** |
| Права и RLS | Роль приложения без BYPASSRLS; `ENABLE/FORCE RLS`; отрицательные SQL/HTTP сценарии для membership, restricted modules, grant create/read/revoke, guessed IDs, связей, поиска, overview, backup и уведомлений; read-only grant доступен только отдельным `/shared/:grantId/...` | **Не подтверждено заново** |
| Публичный периметр | Rate-limit опирается на доверенный IP, а не клиентский `X-Forwarded-For`; HTTPS, origin, CORS, cookie/session и secret policy проверены на staging | **Не подтверждено заново** |
| Конфигурация | `ORION_MODE=server`, `NEXT_PUBLIC_API_URL`, `PUBLIC_API_URL`, `WEB_ORIGIN(S)` и секреты заданы явно; внешний клиент не обращается к localhost-fallback; БД/хранилище не публичны | **Не подтверждено заново** |
| Данные и откат | Backup охватывает БД, документные blobs/версии и необходимые ключи; restore выполнен на пустом узле; проверены контрольные суммы, доступ и ссылки; есть retention, регулярность, ответственный и сценарий отката | **Не подтверждено заново** |
| Живые сценарии | На staging два пользователя проходят регистрацию/вход, разные пространства/роли, DOCX/XLSX, финансы, связи, grant/revoke, два окна и logout; ошибки документированы | **Не подтверждено заново** |
| UI | Все основные разделы проверены на 390/720/desktop и в узкой Dockview-панели, мышью и клавиатурой; нет скрытых действий, пустого инспектора, беспричинной потери черновика | **Не подтверждено заново** |
| Установка/обновление | Есть воспроизводимый пакет/скрипт развёртывания, health/readiness, руководство первого запуска, миграций, обновления и восстановления; свежий оператор способен повторить процедуру | **Не подтверждено заново** |

Поле «не подтверждено заново» не означает, что функция отсутствует или тест падает. Оно означает, что этот документ не содержит свежего доказательства для текущего релизного commit. При выполнении ворот вносить commit, дату, команду/сценарий, результат и ссылку на артефакт. Старые результаты из истории Git не подставлять автоматически.

## Особо проверить перед релизом

- Исторически наблюдался обход grant UPDATE на уровне RLS; позже документировалось исправление. Нужна новая негативная проверка на текущей схеме, а не перенос прежнего FAIL/PASS.
- `login-rate-limit.guard.ts` и `register-rate-limit.guard.ts` раньше читали `X-Forwarded-For` напрямую. Теперь используют `req.ip`; по умолчанию заголовок не доверен, а `ORION_TRUSTED_PROXIES` принимает только явные IP/CIDR. Изолированные HTTP-тесты с ротацией подложного заголовка для входа и регистрации прошли 11 октября; на staging остаётся проверить адрес реального прокси, перезапись им входящего `X-Forwarded-For` и прямую недоступность API извне.
- `apps/web/lib/api-base.ts` ранее имел `localhost:4000` fallback. Проверить production build из другой машины.
- WebDAV-тесты в старых CI имели ошибки; причину подтвердить и исправить, не ослабляя защиту URL. Отдельно проверить восстановление файлов, а не только строк БД.
- Office round-trip: документ с формулами, форматированием, merged cells, chart/pivot и версиями не должен молча терять неподдерживаемое содержимое; если формат не поддержан, пользователь получает честное предупреждение и исходник сохраняется.

## Развёртывание и откат

1. Снять и **проверить** согласованную резервную копию до миграции. Держать секреты вне Git.
2. Подготовить PostgreSQL 16 с раздельными ролями миграций и приложения; применить `infra/postgres/init/01-app-roles.sql` и `prisma migrate deploy` на чистой staging-БД.
3. Собрать web с публичным URL API, запустить API в серверном режиме за HTTPS proxy; ограничить прямой доступ к БД и файлам.
4. Проверить `/system/health`, вход, права двух пользователей, upload/download и backup/restore.
5. При сбое остановить запись и восстановить согласованную пару БД+файлы+ключи. Старый binary сам по себе не откатывает необратимую миграцию.

После закрытой беты могут идти мобильный клиент, полный offline sync, чат, AI API, marketplace и внешние интеграции. Дефекты прав, сохранения данных и восстановления откладывать нельзя.
