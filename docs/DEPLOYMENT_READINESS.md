# ORION: путь к первому развёртыванию

Срез: 2026-10-08. Это текущий список проверок, а `RELEASE_NOTES.md` и
`SONNET_IMPLEMENTATION/12-PROGRESS.md` сохраняют историю прежних прогонов.
Статус ниже относится к этой рабочей копии; прошлый зелёный прогон не равен
новой приёмке после изменений.

## Рекомендуемый первый выпуск

Закрытая веб-бета для нескольких доверенных пользователей на **одной** ноде:
Next.js + NestJS + PostgreSQL 16, постоянное хранилище документов, HTTPS и
обратный прокси. Личное/семейное пространство и небольшая команда равноправны.
ОС сервера пока не выбрана: `ubuntu-latest` в GitHub Actions — среда
автоматической проверки, а не решение о платформе развёртывания.
Нативный desktop-инсталлятор выпускать отдельно: текущий NSIS содержит окно,
но не API и не PostgreSQL (`README.md`). Новые внешние модули Compass и
FinControl не входят в первый релиз; их план — `INTEGRATIONS_COMPASS_FINCONTROL.md`.

## Развёртывание и откат

1. Снять проверенную резервную копию **до** миграции. Сохранить предыдущие
   артефакты API/web и конфигурацию; секреты вне репозитория.
2. Запустить чистую PostgreSQL 16 с отдельной ролью миграций и ролью
   приложения без `SUPERUSER`/`BYPASSRLS`; применить роли из
   `infra/postgres/init/01-app-roles.sql`, затем `prisma migrate deploy`.
3. Собрать клиент с правильным публичным API URL. Запустить API в `server`
   режиме и Next.js за HTTPS reverse proxy. Ограничить прямой доступ к
   PostgreSQL, API и файловому хранилищу.
4. Проверить `/system/health`, регистрацию/вход, загрузку и скачивание файла,
   права двух пользователей и WebDAV backup на staging.
5. При сбое остановить запись, восстановить **согласованную** пару БД и файлов
   вместе с секретами; не считать откатом один только старый binary после
   необратимой схемной миграции. Повторить smoke и зафиксировать время потери
   данных/восстановления.

## Что можно отложить после закрытой беты

- Самостоятельную установку desktop, мобильный/offline-клиент и multi-node.
- Новый plugin runtime, архитектурную экстракцию и интеграции двух внешних
  проектов. Существующий богатый UX сохранять по правилу parity-first из
  `ORION_CONSTITUTION.md`.
- Публичную регистрацию без приглашения, пока не закрыты эксплуатационные
  вопросы abuse monitoring, поддержки и политики данных.
