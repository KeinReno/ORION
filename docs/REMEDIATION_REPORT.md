## Задачи

### P0-1 — валидация Host/Origin на API (DNS rebinding / simple-request CSRF) — выполнено 2026-11-17

- **Статус:** выполнено.
- **Что изменено:**
  - `apps/api/src/common/host-guard.ts` — новый входной guard: Host (без порта/скобок/IPv4-mapped) обязан быть loopback, именем машины, хостом LAN-режима (`PUBLIC_API_URL`) или `ORION_ALLOWED_EXTRA_HOSTS`; иначе 421 до маршрутов. Origin проверяется только при наличии заголовка: допустимы CORS-список плюс origin'ы с loopback-хостом (dev-серверы и интеграционные клиенты ходят с `127.0.0.1:<случайный порт>`); внешний домен или `null` → 403.
  - `apps/api/src/common/host-guard.test.ts` — 13 юнит-тестов.
  - `apps/api/src/configure-app.ts` — guard монтируется в `configureApp` до body-parser и маршрутов; тот же `origins`-список, что и CORS.
  - `apps/api/test/host-guard.integration.test.ts` — 5 интеграционных тестов на полном приложении.
- **Доказательства:**
  - `vitest run apps/api/src/common/host-guard.test.ts` → 13 passed.
  - `vitest run --config vitest.integration.config.mts apps/api/test/host-guard.integration.test.ts` → 5 passed (evil Host → 421, foreign Origin → 403, `null` → 403, loopback без Origin → 200, loopback Origin с произвольным портом → 200).
  - `vitest run --config vitest.integration.config.mts apps/api/test/health.integration.test.ts` → 14 passed (регрессии CORS/origin-поведения нет).
  - `tsc --noEmit` по `tsconfig.json` и `tsconfig.test.json` → чисто; eslint по изменённым файлам → 0.
- **Регрессии:** не обнаружены (см. прогоны выше).
- **Что НЕ проверено:** LAN-режим (`ORION_LAN_HOST=1`) с реальным TLS-адаптером — host из `PUBLIC_API_URL` покрыт юнит-логикой, живой LAN-прогон не выполнялся.
- **Риски и откат:** middleware удаляется одной правкой в `configure-app.ts`; обратимо.
- **Замечание для dev:** web-dev на порту 3011 не входит в CORS-дефолт (`localhost:3010`) — запросы из браузера dev-режима теперь не выполняются, как и не читались раньше. При работе через dev-web добавить в `apps/api/.env`: `WEB_ORIGINS=http://localhost:3011`.
