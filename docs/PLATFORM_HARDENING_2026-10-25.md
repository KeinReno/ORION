# Укрепление платформы — 25.10.2026

Статус: реализация в `codex/platform-hardening`; исходная база `1aa806d` после Windows beta 21. Этот этап не выпускает новый установщик. Утверждённое направление — PLATFORM.md, текущие факты — STATUS.md.

## Изменения

1. Generated ownership различает modules-ext/<id>. Architecture-check проверяет чужие модели и внутренние сервисы между подключаемыми модулями и между ними и Base. Собственные модели, Core и публичные контракты разрешены. Сохраняются прежние пределы статического анализа: *.service.ts, известные receivers, без анализа сырого SQL.
2. ^0.0.x фиксирует patch, ^0.x.y — minor, ^1.x.y — major. Нули слева, неподдерживаемые диапазоны и числа вне безопасного диапазона отвергаются. Версии/требования source JSON сохраняются генератором. При включении platform/contracts/обязательные зависимости проверяются до записи и hooks, в той же транзакции; guard не даёт default-on обойти несовместимость. Выключение сохраняет данные. ADR-0025 описывает контракт и 409 component_incompatible.
3. Contacts.merge больше не пишет Capture. Новый транзакционный EntityReferenceRegistry вызывает владельца Capture; исключение откатывает всю команду. Удалено одно существующее boundary exception, остальные не расширяются. ADR-0026; тесты проверяют перенос, rollback и чужое пространство.
4. Capability map генерируется из реестров, контрактов, владения моделями, паспортов и публичных путей. `pnpm platform-map --component <id>` показывает только нужный компонент. Unit и CI проверяют актуальность JSON. Это декларации, не тестовый сертификат и не выдача полномочий.
5. Snapshot host-контрактов больше не требует ручного bump Core при добавлении независимого modules-ext/permissions. Полные runtime-каталоги не урезаны. create:module обновляет карту автоматически.

## Проверки до эксперимента

- Typecheck прошёл; полный unit на первом срезе — 1474 passed / 189 файлов. После уточнения snapshot policy выполнен отдельный повтор контрактов/генераторов.
- Lifecycle + system-components: 8 passed; Contacts/Captures: 21 passed, включая новый rollback. Полный integration после окончательных изменений и браузерные проверки фиксируются ниже после завершения.
- ESLint: 0 ошибок / 30 существующих предупреждений на первом срезе; итоговый повтор после всех изменений обязателен.
- Architecture-check, registry, module-docs и platform-map:check проходят на первом срезе.

## Полный эксперимент нового модуля

Проводится в отдельном managed worktree, на синтетической БД и отдельных портах. Создаваемый platform-probe и его миграция не попадают в продуктовую ветку. Необходимо зафиксировать: create:module, Prisma generate/migrate, typecheck, generated integration, RLS, production API/web, браузерный CRUD и plugins-off/disable/re-enable, источник версии в system/components, список затронутых файлов и отсутствие ручных изменений Core.

До получения этих результатов полный путь не объявляется проверенным.

## Следующие ограничения

Выполняется первый перенос межмодульной зависимости; остальные записи exception-list остаются отдельными задачами. Нет автоматического обнаружения breaking changes, установки произвольного серверного кода или sandbox из массива permissions. CI по последней проверке блокировался billing; локальные результаты не следует называть зелёным GitHub CI.
