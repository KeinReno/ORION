# Orion Android — автономный клиент и управление экосистемой

**Статус:** продуктовое направление, обсужденное 18.10.2026; **Android-приложение пока не реализовано**. Приоритеты задаёт [PLATFORM.md](PLATFORM.md), текущее состояние — [STATUS.md](STATUS.md). Синхронизация — [ORION_LINK_ARCHITECTURE.md](ORION_LINK_ARCHITECTURE.md), взаимодействие ИИ — [AGENT_HUB_ARCHITECTURE.md](AGENT_HUB_ARCHITECTURE.md).

## Цель и условия

Первый физический Android для испытаний — **OnePlus**; Windows-клиент уже разрабатывается. Сейчас нет своего постоянно работающего сервера и нет возможности арендовать его. Это ограничение первого этапа, а не долгосрочная архитектура: **в будущем Orion Server должен стать основным авторитетным узлом**. Работа без сервера должна сохраняться, а переход к своему серверу не должен требовать переписывать доменные модели и протокол синхронизации.

Android — часть общей платформы, а не копия Windows Workbench. Одинаковые сущности, права, рабочие пространства, контракт Sync Engine и Agent Gateway; разные мобильные навигация, хранилище, фоновые задачи и системные интерфейсы.

## Сценарии использования

1. **Только OnePlus, офлайн:** доступные данные локальны, изменения поддерживаемых моделей сохраняются в очередь. Для неподдерживаемых моделей честно отображать online-only или read-only.
2. **OnePlus рядом с Windows:** обнаружение по Wi-Fi/mDNS или ввод адреса вручную, TLS и подтверждённое pairing, синхронизация по LAN; существующий desktop-код — основа для адаптации, не подтверждённая Android-реализация.
3. **Разные сети без сервера:** асинхронные зашифрованные изменения через настроенный WebDAV, например совместимое Облако Mail.ru, затем S3 как дополнительный провайдер. Если компьютер выключен, изменения ждут в промежуточном хранилище; управлять выключенным компьютером нельзя.
4. **Будущий Orion Server:** основной канал для согласованной работы, прав доступа и интерактивных событий; LAN и провайдерские транспорты остаются дополнительными и резервными.
5. **Несколько пользователей:** авторизация отдельно от доверия устройству, строгая изоляция пространств и проверка прав на авторитетном узле. Уже загруженные офлайн-копии нельзя гарантированно отозвать мгновенно.

## Мобильный интерфейс

Главный экран «Сегодня», пространства, проекты, задачи, календарь, заметки, списки, быстрый ввод и поиск. Раздел «Устройства»: привязка, активный транспорт, last seen, pending count, конфликты, отзыв доверия, диагностика. Раздел «Агенты»: задания, события, handoff, сообщения, согласования и действия с разрешёнными доступными runtime.

**Цветовые темы:** библиотека готовых, создание собственных, настройки по пространству, контраст и доступность. Не ограничивать дизайн чёрно-золотой палитрой. Планируемые системные интеграции: Share sheet, уведомления, камера, биометрия, виджеты, голосовой ввод.

## Архитектурные правила

- **Tauri 2 — кандидат**, не окончательно выбранная технология. Выполнить spike на настоящем OnePlus: APK, жизненный цикл, производительность, Android background work, IPC, шифрование и безопасное хранилище. Альтернатива — другая нативная оболочка над общими платформенными контрактами.
- Предлагаемое место в монорепозитории: `apps/mobile`. Нельзя автоматически переносить Windows Node/PostgreSQL sidecar и предполагать, что Android будет держать PostgreSQL.
- Mobile storage, криптография ключей и offline queue требуют самостоятельной реализации. Существующая IndexedDB-копия desktop **не** зашифрована отдельным ключом устройства, поэтому не объявлять текущее состояние безопасным mobile storage.
- `SyncTransport` доставляет пакет, Sync Engine отвечает за версии операций, idempotency, tombstones и разрешение конфликтов. В UI различать «сохранено на устройстве», «отправлено в relay», «применено вторым узлом». Backup — отдельно.
- Реальное время команд ИИ-агентам требует активного защищённого канала и работающего runtime; WebDAV не предназначен для гарантированного интерактивного управления.

## Последовательность и критерии приёмки

**После базовой стабилизации, в порядке [PLATFORM.md](PLATFORM.md):**
1. Проверить текущую сборку и Windows installer, LAN и Hybrid Sync на независимых физических клиентах/ВМ, сбои связи, конфликтующие правки и права.
2. Проверить Tauri 2 на OnePlus, сделать мобильный прототип с логином, пространством, локальным списком, pairing и offline queue. Тест: сеть выключена, приложение принудительно закрыто/перезагружено, очередь цела.
3. Выпустить полезный мобильный MVP: «Сегодня», проекты, задачи, заметки, списки, календарь, темы, поиск. Функции offline read/write объявлять только после тестов каждой модели.
4. Orion Link для Android: сначала LAN, затем один проверенный WebDAV-провайдер; потом S3. Ручное безопасное переключение — перед автоматическим failover, испытанным на split-brain.
5. Раздел «Устройства и агенты», подтверждения действий Agent Hub с телефона и затем миграция на Orion Server. Не обещать работу агентов при выключенном ПК.
6. Дополнительные приложения Android — камера, виджеты, уведомления, голосовые заметки — расширяются модулями/плагинами и платформенными capability-интерфейсами.

**MVP принят**, только если APK работает на OnePlus, локальные изменения не теряются при потере сети/перезапуске, LAN pairing и sync с Windows не создают дублей, конфликт видим, права соблюдены, есть честный статус доставки/применения, пользовательские темы работают без нарушения контраста.
