# ORION-07 — ПКМ: единые контекстные меню вместо WebView

> **Статус:** APPROVED BACKLOG / к технической сверке, не реализовано этим документом. **Дата согласования:** 27.10.2026. **Приоритет:** P0. **Область:** Весь Desktop/Workbench.  
> **Источник:** наблюдение пользователя в установленном Orion и согласование продуктовых решений. Техническая причина и соответствие текущему HEAD пока не установлены.

## Проблема

На пустом пространстве виден системный WebView/Edge-контекст («Назад», «Обновить», «Сохранить как»), вместо команд Orion.

## Задачи для реализации

- Спроектировать типизированный Command Registry + context resolver (раздел, target, выборка, доступность, права).
- Собственное меню с общими и локальными командами, подменю, разделителями, disabled reason и горячими клавишами.
- Покрыть пустые области, карточки, строки, граф/ребро, Гант/дату, дерево, редакторы, файлы и множественное выделение.
- Клавиатура Shift+F10/Menu, Escape, стрелки, Enter; общая реализация команд для кнопок/командной палитры/shortcut.

## Критерии приёмки

1. ПКМ в управляемой области Orion открывает релевантное меню; ненужное меню браузерного движка не появляется.
2. Текстовые поля сохраняют копирование, вставку и контекстный ввод/орфографию.
3. Модуль или плагин добавляет пункт только через зарегистрированный публичный extension point.

## Зависимости

Core/UI command contracts и доступность.

## Риски / ограничения

Глобальный preventDefault без учета target ломает нативные сценарии и accessibility.

## Инструкции исполнителю

1. Перед реализацией прочитать `AGENTS.md`, `docs/PLATFORM.md`, `docs/STATUS.md`, `docs/AI_REFACTOR_MIGRATION_MAP.md`, локальный `MODULE.md` и применимые ADR.
2. Сверить наличие функций/дефектов на текущем HEAD и в установленной сборке; не переписывать уже работающий механизм без доказательства необходимости.
3. Для новых API, capabilities, прав или границ Core/Module/Plugin — сначала согласовать публичные контракты/ADR; не импортировать internals другого модуля.
4. Добавить необходимые модульные/контрактные и UX/регрессионные проверки; проверить desktop/Tauri и узкий Workbench.
5. В отчёте указать commit SHA, изменённые файлы, доказательства приёмки и тесты `passed/failed/not run`. Не объявлять документ подтверждением готовности продукта.
