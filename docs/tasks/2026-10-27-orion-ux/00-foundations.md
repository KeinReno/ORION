# 00 — Единые основы взаимодействий Orion

> **Класс:** APPROVED BACKLOG / архитектурная проработка, не существующая реализация. Относится к ORION-01–11, ORION-15, ORION-19.

## Необходимые решения

1. **Command Registry.** Идентификатор команды, область доступности/фокус, параметры и target, декларация capability/permission, исполнение, ошибка, undo policy. Одни действия вызываются из кнопок, ПКМ, палитры и shortcuts.
2. **Контекстный resolver.** Различать фон/объект/текст/выделение, раздел/окно/пространство, полномочия, координату точки действия. Публичные contributions для модулей и плагинов.
3. **Drag-and-drop contract.** У каждого перетаскивания тип source, список допустимых targets, preview, валидация, commit, rollback, feedback. Не следует навязывать один низкоуровневый движок всем типам поверхностей: едины семантика, события и качество UX.
4. **Selection/Undo.** Мультивыделение, доступные клавиатурные альтернативы, история пользовательских операций и чёткие границы серверных/необратимых команд.
5. **Рабочие панели.** Раскладка/позиция/плотность/видимость — преимущественно персональное UI-состояние; бизнес-данные не переписываются перетаскиванием панели.
6. **Единая модель задач и планирования.** Родительство, топологические зависимости, срочность, важность, дедлайн, начало/конец, длительность и прогресс — разные свойства, изменение одного не должно скрытно переписывать другие.
7. **Публикация и приёмка.** UI/API commit SHA и канал сборки должны быть видимыми; приёмка Windows/Tauri не заменяется тестами веб-версии.

## Архитектурные ограничения

- Core → Contracts/SDK → Modules → Extension Points → Plugins, как в `AGENTS.md`.
- При отсутствии UI extension point оформить `NEW_EXTENSION_POINT_REQUIRED` и proposal/ADR; не связывать Base напрямую с внутренностями plugin.
- Не переписывать `docs/STATUS.md` до подтверждённой проверки состояния кода.
- Сохранять дефолтную полноту функций при текущем plugin extraction; крупный редизайн отдельно от экстракции и миграции контрактов.
- Права на операции проверяются сервером, пользовательские данные и изоляция пространств обязательны.

## Проверки платформенного среза

- Базовые команды работают одинаково через ПКМ/клавиатуру/кнопку.
- Доступность клавиатуры, разные цветовые темы, масштабирование, узкая/широкая раскладка.
- Смена пространств, offline, рестарт, ошибки API, конкурентное редактирование и восстановление отменённого действия.
- Unit + integration + visual/smoke + typecheck/lint + architecture/plugin-contract/map; явно отмечать, что не запускалось.
