## Результат
Завершить визуальную и функциональную миграцию внутренних вкладок проекта в KAIDEN Precision при сохранении существующих проектов, связей, задач, этапов, финансовых показателей, статусов и навигации. Основной обзор/доска уже частично обновлены, повторно их переписывать не нужно.

## Baseline
`apps/web/panels/ProjectsPanel.tsx` существует. По handoff: обзор «Сейчас» и доска улучшены, но вкладки проекта и полная согласованность внутренних экранов не завершены. Сначала найти фактический component tree проекта, внутренние tabs и тесты. Не переносить код из старых веток без доказанной необходимости.

## Состав работ
1. Сделать карту экранов проекта: список, доска, карточка, внутренние вкладки, связанные задачи/заметки/документы/финансы, пустые и запрещённые состояния.
2. Довести навигацию по вкладкам и редакторы до текущей оболочки: согласованные заголовки, отступы, плотность, фильтры, действия, подтверждения удаления, состояния загрузки/ошибки, достаточные hit targets.
3. Из связанного объекта открывать задачу/заметку/документ через **существующий** штатный механизм навигации и окон, без самодельных global routes. Сохранять контекст пространства и проверку доступности модулей.
4. Сохранить рабочие drag/drop, сортировки, board layout, responsive и restore state, текущие инспекторы и поп-аут окна; UI не должен запускать повторный fetch/мутацию только из-за смены оформления.
5. Вкладки без данных, ограниченные права и выключенные плагины должны деградировать корректно. Чужие workspace IDs никогда не подставлять в запросы.
6. Исправить только локальные UI-дефекты, а backend/финансы/общий inspector/токены не трогать (существующая проблема смешения валют в project spentAmount — НЕ исправлять в этом срезе, зарегистрировать отдельно).
7. Пройти ширины 320, 390, 768, desktop, большие названия, длинные списки и клавиатуру, типовую матрицу Precision/Arctic/custom.

## Граница редактирования
`apps/web/panels/ProjectsPanel.tsx` и компонентные файлы, принадлежащие **только** проектам. Общий shell, `@orion/ui`, theme engine, shared/core/types, Prisma/API, компоненты задач и прочих панелей НЕ менять самостоятельно. Если без общего изменения невозможно — занести минимальный diff в свой отчёт как блокировку координатору.

## Проверки/приёмка
- Список → карточка → каждая вкладка → связанный объект → назад без сброса пространств.
- Список и доска не потеряли сортировку, drag/drop, фильтры и сохранение.
- Участник без прав видит ожидаемые ограничения; проект другого workspace не открывается.
- Нет горизонтального overflow на 320/390; навигация доступна клавиатурой; очевидные ошибки не спрятаны.
- У каждого незавершённого до работы экрана есть сравнение «до/после» и тест ключевого перехода.
- Для проверки использовать existing unit/component/e2e тесты проектов и при необходимости дописать project-local тест. Общий e2e/production build — очередь координатора.
