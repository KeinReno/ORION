# Чат Grok 1 — библиотека и пользовательские цветовые темы

> **Статус: COMPLETED / HISTORICAL (19.10.2026).** Это ТЗ первой волны, соответствующий результат уже интегрирован PR #8–#12. Отчёт — `reports/AGENT_01.md` (в случае несоответствия номера открыть [README](README.md)). **Не выполнять повторно исходную команду для Cursor.** Текущий backlog — [STATUS.md](../STATUS.md), [PLATFORM.md](../PLATFORM.md).

## Результат
Полноценная система тем KAIDEN Orion: шесть существующих пресетов остаются доступны, пользователь может создать, редактировать, переименовать, дублировать, выбрать и удалить собственную тему; допускается назначение темы рабочему пространству с согласованным ACL и безопасным fallback. Не ограничивать продукт чёрно-золотой палитрой. Это завершение Theme Engine, а не создание второй параллельной системы.

## Исходное состояние
По `docs/STATUS.md` и handoff: существуют токены, Theme Engine, 6 палитр, личная тема через API, частичная матрица экран × палитра; нет библиотеки тем, переопределения на пространство и независимого выбора оболочки/палитры. Сначала проверить фактические файлы и уже реализованные API. Существующее повторно не писать.

## Входит в ТЗ
1. Инвентаризация текущих theme tokens, локальных/серверных настроек, UI изменения темы и схематизации в shared packages; составить карту реальных файлов.
2. Пресеты: текущие 6 без регрессии; явное различение preset/custom; live-preview без долговременной записи до сохранения; reset/cancel откатывает предпросмотр.
3. Пользовательские темы: полный CRUD/duplicate, разумная валидация цвета, запрет некорректных комбинаций, сохранение после перезапуска и на разных устройствах в рамках существующей системы предпочтений/серверной модели; не допускать потери персональных тем при миграциях.
4. Пространства: явно выбирать режим «моя тема» / «тема пространства» / «по умолчанию». Предлагаемый приоритет **временный preview → theme override workspace → личный выбор → системный default**, но фактические права и модель согласовать с текущими ADR. Только роль с правом менять настройки пространства может менять общий override. Палитра пространства должна быть доступна всем его участникам, а не ссылаться на приватный объект конкретного пользователя.
5. Независимый выбор вида оболочки и цветовой палитры, если это допускает существующая архитектура; не создавать несовместимые с темами дубли shell.
6. При отсутствии/удалении темы, потере доступа или переключении пространства — корректное определённое fallback-поведение без мерцания и бесконечного цикла сохранений; явная логика удаления темы, используемой пространством.
7. Контраст: текст обычного размера минимум WCAG AA 4.5:1, крупный текст/значимые контуры минимум 3:1, отдельно опасный текст и destructive fill; проверить темы на реальных экранах, а не только token unit-test.
8. Пройти светлую и тёмную собственную тему, длинные названия, клавиатуру, 320/390/desktop ширины. Настройки должны быть доступны пользователю без ручного JSON и перезапуска.

## Зона файлов
Theme-specific editor, management, tokens, persistence и API. **Запрещено:** массово править отдельные экраны задач/заметок/проектов/документов/календаря; менять общие Prisma/shared schemas, root styles, общую оболочку, lockfile или миграции без разрешения координатора согласно `00_SHARED_TREE_PROTOCOL.md`. В этом случае сначала подготовить минимальный контракт и блокировку.

## Обязательные проверки
- Preset → custom → save → restart/relogin → применена та же настройка.
- Workspace A override не влияет на B; при переходе A → B нет утечки чужого цвета.
- Недостаточная роль не меняет общий override, переключение члена на personal theme не переписывает настройки workspace.
- Неизвестная/удалённая/некорректная тема вызывает предсказуемый fallback.
- Все шесть пресетов, собственная light/dark, keyboard, 320/390/desktop.
- Существующие tests и smoke routes, плюс новые тесты для приоритетов и CRUD; адекватная обработка конфликтов редакций и ошибок API.

## Приёмка
Пользователь создаёт тему в интерфейсе, редактирует и назначает личную/общую, видит её после повторного входа, может вернуться к пресету; не ломаются статусные цвета и другой workspace; контраст и права проверены. Итоговый отчёт `reports/AGENT_01.md` с перечислением конкретных файлов, проверок и согласуемых shared-правок.
