# Качество, приёмка и формат отчёта пяти агентов

> **Статус: HISTORICAL — критерии приёмки волны 17–18.10.2026.** Использовать для интерпретации отчётов, не принимать указанные baseline-счётчики тестов как текущие. Новые изменения проверяются на своём SHA по [STATUS.md](../STATUS.md).

## Общий Definition of Done для каждого модуля
Срез считается готовым **только если одновременно**:
1. UI завершён на всех оговоренных экранах/состояниях, а не только на одном screenshot.
2. Исходные действия, режимы, ACL, границы workspace, disabled plugins, loading/error/empty, переключение вида и навигация не регрессировали.
3. Изменения в рамках назначенного владения, нет параллельных самодельных сервисов, тем и навигации.
4. Для каждого исправления есть воспроизводимый сценарий; тесты/скриншоты/описание ручной проверки связываются с конкретными файлами.
5. Проваленные, заблокированные и не запускавшиеся проверки отделены от пройденных.
6. Заведён собственный отчёт `reports/AGENT_0N.md` и никакие чужие рабочие изменения не откатили.

## Проверяемая матрица UI
- Тема: Precision, Arctic, custom dark; для theme engine дополнительно все шесть пресетов и custom light.
- Экран: desktop 1440, laptop 768, mobile 390 и 320, где это применимо.
- Данные: пустое / стандартное / длинные названия и плотные списки.
- Состояние: загрузка / ошибка / нет прав / модуль отключён / сохранение / конфликт.
- Ввод: мышь, последовательное Tab/Shift+Tab, Enter/Escape, возврат фокуса диалога, доступные подписи элементов.
- Навигация: объект внутри workspace, переход к связанному объекту, назад, смена workspace, сохранение доступного вида.
- Контраст: обычный текст ≥4.5:1, крупный/не-текстовые значимые элементы ≥3:1; для опасных действий — отдельный текст и fill, без цвета как единственного индикатора.

Доказательства: ссылки на конкретный тест/лог, перечень увиденных screenshot, проверка overflow и фактическая ширина. **Отсутствующий visual screenshot ≠ визуальная приёмка.** Тест без запуска ≠ тест пройден.

## Локальные проверки агента
Сначала точечные проверки собственного модуля по реально найденным package/test командами. Без новых зависимостей и без изменения общей базы. Зафиксировать exact command, exit code, pass/fail. Перед полным прогоном координатор убеждается, что все пять чатов прекратили писать файлы.

## Финальный последовательный gate — только координатор
Из корня локального проекта, когда нет конкурирующих операций, с корректно настроенным тестовым окружением:
1. `corepack pnpm typecheck`.
2. `corepack pnpm lint` (ошибок 0; warnings записать, не считать автоматически новым дефектом).
3. `corepack pnpm test`.
4. `corepack pnpm architecture-check` и `corepack pnpm plugin-contract-check`.
5. `corepack pnpm build`, `corepack pnpm build:desktop-export` — отдельно и последовательно; после сборки проверять реальные output/exit status.
6. `corepack pnpm test:integration` **только на выделенной тестовой PostgreSQL** после подтверждения правильных ENV и миграций; не на рабочих данных.
7. `corepack pnpm test:e2e:local` при наличии необходимого локального тестового окружения; известные browser limitations фиксировать отдельно и не записывать как pass.
8. Ручная матрица QA экран × палитра × разрешение; позже отдельная Windows/Tauri приёмка на чистом профиле.

**Базовая точка сравнения на 17.10** из `docs/STATUS.md`: typecheck clean, 0 lint errors / 15 warnings, 1124 unit, architecture OK, plugin 10, 466 integration + 1 skipped, 120/122 local e2e (2 известных сценария HH folder import). Это исторический отчёт по указанной ревизии, **не гарантия для нового HEAD**. После новых коммитов повторно измерить.

## Запрет ложной приёмки
Нельзя объявлять desktop готовым только потому, что `build:desktop-export` прошёл. Нужна сборка и запуск Windows Tauri/installer, локальная сеть и реальные два устройства — отдельные gates. Изменения агентских панелей не должны претендовать на закрытие этих вопросов.

## Координатор
Только один процесс последовательно интегрирует shared-правки, проводит общие проверки и фиксирует Git-коммиты с **явно указанными путями**, проверяя текущий `git diff`; не делать blanket stage/reset. Каждый модуль можно принять независимо, но статус «полный редизайн завершён» выставляется только по результатам `07_NEXT_WAVES.md`.
