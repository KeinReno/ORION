# Чат Grok 4 — редактор заметок и список документов

> **Статус: COMPLETED / HISTORICAL (19.10.2026).** Это ТЗ первой волны, соответствующий результат уже интегрирован PR #8–#12. Отчёт — `reports/AGENT_04.md` (в случае несоответствия номера открыть [README](README.md)). **Не выполнять повторно исходную команду для Cursor.** Текущий backlog — [STATUS.md](../STATUS.md), [PLATFORM.md](../PLATFORM.md).

## Цель
Закончить два тесно связанных, но **последовательных внутри одного чата** среза: сначала редактор заметок, затем представление списка файлов/папок в «Документах». Не менять бизнес-контракты хранения, экспорта и прав.

## Baseline
`apps/web/panels/NotesPanel.tsx`, `apps/web/panels/DocumentsPanel.tsx` существуют. Согласно handoff, списки и просмотр частично переведены на KAIDEN, но редактор заметки и список файлов ещё не завершены. Сначала изучить текущую реализацию, CodeMirror/editor boundary, note save, документы и component tree.

## Этап A — заметки
1. Завершить редактор: понятная структура title/content/tags/links/metadata, логика сохранения, видимые «сохраняется/сохранено/ошибка», клавиатура, предпросмотр/режимы, если уже предусмотрены контрактом.
2. Не потерять локальный ввод при серверной ошибке или конфликте ревизии; использовать существующий `saveNoteWithRevision` и текущие методы, не обходить их прямыми запросами.
3. Обеспечить работу фокуса, скролла редактора, перехода по связанному объекту, открытия рядом/в окне в рамках имеющейся инфраструктуры.
4. Фильтры/теги/архив/восстановление/удаление должны остаться функциональными; несовместимые или выключенные модули не ломают экран.
5. Не реализовывать «восстановление после аварийного завершения» локальным неконтролируемым storage — это отдельное архитектурное ТЗ второй волны.

## Этап B — документы
1. Завершить список файлов и папок: навигация, сортировка, плотность, длинные имена, иерархия, выбранные элементы, контекстные действия, пустое состояние, ошибки и загрузка.
2. Сохранить текущие upload/download, rename, move, delete/restore/purge, preview, bulk actions и существующую проверку прав. Не менять базовый storage driver/WebDAV/доступ в API.
3. Переход из проекта/поиска к документу и обратно через имеющийся механизм; без глобальной замены роутинга.
4. Предпросмотр PDF/других типов не регрессирует (внимание к Tauri CSP и blob URL). Не изменять CSP без отдельной проверки.
5. Убедиться в функциональности при пустых каталогах, больших списках, длинных названиях, ошибочном файле, конфликте операции.

## UI/доступность
Контраст в Precision, Arctic и пользовательской тёмной теме; ширины 320, 390, 768 и desktop; клавиатурный путь от списка до editor/preview и обратно; явный focus; отсутствие горизонтального overflow; не скрывать destructive действия без подтверждения. Действующие user/workspace/ACL и состояние окна сохраняются.

## Владение
`NotesPanel.tsx`, `DocumentsPanel.tsx` и компоненты, принадлежащие только этим двум модулям; свои targeted tests. НЕ трогать глобальные токены, `@orion/ui`, shell, Prisma, API contracts, общий inspector, source для календаря/проектов/задач. Любые shared-правки — BLOCKED к координатору.

## Проверки
- Заметка: создать → редактировать → сохранить → перезагрузить → прочитать; отмена/ошибка не стирает локальные правки, конфликт отображается.
- Теги, поиск/фильтры, архив/восстановление и отключённые модули без регрессий.
- Документы: папка → загрузка → просмотр → переименование/перемещение → удаление/восстановление; неправильные/чужие объекты не доступны.
- PDF preview, массовые операции и кнопки при disabled/permission cases не падают.
- UI-матрица темы × ширины, контент × пустое/много данных, клавиатура, snapshots до/после.
- Локальные тесты и точная фиксация невыполненного; глобальный e2e запускает координатор.
