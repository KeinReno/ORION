Дата 17.10.2026 · baseline `origin/master` · ветка `claude/kaiden-tz03-tasks` (облачная сессия Claude, срезы делаются последовательно, у каждого свой PR; протокол общей рабочей копии не применялся).

## Аудит baseline
Список, доска, виды, фильтры, группировки, «Только мои», автосохранение с CAS (`expectedRevision`, 409 `task_revision_conflict` с выбором «Загрузить версию сервера» / «Сохранить мою поверх»), защита несохранённого ввода (`useUnsavedDraft`, `beforeunload`, закрытие панели) и открытие задачи из проекта уже реализованы и покрыты `tasks-screens`, `task-object-context`, `projects-journey`, `object-entry-points`. Их не переделывал.

Найдено на снимках до правок (`evidence/task-detail/before`, данные `e2e/projects-seed.ts`, длинное реальное название):
- Название — однострочное поле. Длинный заголовок обрезался краем панели, прочитать его целиком было нельзя.
- Статус стоял в шапке рядом с «Задачи», таймером и «⋯». На 320 px от него оставалось «В р…», а свойства задачи были разнесены: статус наверху, остальное ниже.
- Описание прокручивалось внутри пяти строк даже при свободном экране.
- Подписи свойств оборачивали поле, поэтому экранный диктор читал имя вместе со значением («Приоритет Высокий»).
- На доске внутри проекта каждая карточка несла чип этого же проекта (передано из отчёта 02).

## Реализация
- **Название** растёт по тексту (`field-sizing: content`) и читается целиком. Это одна строка смысла: Enter не добавляет перенос, вставленные переносы становятся пробелами.
- **Статус** — первое свойство в сетке рядом со сроком, приоритетом, исполнителем и проектом. В шапке остались «Задачи», таймер и «⋯».
- **Подписи** связаны с полем через `for`/`useId`: имя поля — ровно «Приоритет», «Проект» и т. д.
- **Описание** растёт по тексту до 60 % высоты экрана, дальше прокрутка.
- **Карточка на доске проекта** без чипа проекта; в общем списке задач чип на месте.

Сохранение идёт прежним путём (тот же `set`, автосохранение, CAS); новых полей, запросов и мутаций нет.
