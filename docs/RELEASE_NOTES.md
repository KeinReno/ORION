**Release: технически READY по проверяемому P0-периметру, но формально
BLOCKED** до трёх условий, ни одно из которых не техническое:

## Что было найдено и исправлено за время работы

Реальные баги (не косметика), найденные и исправленные за весь backlog
S00–S22, по журналу `12-PROGRESS.md`:

- **Обход module restrictions через агрегаторы (S01).** `ModulesService
  .enabledSetTx` знала только про `disabled`, а не про `restricted`: сумма
  финансовой операции из restricted-для-`member`-модуля всё равно попадала в
  `spentAmount`/`activity` проекта, сама операция находилась через
  `/search`, а `entityLink` на неё отдавал `title` через `/links` — хотя
  прямой `GET /finance/*` уже честно отвечал 403. Добавлен actor-aware
  `accessibleSetTx`.
- **6 моделей отсутствовали в реестре бэкапа (S03).** `Milestone` и ещё пять
  моделей существовали в схеме и в RLS-миграциях, но не были перечислены в
  `SNAPSHOT_MODELS` — бэкап/восстановление их молча пропускали бы. Пропуск
  был только в `snapshot.service.ts`, не в схеме. Закрыто явным реестром
  (`snapshot-registry.ts`) со сверкой со схемой при старте процесса.
- **Timezone-баг терял записи времени в SQL-агрегации (S15).** Для
  часового пояса `Europe/Moscow` (+3) фильтр `startedAt >= <UTC-момент>`
  фактически сравнивался со сдвигом на 3 часа вперёд: тест на 620
  фикстурных строк показывал `count: 440` вместо `620` (440 = 620 − 180,
  180 = 3 часа × 60 записей/час — арифметика подтвердила причину).
  Исправлено явным `::timestamp`-кастом при биндинге ISO-строки.
- **Keyboard-trap во вложенных модалках (S14b).** `focus-trap.ts` насильно
  утаскивал фокус обратно в Sheet при каждом Tab, ломая именно тот сценарий
  (sidebar → list → detail → modal → close → возврат фокуса), который
  проверяет U12.
- **Race condition в habit-toggle (S16).** Конкурентный toggle одной и той же
  привычки давал 500 или тихую потерю данных вместо идемпотентного
  поведения. Найдено и исправлено.
- **Silent-каскад переноса вех без preview (S14a).** `MilestonesService
  .update` умел finish-to-start каскадный перенос зависимых вех, но делал
  это без предупреждения пользователя — ровно то, что карточка требовала не
  допускать. Добавлен read-only `reschedule-preview` эндпоинт и
  preview-gated commit в UI (Gantt).
- **Наивное суммирование финансов по разным валютам (S16).**
  `formatMoney(totalBalance)` печатал сумму без учёта валюты, молча
  подставляя ₽ по умолчанию — вводящая в заблуждение цифра для
  мультивалютного пространства. Исправлено в `FinanceSummaryRow`
  (скрывается при `balancesByCurrency.length > 1`); `ReportsView`/
  `BudgetsView` этот класс бага всё ещё содержат — задокументировано как
  открытый пункт, не скрыто.
- **Readiness false-positive в desktop-лаунчере (S18).** Прежняя логика
  запуска полагалась на фиксированный sleep/TCP-угадывание готовности API —
  заменена на реальный HTTP-poll `/system/health` (`scripts/readiness.mjs`).
- **Rebinding-уязвимость в SSRF-гарде (S05, добивочная сессия).**
  `assertPublicRemoteUrl` проверяла только hostname до резолва: публичный
  домен, резолвящийся через DNS rebinding на внутренний IP уже после
  проверки, проходил бы SSRF-заслон. Закрыто повторной проверкой резолвленного
  IP (`assertResolvedHostIsPublic`) непосредственно перед каждым сетевым
  вызовом.
- **Рассинхронизация checksum/байтов при replaceContent/restoreVersion
  (S14c, добивочная сессия).** Fault-injection тест поймал реальный баг: при
  сбое посреди замены содержимого файла live-байты могли остаться
  перезаписанными, а чек-сумма в БД — от старой версии. Исправлено
  безусловным `revertContentIfWritten` в catch-ветке (по образцу уже
  существовавшей компенсации в `update`/`remove`/`restore`).
- **Timezone-баг во all-day событиях календаря (S16).** Бакетирование
  all-day событий по дате ломалось на границе часовых поясов. Найдено и
  исправлено (`allDayAnchor`); drag&drop-related edge case для all-day
  переноса найден, но не исправлен — задокументирован как открытый пункт.

## Обновление, backup и rollback

### Обновление кода/схемы

Как и раньше: `git pull` → `pnpm install` → `pnpm db:migrate` (dev) или
`prisma migrate deploy` (production/CI, применяет все накопленные миграции
по порядку — в сессии S19 проверено с нуля, 61 миграция подряд). Изменения
контракта БД проходят через обычные Prisma-миграции в
`apps/api/prisma/migrations/`; отдельной процедуры для этого бэклога нет.

### Backup

Бэкап делает **владелец пространства** (после S02 — только эта роль) через
`SyncPanel` в веб-клиенте или напрямую эндпоинты `SyncController`
(`apps/api/src/sync/sync.controller.ts`):

- `POST workspaces/:id/sync/backup` — создаёт зашифрованный `.orion`-архив.
  С S03/S04 архив содержит не только строки БД (по явному реестру
  `snapshot-registry.ts`, версия формата снимка — 2), но и байты файлов
  документов с их версиями (`blob-backup.service.ts`), чек-суммы считаются из
  реально прочитанных с диска/WebDAV байт, не из значения, сохранённого в БД.
- `GET workspaces/:id/sync/backups` — список существующих архивов (если
  настроен внешний WebDAV-приёмник; локального автоматического расписания
  бэкапов нет — команды из README/CLAUDE.md его не заводят).
- Архивы старого формата (до S03/S04 — версия снимка 1, или без блобов)
  **осознанно отвергаются** при попытке восстановления, а не тихо
  доигрываются в неполном виде — это fail-closed поведение, не баг.
- `POST workspaces/:id/sync/restore` (dry-run превью) теперь дополнительно
  отклоняет "протухшее" превью — apply, отправленный после того, как
  манифест архива изменился между preview и apply, отвергается по
  `manifestHash` (закрыто в добивочной сессии S04), а не тихо применяется
  к другому снимку, чем показывалось в превью.

### Restore / rollback

`POST workspaces/:id/sync/restore` с `dryRun: true` — предпросмотр без
изменений (сколько строк/файлов, каких моделей); тот же запрос без
`dryRun` — применяет. Порядок восстановления внутри `SyncService.restore()`
важен и зафиксирован в коде: **сначала блобы, потом БД** — иначе при сбое
восстановления файлов клиент может получить усечённое тело файла с
Content-Length от уже обновлённой строки БД (найдено и исправлено в S04).
Восстановление файлов идёт через staging-каталог и журнал вне
`<workspaceId>/...`, так что прерванный на середине своп переживает падение
процесса — следующий вызов `restore` автоматически вызывает
`BlobBackupService.recover()` и либо продолжает, либо сообщает явное
состояние («не начато» vs «своп прерван»), не оставляет пространство в
неопределённом состоянии молча.

Rollback кода/схемы, если новая версия оказалась хуже, — стандартный git
rollback на предыдущий коммит/тег плюс, если были новые миграции, ручной
`prisma migrate resolve`/откат данных вручную (Prisma не генерирует
автоматические down-миграции — это не специфика этого бэклога, а общее
свойство используемого инструмента, ничего не добавлено сверху).

## Известные ограничения (не скрыты, перечислены явно)

- Визуальная/кликовая проверка (U01–U14) не проводилась ни разу за весь
  бэклог — нет браузерной автоматизации в среде агента (карточки S00, S12,
  S13, а также визуальная часть S11).
- Нативная desktop-сборка (`tauri build`/`tauri dev`) не запускалась ни разу
  — нет Rust/Cargo/Tauri CLI в среде агента (карточка S18). CSP-совместимость,
  рендер PDF/вложений под новым CSP и NSIS-инсталлятор не проверены вживую.
- Lists: «деструктивное копирование» из карточки S16 не реализовано —
  требуется решение продукта, не техническая доработка.
- Reports/Budgets (Finance) агрегируют суммы без учёта мультивалютности —
  известный v0-пробел (`FinanceSummaryRow` уже защищён, `ReportsView`/
  `BudgetsView` — нет), задокументирован в PLAN.md v0.29.
- Drag&drop-перенос all-day событий календаря на границе часовых поясов —
  найденный, но не исправленный edge case (S16), отдельно от исправленного
  бага бакетирования `allDayAnchor`.
- CAS/revision-защита от конфликтов есть только у заметок, не у задач/
