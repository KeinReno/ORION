# Автопубликация Tasks: первый backend-срез

Дата: 26.10.2026. Класс: implementation report. База `fdb52cc`, отдельная ветка
`codex/task-publication-rules`. Направление и согласованные владельцем решения:
[ADR-0035](adr/ADR-0035-publication-rules.md). Публичный контракт:
[PUBLICATION_RULES](platform-api/PUBLICATION_RULES.md).

## Что изменилось

Раньше публикации были только ручными. Теперь source owner может создать
остановленное правило Tasks, выбрать фильтр проектов/статусов и передаваемые поля,
просмотреть кандидатов и участников, подтвердить будущие записи и включить правило.
Изменения выбранных полей распространяются через существующий outbox; отдельная
периодическая сверка покрывает изменения вне TasksService. Нет нового транспорта,
базы данных или типа общих пространств.

Отозванные публикации не оживают, ручные не перехватываются, независимые копии
сохраняются. Пауза останавливает дальнейшие обновления, но не отзывает прежний доступ;
отзыв/удаление правила закрывает доступ. Уточнение состава раскрываемых полей требует
паузы, нового предпросмотра и согласия. Последнее подтверждение не вытесняется
частыми записями фоновых проходов в ограниченной истории.

Shared владеет конфигурацией и состоянием публикаций, Tasks — фильтрацией и чтением
задач через PublicationAdapter. Все 17 прежних архитектурных исключений остаются
закрытыми. Версии: Platform API 1.10.0, Integration 1.9.0, Event API 1.1.0.

## Проверки и среда

Использован существующий managed worktree. PostgreSQL отдельно на 127.0.0.1:5444;
синтетические `orion_rules_test`, `orion_rules_verify`, `orion_e2e`. Основной checkout,
личные данные, установленный desktop runtime и его БД 55432 не мигрировались.

- Полный unit: **1504 passed / 192 files**.
- Целевой HTTP/RLS/outbox набор до финального общего прогона: **29 passed**.
- Production API/web и Chromium: **2 passed**, новая автопубликация и прежний ручной
  сценарий с offline retry, закреплением, копией и отзывом. Проверена ширина 390px.
  Новый сценарий использует реальный outbox cron, без тестового dispatch endpoint.
- Полный typecheck passed; повторный API typecheck и production API build passed.
- Lint: 0 errors / 30 прежних warnings; изменённые новые файлы — чистый scoped lint.
- Architecture, 11 plugin contracts, module-docs и platform-map checks passed.
- Полный integration: результат финального прогона фиксируется перед merge.

В интеграциях проверены: stale preview, изменение состава участников, отсутствие
future consent, FORCE RLS, фильтры, пересечение правил, ручной отзыв, возврат задачи
в фильтр, удаление оригинала, независимая копия, потеря source ownership/target
membership, отключение Tasks без автоматического возобновления, обработка порций
правил, transient failure/retry и безопасный restore обоих концов. Дополнительный
сценарий совмещает фоновую публикацию с restore, проверяя порядок блокировок.

При расширении полного набора исправлены допущения тестового стенда: сверка за один
проход обрабатывает максимум 20 правил, диспетчер — максимум 100 доставок; тесты не
могут предполагать пустую общую очередь. Мок упавшего handler ограничен собственным
событием/подписчиком и восстанавливается после каждого теста. Лимиты production
диспетчера ради тестов не увеличивались. Генерируемый паспорт Tasks пересобран.

## Границы и передача следующему агенту

Это backend задачи №1. В установленной Windows beta24 этой функции ещё нет.
Добавлена миграция схемы (144-я в текущем дереве); доставка этой версии потребует
полного установщика. Самостоятельный релиз в этом срезе не публикуется.

Нет интерфейса управления правилами, Family/Restricted presets, назначения
согласующих, предложений правок, Knowledge rules, Android parity или Orion Link.
Не показывать эти функции доступными на основании принятого ADR.

Следующий backend-срез — согласующие и предложения смены статуса с отдельным
состоянием ожидания, operationId, CAS, текущей проверкой прав и журналом принятия.
Не поручать параллельную запись в PublicationsService, shared-types и schema.prisma
двум агентам. UI может готовить компоновку по PUBLICATION_RULES.md, используя
типизированные точки расширения; не добавлять неработающие переключатели.

Сохраняются ограничения: preview до 100 кандидатов, owner-only управление правилами,
асинхронная задержка отзыва, 20 правил на проход сверки, отсутствие межузлового
обмена. Физические Windows/Android, длительный реальный офлайн и installed upgrade
этим backend-проходом не проверялись.
