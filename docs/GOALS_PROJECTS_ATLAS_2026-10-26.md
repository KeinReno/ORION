# Цели и проекты: атлас маршрутов

Статус: реализация UX-среза от 26.10.2026. Это отдельная работа по интерфейсу; расчёт прогресса, владение данными и API целей не меняются.

Синтетические браузерные снимки: [обзор созвездий](assets/goals-atlas/overview-1440.png), [маршрут в узкой панели](assets/goals-atlas/route-390.png), [проекты по целям](assets/goals-atlas/projects-by-goals-1440.png).

## Решение

- «Цели» открываются видом «Созвездия». Список остаётся доступным для точной настройки весов, родителей и планов.
- В обзоре каждое корневое созвездие показывает результат, состояние, следующий шаг и до трёх проектов. Переход ведёт к исходному проекту, без копирования данных. Общий проект может присутствовать у нескольких целей.
- Ссылка на цель из проекта открывает её звезду внутри нужного созвездия; прежний список остаётся отдельным видом для настройки.
- На большой ширине остаётся интерактивная карта. На узкой ширине маршрут показывается читаемым вертикальным списком узлов; выбор ведёт в тот же инспектор.
- Обычное перетаскивание пустого поля двигает карту. «Расположить» меняет только личные координаты в браузере. «Изменить связи» явно включает перенос подцели и перетаскивание проекта; серверная связь действует для всего пространства. У переноса подцели уже есть отмена.
- В «Проектах» при включённом `projects-goals` появляется вид «По целям». Он использует уже отфильтрованный список проектов, показывает проект в каждой связанной цели и отдельную группу без привязки. При отключённом плагине кнопка и вид отсутствуют, обычная доска работает.

## Extension Proposal: `projects.board.grouped`

`NEW_EXTENSION_POINT_REQUIRED`: существующие слоты проекта относятся к внутренней странице проекта, а не к доске. Прямой импорт `projects-goals` в базовую панель «Проекты» нарушил бы направление зависимостей.

Предлагаемый и реализованный типизированный слот передаёт плагину только `workspaceId`, уже отфильтрованный `ReadonlyArray<Project>` и `onOpenProject`. Базовая панель владеет поиском, фильтрами, архивом, оболочкой и переключателем вида. Плагин владеет запросом целей и группировкой. Никаких новых прав или межмодульного доступа этот слот не выдаёт; `useProjectGoals` использует существующий публичный запрос. Если contribution отсутствует или плагин выключен, базовая панель не показывает переключатель.

Добавление слота подняло версию публичного plugin-контракта с `1.3.0` до `1.4.0`; обновлены снимок поверхности и сгенерированная карта capabilities.

## Критерии приёмки

1. Пустая цель, несколько проектов, общий проект у двух целей, неизвестный прогресс и длинные названия читаются в обзоре.
2. Карта и компактный маршрут выбирают один и тот же узел; история не разрешает изменять связи.
3. Личное расположение звёзд не изменяет иерархию. Перенос подцели и добавление проекта доступны только в явном режиме и сохраняют существующий серверный отказ для недопустимой связи.
4. Переходы «цель → проект → задача» и «проект → цель» открывают исходные записи.
5. С выключенным `projects-goals` проекты остаются работоспособны; данные не удаляются.
6. Проверить desktop, узкую dock-панель, клавиатуру, длинные названия, историю, ошибку загрузки целей и тему.

## Границы

Контекстное меню по правому клику, жест pinch на сенсорном экране, переход камеры с анимацией и автоматический еженедельный обзор не включены в этот срез: для них нужны отдельные проверки нативного ввода и состояния доступности. Явные действия через инспектор и кнопки остаются основным путём.
