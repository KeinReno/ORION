Скопировать агенту либо использовать этот файл как точку входа:

> Прочитай CLAUDE.md и docs/SONNET_IMPLEMENTATION/23-UNIVERSAL-CONNECTED-CORE.md, затем 24-CONNECTED-CORE-BACKLOG.md и 25-OFFICE-REVIEW.md. Реализуй согласованную модель: личные сферы Дом/Работа, пространства-владельцы данных, универсальные модули, типизированные связи, контекстные действия, независимые окна и личные раскладки. Начни с U00 — проверь реальное состояние кода и составь карту существующих связей/прав/backup. Не считай историю PROGRESS доказательством закрытия дефектов.
>
> Для ближайшего среза исправь подтверждённые потери офисного содержимого F01–F04 и защиту несохранённого ввода F05. В evidence приложены четыре падающих regression tests, их нужно перенести в постоянные suites и добиться PASS, не ослабляя assertions. Офисный путь остаётся native без Docker/Document Server; не возвращай ONLYOFFICE и не добавляй real-time coediting. Диаграммы и сводные должны сохраняться и отображаться, наличия XML в первом экспорте недостаточно.
>
> Затем последовательно выполни U01 и U02: реестр типов/связей, серверные проверки обоих объектов и общий picker/связанные материалы на note↔task и document→transaction. Каждый этап — отдельный законченный срез с проверками и записью в 12-PROGRESS. Остальные задачи бери по зависимостям 24. Не реализуй весь backlog одной массовой переделкой.
>
> Сохрани существующие предметные модели и работающие функции. Не заменяй их универсальной JSON/EAV базой. Ссылка не даёт доступ, перемещение панели не переносит данные, обзор не дублирует деньги. Межпространственный доступ — отдельный U09, не ослабление RLS. Будущие Контакты/CRM/Имущество не строить до базового сквозного сценария U07. Вложения и офисные документы интегрировать с общими связями после устранения потерь содержимого.
>
> Проверяй реальные отрицательные сценарии: права, конкуренцию, повтор запроса, восстановление, смену workspace/окна, save→reopen→save. Используй отдельную тестовую БД/синтетические файлы; не редактируй реальные пользовательские материалы ради проверки. Не откатывай чужой dirty working tree. В финале каждого среза сообщи изменения, команды/результаты, NOT RUN, оставшиеся риски и следующий шаг. Работай по уже согласованным решениям; новые покупки/внешние передачи файлов не подразумеваются.
