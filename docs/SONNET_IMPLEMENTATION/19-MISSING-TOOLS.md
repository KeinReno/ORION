# Каких инструментов не хватает ORION

Дата: 2026-09-22. Владелец согласовал это направление развития; это не поручение реализовать всё одновременно. Детальные контракты новых инструментов ещё требуют отдельных задач. Офисное редактирование дополнительно согласовано и конкретизировано в 20-DOCUMENT-EDITORS и 21-OFFICE-IMPLEMENTATION. Личный и командный сценарии равноправны. Основа: Prisma schema, каталог plugins, 06-MODULES, 07-PLUGINS и результаты проверки 18-REVIEW-FINAL-PASS. Отсутствие самостоятельной модели не доказывает отсутствие любого похожего UI; ниже различаются новые сущности и развитие существующих возможностей.

## Задача и границы

Пользователь хочет вести личную работу и работу небольшой студии в одном продукте. Желаемый результат: захватить входящее → выбрать работу → выделить время → выполнить → передать результат → проверить итоги. Для студии дополнительно: клиент → договорённость → проект → согласование → оплата. Сейчас многие части существуют, но целостные процессы и отдельные бизнес-сущности ещё не оформлены.

Критерий успеха: пройти эти цепочки без повторного ручного ввода одних данных и без таблицы вне ORION. Предлагаемые изменения затрагивают задачи, события, проекты и новые клиентские/согласовательные записи в конкретном workspace. Личные обзоры приватны по умолчанию; командное планирование не раскрывает личные пространства. Создание связанных записей требует превью и защиты от повторного выполнения. Внешняя отправка — отдельное явное действие, не побочный эффект.

Порядок ниже — гипотеза по устройству продукта, не результат исследования спроса. Coverage gap: proposed `rule/prioritize-complete-workflows`, категория Product strategy: приоритет определяется завершением рабочего сценария, а не числом новых разделов. Применяется ко всем предложенным приоритетам. Перед большой реализацией проверить на реальной неделе пользователя и одном проекте студии.

## Первая очередь после исправления ошибок из 18-REVIEW-FINAL-PASS

| Инструмент | Что уже есть | Что добавить минимально | Где разместить |
|---|---|---|---|
| План дня и загрузка недели | Задачи с оценками/датами, календарь, учёт времени | Несколько временных блоков для одной задачи; свободное время с учётом встреч; запланированная нагрузка против доступных часов; перенос блока без изменения дедлайна | Сегодня/Календарь; командная загрузка внутри Проектов |
| Обзор недели | Dashboard, Inbox, проекты, отчёты | Последовательный разбор входящих, просроченного, проектов без следующего действия и плана следующей недели; сохранять решения обзора | Режим существующего Dashboard, без нового верхнеуровневого модуля |
| Шаблоны проектов | Шаблоны заметок; задачи, вехи и зависимости | Создавать проект из набора вех, задач, чек-листов и стартовых документов; даты относительно старта; превью; роли вместо прежних исполнителей | Расширение Проектов |
| Клиенты и контакты | Проекты и финансовые связи; самостоятельных Client/Contact в схеме нет | Организация/человек, контакты, ответственный, связанные проекты и документы, следующее действие; минимальные этапы обращения при необходимости | Небольшой отключаемый модуль Контакты |

Решение о размещении и повторном использовании: `rule/smallest-intervention`. Для каждого инструмента сначала использовать существующие сущности; не создавать вторую модель задач, событий или денежных операций.

Детали первой версии:

- Планирование: отдельно хранить срок задачи, запланированные интервалы и фактически отработанное время. Не считать диапазон Ганта полной занятостью человека. Отсутствующая оценка — «не оценено», а не ноль. Личная загрузка не публикуется команде автоматически. `rule/name-object-scope-consequence`, `rule/cover-reachable-states`.
- Обзор: первый экран показывает количество объектов для разбора, каждый шаг допускает пропуск, возврат сохраняет прогресс. После обзора остаются выбранные следующие действия. Не создавать новую копию списка задач. `rule/smallest-intervention`, `rule/preserve-user-input`.
- Шаблоны: перед применением показать создаваемые объекты, даты и назначения; повтор отправки не создаёт второй проект. При отсутствии участника запросить назначение, не подставлять случайного. Правки шаблона не меняют уже созданные проекты. `rule/name-object-scope-consequence`, `rule/cover-reachable-states`.
- Контакты: контакт не равен пользователю ORION и не получает доступ к workspace. Связь с проектом не отправляет приглашение. По умолчанию карточка доступна только по внутренней политике workspace. `rule/name-object-scope-consequence`.

## Вторая очередь: завершить работу студии

| Инструмент | Минимальный результат | Граница |
|---|---|---|
| Согласование результата | Версия документа/результата → назначенный проверяющий → согласовано или нужны изменения → комментарий и история | Сначала внутреннее согласование. Новая версия не наследует одобрение старой. Внешний гостевой доступ требует отдельной политики |
| План оплат по проекту | Сумма и дата ожидаемого платежа, статус, привязка фактических поступлений, частичная оплата | В проекте уже есть бюджет, ставка, валюта и операции. Не дублировать их и не выдавать ожидание за поступление |
| Встречи и решения | Из события открыть заметку по шаблону; зафиксировать решения и явно создать поручения с ответственными | Развить Calendar/Notes/Tasks. Не нужен отдельный чат или сервис видеозвонков |
| Импорт и перенос данных | CSV/Markdown для выбранных сущностей, сопоставление полей, превью, дубликаты, отчёт об ошибках | Начать с одного формата и модуля, например финансовых операций; повторный импорт не размножает данные |

Правила: размещение — `rule/smallest-intervention`; согласование и привязка платежа — `rule/name-object-scope-consequence`; частичные оплаты, смена версии, ошибки импорта — `rule/cover-reachable-states`; сохранение текста встречи при сбое — `rule/preserve-user-input`.

Счета клиентам и генерацию коммерческих документов можно добавить после определения реквизитов, нумерации и нужных форматов. Сейчас это не спецификация бухгалтерского или юридического продукта.

## Позже и по подтверждённому спросу

- Автоматизации: одно событие → условие → действие. Например, создать задачу после перехода проекта на этап. Предпросмотр, журнал, повтор без дубликатов, проверка текущих прав, защита от циклов. Расширение поверх готовых модулей; не marketplace произвольного кода. `rule/smallest-intervention`, `rule/cover-reachable-states`.
- Захват извне: отправка текста/ссылки во Входящие из браузера или мессенджера. Начать с одного канала, сохраняя источник, выбранный workspace и статус доставки. Нынешние исходящие уведомления не равны входящему захвату. `rule/name-object-scope-consequence`, `rule/error-states-recovery`.
- AI-помощь: черновик задач из заметки, сводка проекта, поиск по разрешённым материалам. Сначала превью и ручное применение; явные границы передаваемых данных и расходов. Не запускать до исправления контроля доступа. `rule/name-object-scope-consequence`.

Полный offline sync, собственный чат, видеозвонки, универсальный no-code конструктор и произвольные плагины не входят в предложенную первую очередь: потребуют самостоятельной архитектуры и отвлекут от перечисленных сценариев. Это рекомендация по объёму, а не запрет на будущее.

## Общая приёмка будущих инструментов

Для каждого сценария определить и проверить загрузку, пустое состояние с первым действием, частичные/устаревшие данные, ошибку с повтором, недостаток прав, сохранение ввода и безопасное повторение записи. Управление доступно клавиатурой. Общие правила: `rule/cover-reachable-states`, `rule/empty-state-action`, `rule/preserve-user-input`, `rule/keyboard-complete-flow`.

Предлагаемый порядок: исправить три подтверждённых дефекта → планирование и обзор для личной работы + контакты для студии → шаблоны → согласования/оплаты → импорт → автоматизации по реальным повторяющимся действиям. Новые предложения не отменяют незавершённые карточки текущего backlog.
