# UX: оболочка и рабочие потоки

> Актуальные продуктовые решения владельца по фронтенду от 2026-10-08:
> [`../FRONTEND_WORKSPACE_SPEC.md`](../FRONTEND_WORKSPACE_SPEC.md). Сферы —
> необязательные личные группы в меню, не уровень иерархии; иконки модулей
> всегда видны, названия пользователь включает при желании. Последующие
> предложения ниже применять только если они не противоречат этой спецификации.

## Информационная архитектура

Сохранить sidebar и постоянный Workbench. Sidebar ориентирует по задачам пользователя:

```text
ORION                       [пространство ▾]
Поиск / команды             Ctrl+K
Сегодня
Входящие                    7

РАБОТА
Задачи
Проекты
Календарь
Время

МАТЕРИАЛЫ
Заметки
Документы

УЧЁТ                         (если включены)
Финансы
Склад

ЛИЧНЫЕ ИНСТРУМЕНТЫ           (название группы, не обещание private ACL)
Привычки
Списки

Уведомления
Настройки
```

Название «Личные инструменты» допустимо только с понятной видимостью данных. Если привычки/списки общие для workspace, предпочтительно назвать группу «Рутины». Не создавать ложного обещания приватности. Конкретный порядок сохранить пользовательским, если настройка уже существует.

Backup предлагается переместить в Настройки → Данные и восстановление; существующий panelId sync сохранить как alias для сохранённых layout/deep links. В текущем panel-registry UI-название уже «Резервные копии» — его сохранить, не выполнять фиктивное переименование. Двусторонней синхронизации пока нет.

Основание: `rule/preserve-mental-model`, `rule/smallest-intervention`, `rule/name-object-scope-consequence`.

## Пространства и первый запуск

- Аккаунт идентифицирует человека; workspace определяет набор данных и участников. Не называть workspace физической папкой: файлы частично на диске, записи — в PostgreSQL.
- После входа возвращать в последнее доступное пространство; если его нет, открыть выбор. Если пользователь осознанно вышел к выбору, не перенаправлять обратно автоматически.
- Новое пространство: имя и профиль personal/team, затем сразу рабочая поверхность. Приглашения, фон, WebDAV и уведомления — позже по месту.
- Личное и командное пространства визуально различаются названием/иконкой и участниками, а не совершенно другой оболочкой.
- Переход между пространствами проверяет dirty editors. Выбор: сохранить, оставить локальный черновик, отменить переход. Не смешивать данные в одной открытой форме.

Правила: `rule/value-before-interruption`, `rule/preserve-user-input`, `rule/preserve-mental-model`.

## Сегодня

Заголовок: дата и текущий scope. Главный элемент — захват мысли. Далее «Мой фокус», просроченное, ближайшие события, входящие для разбора. Руководитель может перейти к обзору команды; это отдельный вид, а не замена персонального Сегодня.

Фокус содержит максимум 3 выбранных задачи как продуктовый default; полный список доступен по ссылке. Не терять существующие выбранные задачи при смене default. Просрочка видна отдельной группой, но не красит весь экран. День сменяется без reload, включая sleep/wake и timezone change.

Каждый блок загружается независимо. Ошибка календаря не скрывает задачи. Сумма финансов не показывается без доступа; отсутствие прав не превращается в «0 ₽». `rule/one-primary-action`, `rule/cover-reachable-states`.

## Универсальная модель списка и деталей

Header: название, count при известной полноте, один primary CTA. Toolbar: поиск, компактные фильтры, вид, меню второстепенных действий. Контент: список/доска/таблица. Детали: master-detail либо sheet в зависимости от ширины **панели**, а не только окна.

При закрытии деталей восстановить выбранную строку и позицию прокрутки. Создание и редактирование используют одну форму. Вложенные модальные окна запрещены: выбор связанного объекта inline/combobox либо переход внутри одного sheet.

Правила: `rule/inline-before-modal`, `rule/no-nested-modals`, `rule/structure-before-containers`.

## Реестр состояний

| Состояние | UI и действие |
|---|---|
| Первичная загрузка | Skeleton реальной геометрии, доступное сообщение |
| Refresh | Старый контент остаётся, небольшой статус обновления |
| Данных ещё нет | Объяснение объекта и кнопка первого действия |
| Фильтр дал 0 | Сохранить фильтры, предложить сброс |
| API недоступен | «Не удалось подключиться», retry; данные не объявлять пустыми |
| Частичный ответ | Видимые успешные блоки + ошибка конкретного блока |
| Нет доступа | Не раскрывать содержимое/название запрещённого объекта |
| Модуль выключен | Объяснить; owner может включить, member видит путь к владельцу |
| Dirty | «Есть несохранённые изменения», уход безопасен |
| Saving | Стабильная кнопка/ширина, busy и защита от double submit |
| Saved | Только после ответа сервера |
| Save error | Ввод сохранён, повторить/скопировать |
| Conflict | Локальная и серверная версии, явный выбор, без автоoverwrite |
| Delete pending | Конкретный объект и последствия, повторный submit заблокирован |

Правила: `rule/cover-reachable-states`, `rule/loading-stable-labels`, `rule/error-states-recovery`, `rule/preserve-user-input`.

## Разрушительные действия

Мягкое удаление/архивация → мгновенно и undo, если сервер реально умеет вернуть. Не изображать undo только возвратом строки в кэш. Постоянное удаление → ConfirmDialog с предметным глаголом. Restore всего workspace → owner, preview, проверка актуальности preview, защитный backup и ввод имени/идентификатора пространства.

Обычное перемещение файлов не требует type-to-confirm само по себе: количество объектов, папка назначения, существующие конфликты и возможность отмены важнее количества кликов. Это исправляет чрезмерную рекомендацию старого UI_UX_DESIGN.

Правила: `rule/destructive-proportional`, `rule/destructive-names-action`, `rule/name-object-scope-consequence`.

## Поиск и клавиатура

Ctrl/Cmd+K: один command center с группами «Найдено» и «Действия», scope текущего workspace всегда виден. Escape закрывает и возвращает focus. Enter открывает конкретную сущность. Недоступные домены исключаются сервером. Открытие ещё не загруженной панели обязано дождаться intent acknowledgement.

Сохранить рабочие shortcuts; добавить справку сочетаний. Новые однобуквенные hotkeys не срабатывают в input/textarea/CodeMirror/contenteditable. DnD имеет альтернативу меню/кнопками; календарь позволяет перенос через форму времени. Правила: `rule/keyboard-complete-flow`, `rule/accessible-name-required`.

## Дополнение: сферы, окна и связанные карточки

Новый контракт UX — 23-UNIVERSAL-CONNECTED-CORE. Пользовательские сферы группируют пространства, переключатель явно показывает текущий контекст. Два окна независимы. Drag раздела создаёт представление/Dockview split и имеет альтернативу меню; не переносит данные. Карточки показывают связанные задачи, заметки, материалы и напоминания через единые controls. Редкие блоки раскрываются по необходимости, не десять обязательных пустых вкладок.
