# Визуальная спецификация

## Направление

**Спокойная рабочая среда с выразительным акцентом и высокой читаемостью.** Сохранить тёмную графитовую основу, текущий accent mechanism, системный шрифт, Lucide и dockview. Бренд выражается точностью, ритмом строк и хорошими деталями, а не постоянным движением фона.

Текущий login визуально осмотрен: тёмная карточка, фиолетовый ambient фон, умеренная сетка. Остальные рекомендации основаны на коде и существующем UI_UX_DESIGN, не на полном визуальном обходе populated-панелей. Перед реализацией экранных изменений агент обязан сделать baseline screenshots.

Не удалять пользовательские WebGL/стекло/курсор: они добавлены осознанно. Для новых пользователей рабочий preset — спокойный, непрозрачные панели, системный курсор; эффекты остаются в расширенных настройках. Существующие preferences не сбрасывать.

## Что уже реализовано

В globals.css уже есть semantic success/warning/danger, type scale и density row tokens. В packages/ui уже есть AutosaveStatus, CheckToggle, StatusMark, StatCard, FuseButton и другие примитивы. Сначала инвентаризировать API этих компонентов. Не создавать вторые компоненты с тем же назначением по старому дизайн-документу.

## Рабочие токены

Использовать существующие CSS-переменные, дополнить роли при необходимости. Ниже целевые параметры, а не приказ переименовать все классы:

| Роль | Цель |
|---|---|
| Background | Текущий графит около #0a0a0c |
| Surface | #101014–#17171c, с различимыми слоями |
| Main text | Текущий светлый foreground, не pure white для каждого текста |
| Secondary text | Измеренный контраст ≥4.5:1 для обычного текста |
| Accent | Текущий выбор пользователя; фокус/главное действие/выбор |
| Success/warning/danger | Существующие semantic tokens; состояние дополнительно текстом/иконкой |
| Focus | Единый видимый focus ring, не перекрыт соседями |
| Radius | Controls 8px, контейнеры 12px, pills только у badges |
| Spacing | Шаг 4px, основные интервалы 8/12/16/24/32px, выражать rem где уместно |
| Row | 40–44px обычный режим, 32–36px compact для pointer; touch минимум удобной зоны 44px |

Контраст проверить при всех пяти accent presets и при настройках стекла. Если custom фон делает текст нечитаемым, обеспечивать достаточный подложечный слой независимо от эффекта. Нельзя гарантировать контраст одним hex текстового токена без учёта фона.

### Типографика

Root не уменьшать для density. Основной текст 14–15px, control text ≥14px, label 12–13px; 11px только вторичные метки, не суммы/основные действия. Display 24px/600, section 18px/600. Body line-height 1.45–1.55, таблицы 1.3–1.4. Денежные значения и длительности — tabular-nums и выравнивание вправо.

Compact уменьшает padding/gap/row height; типографику максимум на одну небольшую ступень, без двойного root+rem shrink. Стандартный браузерный zoom 200% не должен ломать основные действия.

## Компоновки

### Сегодня, широкая панель

```text
Сегодня · Понедельник, 21 сентября                   [обзор команды]
[ Записать мысль или задачу…                                  ↵ ]

Мой фокус (до 3)                        Расписание
○ Подготовить предложение               10:00 Встреча
  Проект · срок · [таймер]               14:30 Проверка макета
○ Согласовать материалы

Требует внимания                        Входящие · 7 [Разобрать]
Просрочено · 2                          Привычки (если включены)
```

Без ряда декоративных KPI-карточек над реальной работой. На узкой панели последовательность: capture → focus → требует внимания → расписание → остальные блоки.

### Задачи

```text
Задачи                                              [+ Задача]
[Поиск] [Проект ▾] [Исполнитель ▾] [Срок ▾]    Список | Доска
Мои задачи / Все / сохранённые виды
-------------------------------------------------------------
○ Название задачи       Проект       Срок       Исполнитель
○ Название задачи       Проект       Срок       Исполнитель
                              | детали выбранной задачи →
```

Для личного пространства скрыть колонку исполнителя, если она не нужна. На narrow заменить боковые детали одним sheet. Канбан не ужимать до нечитаемых колонок; допускается горизонтальный scroll внутри доски, альтернатива список.

### Проект

Название, статус, срок; ниже контекст/цель и вкладки «Обзор / Задачи / План / Материалы / Учёт» только при доступных возможностях. Обзор — следующий шаг, риски, milestone progress, последние изменения. Не дублировать весь Dashboard внутри проекта. Финансы/время отображать только с разрешением.

### Заметки / Документы

Трёхчастная композиция только при достаточной ширине: навигация/список/содержимое. В docked узкой панели сначала список и переход к содержимому, с видимой кнопкой назад. Читаемая ширина длинной заметки 65–85 символов; код и таблицы могут прокручиваться отдельно.

### Финансы / Склад / Время

Таблицы с устойчивыми колонками, сумма/количество вправо, status не только цветом. Итоги за период отделены от текущей страницы. Основное действие предметно: «Добавить операцию», «Приход», «Запустить таймер». Не использовать карточки для каждой строки бухгалтерского списка.

## Адаптивность — по ширине панели

- ≥1100px содержимого: two-column там, где это полезно.
- 720–1099px: одна основная колонка, детали overlay или ограниченный master-detail.
- <720px: одна панель, sheet/страница деталей; фильтры раскрываются, primary CTA доступен.
- 320px: нет горизонтальной прокрутки оболочки; широкие таблицы/Гант имеют собственную прокрутку и доступную альтернативу.

Sidebar на узком экране — drawer с focus trap/return focus. Resize dockview не должен ломать layout; использовать container queries или наблюдение ширины контейнера там, где viewport media query не отражает размер панели.

## Motion и детали

Обычные переходы 120–180ms, sheet 180–240ms. Не анимировать значения финансов так, что их нельзя сразу прочитать. Reduced motion выключает ambient loops, курсорные эффекты и большие spatial transitions, но сохраняет понятную обратную связь. WebGL при hidden document останавливается; статический fallback при невозможности контекста.

## Приёмка визуальной задачи

Одна baseline-сессия desktop+narrow, одна пакетная правка, одна повторная проверка. Состояния: empty, realistic populated, loading, error, long title, запрет доступа. Нужны screenshots и описание реально проверенного; «выглядит премиально» не критерий.

Продуктовые правила: `rule/structure-before-containers`, `rule/one-primary-action`, `rule/no-custom-focus-bypass`, `rule/accessible-name-required`. Конкретные цвета/размеры — авторское проектное предложение (coverage gap), корректируемое по измерению контраста и rendered QA.
