Весь офисный этап принимать рано.

## F01 · P1 · Chart/pivot исчезают при следующем пересчёте

`apps/web/lib/office/xlsx-codec.ts`, `recalculate`, около 357–406: возвращает `{ sheets }`, теряя charts/pivotTables. `xlsx-editor.tsx`, `setCell`: вызывает recalculate после изменения ячейки.

Подтверждение: добавить chart и pivot в WorkbookState, выполнить recalculate; оба поля undefined. Обычный ввод в ячейку после вставки диаграммы уже удаляет её перед сохранением.

Исправить сохранение полной структуры книги при пересчёте. Приёмка: chart/pivot остаются после правки исходных и посторонних ячеек; данные и визуализация обновляются корректно; ошибка формулы не обнуляет структуру.

## F02 · P1 · Повторное открытие/сохранение удаляет chart/pivot из XLSX

`xlsx-codec.ts:160–194`, `xlsxToWorkbookState`: читает только sheets/rows/values/formulas. `workbookStateToXlsx` после такого чтения выбирает ExcelJS write path, поскольку charts/pivotTables отсутствуют.

Подтверждение: первая запись книги действительно содержит `xl/charts/chart1.xml` и `xl/pivotTables/pivotTable1.xml`. Прочитать её текущим parser и сохранить второй раз — оба файла отсутствуют. Текущие штатные tests проверяют первую запись OOXML, но не сохранность после второго цикла.

Исправить импорт/модель/повторную запись поддержанных chart/pivot. Для неподдержанного содержимого определить fail-closed: безопасный read-only либо явное преобразование в отдельную копию с отчётом потерь. Не утверждать lossless preservation неизвестных OOXML частей без проверки relationships/ranges после редактирования. История версий помогает восстановлению, но не оправдывает незаметное удаление содержимого.

## F03 · P1 · Теряется структура и формат XLSX

`CellState/SheetState` и read/write mapping в xlsx-codec не хранят number format, merges, widths/styles. Подтверждение: A1=123.45 с format 0.00, B2:C2 merge → read/write → format undefined, merge false. Это изменение документа, даже если числовое значение осталось.

Определить поддержанный контракт форматирования и сохранять его при обычном редактировании. Unsupported элементы выявлять до замены исходного файла. Отдельно добавить fixtures dates, rich text, hyperlinks, hidden sheets, shared/array formulas: текущие casts сложного ExcelJS value в primitive не являются конвертацией этих типов. Эти дополнительные случаи пока не проверены.

## F04 · P1 · DOCX export молча исключает картинки

`apps/web/lib/office/docx-codec.ts`, `textRunsFromInline` и `blocksFromNodes`: image включён в schema редактора, но writer не создаёт ImageRun/media. Подтверждение: JSON документа с paragraph+image → DOCX без файлов в word/media. Это проверка exporter на поддержанном узле, а не полный импорт настоящего Word-файла с картинкой.

Добавить корректный round-trip картинки с размерами/alt или запретить обычное сохранение такого файла с ясным предложением копии. Проверить ссылки, объединённые ячейки и списки отдельно; не объявлять их сохранность по тесту простого абзаца.

## F05 · P1 · Новые правки могут быть затёрты ответом сохранения/refetch

Код: `docx-editor.tsx` и `xlsx-editor.tsx`, `save` снимает dirty после await; формы остаются редактируемыми. `useReplaceDocumentContent` инвалидирует document-blob; эффекты по blob заново устанавливают JSON/grid и снимают dirty.

Кодовый риск: отправить состояние A, пока запрос идёт ввести B; ответ A/refetch может заменить B и показать «сохранено». Динамический slow-network test пока NOT RUN. Добавить edit generation/saved generation и согласованное принятие обновлений; dirty-редактор не заменять фоновым blob без явного решения. Отдельно защитить закрытие/переключение файла с несохранённым вводом. В модели «по очереди» нужны конфликты старых открытых вкладок: текущий replaceContent не получает base revision, P2002 на одновременное создание истории не защищает от последовательного stale save.

Приёмка: delayed save + новый ввод, refocus/refetch, две последовательно сохраняющие устаревшие вкладки, restore при открытом редакторе. Silent last-write-wins не считать защитой; как минимум сохранить обе версии и явно потребовать разрешения конфликта. Предпочтителен серверный CAS с согласованной миграцией клиентов.

## F06 · P2 · Диаграммы и сводные пока не видны и не управляются

В xlsx-editor есть формы добавления, но JSX рендерит только сетку ячеек: нет renderer/list/edit/delete для charts/pivotTables. В живом UI после добавления «Проверочная диаграмма» появился dirty, но диаграммы на экране нет. Для pivot отсутствие поверхности подтверждено чтением JSX; отдельный browser click-through pivot не выполнен.

Добавить видимую диаграмму с обновлением по диапазону, выбором/редактированием/удалением; сводную таблицу с рассчитанным результатом, полями и явным обновлением. Проверять одинаковую семантику в UI, сохранённом файле и повторном открытии. XML внутри ZIP — необходимая, но недостаточная приёмка.

## F07 · P2 · Grid пока не обеспечивает привычную табличную работу

`xlsx-editor.tsx`: MAX_DISPLAY_ROWS=200, MAX_DISPLAY_COLS=40; вне предела нет интерфейса перехода. Значение input для формул — исходная `=formula`, результата расчёта в отдельном отображении нет. Нет формульной строки, управления листами/форматами, выделения диапазонов и табличного paste. Inputs не имеют адресного accessible name. Это не означает потерю строк за пределом при каждой записи, но они недоступны для редактирования/проверки.

Кроме того, key input зависит от dirty. При первом blur dirty меняется и поля remount: во время живой проверки переход A1→B1 прервал ввод с ошибкой смены target; A1 сохранился в локальном состоянии, повторный ввод B1 сработал. Это наблюдение и кодовый механизм, полноценный keyboard regression ещё нужен.

Приёмка: устойчивый focus; Enter/Tab/стрелки; имя A1 для screen reader; результат формулы в ячейке и текст в режиме редактирования; диапазонный copy/paste; видимые и обоснованные лимиты; создание/переименование листов. Не обещать Excel-подобное управление по одному HTML table.

## Поправки к прежним документам

20/21 остаются native-first. Но тезис «типичный файл выглядит разумно» не разрешает незаметно удалять картинки, диаграммы или структуру. Добавление поддержки означает полный цикл edit→save→reopen→edit→save. Диаграммы и сводные названы обязательными в текущем 22-SPREADSHEET-CHARTS-RESEARCH; старую строку OF02, допускающую NOT SUPPORTED как завершение этой функции, считать переопределённой.

Журнал O04/O05 содержит утверждения прошлых сессий и не заменяет приёмку. Не переписывать историю; добавить корректирующую запись с текущими дефектами. Новая функциональная проверка не подтверждает весь офисный этап DONE.
