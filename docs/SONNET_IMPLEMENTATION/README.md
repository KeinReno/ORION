## Приоритеты

Дополнение 22 сентября: U00 фиксирует реальное состояние перед изменениями. F01–F05 защищают уже редактируемые пользовательские файлы; U01–U07 строят связанное ядро внутри workspace. Межпространственные grants/проекции (U09) выполняются после обычных связей и не обходят membership/module policy. Предыдущие S/O статусы — история, свежая приёмка находится в 25.

- **P0:** закрыть обход ограничений модулей через агрегаторы; ограничить backup/restore владельцем; исключить потерю данных при неполном restore; отделить локальный вход от сетевого режима; исправить падающий desktop export из-за invite route.
- **P1:** персональные таймеры и уведомления; сохранение черновиков и конфликты; надёжные переходы к сущностям; честные loading/error/empty; рабочий командный сценарий.
- **P2:** унификация интерфейса, поиск, фильтры, производительность, экспорт, полнота модулей, удобный desktop-запуск.
- **P3:** дополнительные интеграции и автоматизации после приёмки основного продукта.

P0 — блокер соответствующего сценария выпуска, а не заявление о подтверждённой эксплуатации уязвимости. Динамические проверки доступа и восстановления ещё должны быть выполнены на отдельной тестовой БД.

## Граница данного результата

Этот комплект — аудит и спецификация. При его подготовке прикладной код не исправлялся, миграции не применялись, пользовательская БД не изменялась. Большой существующий dirty working tree принадлежит пользователю. Документы намеренно отличают `ФАКТ`, `РИСК`, `РЕШЕНИЕ` и `ПРОВЕРИТЬ`.

Не читать пожелание работать до лимитов как команду бесконечно переписывать план. Полезная единица работы — завершённая проверяемая задача. При исчерпании контекста сохранить checkpoint, а не объявлять весь продукт готовым.
