# Спецификация предметных модулей

Общие состояния, клавиатура и сохранение — обязательный контракт из 04-UX. Для всех строк ниже действуют `rule/cover-reachable-states`, `rule/preserve-user-input`, `rule/one-primary-action`. Архитектурные изменения перечислены как инженерные решения, а не существующие возможности.

## 1. Входящие

**Есть:** capture, обработка в задачу/заметку/событие, очередь, связь с проектом. Файлы: `panels/InboxPanel.tsx`, `panels/inbox/*`, `api/src/inbox/*`, shared-types/capture.

**Цель:** нулевое усилие при сборе, ясный следующий шаг при разборе.

- Быстрый ввод всегда принимает обычный текст; дополнительные синтаксические сокращения не обязательны для работы.
- После обработки остаться в очереди, выбрать следующий элемент. Undo предлагается только если атомарно можно вернуть исходное входящее и корректно обработать созданную сущность.
- Конвертация создаёт ровно один объект при повторном запросе; исходное входящее помечается обработанным в той же транзакции.
- Выключенная/закрытая правами цель не доступна для создания; уже введённый текст остаётся.
- Командный inbox пока общий для workspace, видимость явно подписать. Личные быстрые мысли вводятся в личном workspace; не изобретать скрытую приватность внутри общего inbox.

**Приёмка:** двойной Enter/повтор HTTP не дублирует задачу; отключение tasks во время формы даёт понятный отказ без потери текста; закрытие окна на dirty capture безопасно.

## 2. Задачи

**Есть:** статусы, приоритеты, сроки, напоминания, подзадачи, зависимости, повторения, порядок, сохранённые виды, assignee с team. Файлы: `TasksPanel.tsx`, `task-form.tsx`, `tasks/*`, `api/src/tasks/*`.

**Цель:** задача имеет понятное действие и текущий статус без обязательного заполнения десятка полей.

- Быстрое создание: название; остальные поля раскрываются. Срок без времени не следует незаметно превращать в UTC-полночь другого дня.
- Личный default — список; командный — «Мои задачи», рядом Все. Существующий выбранный вид пользователя сохраняется.
- Детали: название/статус, описание, срок/приоритет, проект/веха, исполнитель при team, подзадачи/зависимости, файлы/связи, история/комментарии после S17.
- Closed определяется общим isTaskClosed, включая canceled. Заблокированная зависимостями задача показывает причину; не добавлять автоматический запрет завершения без отдельного решения.
- Завершение recurring не изменяет старый occurrence; поведение следующей задачи документировано и защищено от duplicate generation.
- Bulk actions показывают count и scope, включая различие выбранных строк/всех по фильтру. Фильтр не должен расширять выбор незаметно.

**Приёмка:** перенос клавиатурой, nested tasks без циклов, assignee только из workspace, смена project не оставляет milestone другого проекта, concurrent update даёт conflict.

## 3. Проекты и план

**Есть:** общий контекст, задачи/материалы/расходы/время, lifecycle, вехи, Гант, cascade reschedule. Файлы: `ProjectsPanel.tsx`, `projects/gantt.tsx`, `api/src/projects/*`, `api/src/milestones/*`.

**Цель:** увидеть результат, следующий шаг и риск сроков, затем перейти к действию.

- Обзор проекта не заменяет список задач: показывает цель, ближайшую веху, незавершённое и ссылки на материалы.
- Табы зависят от разрешений. Запрет finance скрывает и expense aggregates, и financial activity, и стоимость времени, если она раскрывает закрытые ставки.
- Перенос вехи с каскадом показывает preview затронутых вех/дат до применения; при конфликте не применять часть цепи.
- Сохраняется finish-to-start модель; lag/lead, ресурсы и critical path не входят в v1.
- Архив проекта не удаляет материалы/задачи; закрытые/архивные сущности не исчезают из исторических отчётов.
- Бюджет проекта, расходы и стоимость времени — разные числа; запретить неявное сложение без подписанного определения.

**Приёмка:** цепь A→B→C сдвигается детерминированно; цикл отвергается; timezone и пустые даты не ломают Гант; узкий экран имеет список вех вместо обязательного drag.

## 4. Календарь

**Есть:** события, повторы/исключения, ICS feed/subscription, day/week/month/agenda, связанные задачи.

- Явно различать event (занимает время) и deadline task (срок), внутренний календарь и readonly external source.
- Редактирование повторения спрашивает scope «это событие / весь ряд», только поддержанные API варианты. «Это и последующие» не показывать без корректного split-series.
- All-day хранится/отображается как день, timed event — instant + zone semantics. DST/смена зоны входят в тесты.
- Внешняя подписка показывает last successful refresh и ошибку, не стирает старый календарь при сбое.
- Изменение времени доступно без DnD. Перекрывающиеся события читаемы и доступны.

**Приёмка:** день смены времени, UTC−11/UTC+14, исключение recurring, readonly editing, недоступный feed, timezone preference.

## 5. Заметки

**Есть:** Markdown/CodeMirror, tags, wiki-links/backlinks, history, templates, archive/trash, attachments. Реальный редактор вынесен в `note-editor.tsx`; не рефакторить по устаревшему описанию CLAUDE.

- Основная композиция list/editor, preview — явный режим. Граф связей не нужен для v1.
- Автосохранение serializes запросы; свежий ввод не затирается ответом старого запроса. Состояния dirty/saving/saved/error/conflict.
- Локальный черновик ключуется user/workspace/note; пользователь понимает, что он пока на устройстве. Logout не передаёт его другому аккаунту.
- Конфликт предлагает сохранить локальную копию и увидеть серверную; никогда автоматически «побеждает последний запрос».
- Wiki-link на неоднозначное название предлагает выбор; rename сохраняет/обновляет связи по существующему контракту.
- Отвязка вложения удаляет связь, не бинарный файл. Удаление файла из Documents даёт предсказуемую missing/trash state в заметке.

**Приёмка:** два редактора, offline во время debounce, переключение workspace до ответа, restore revision с dirty draft, отсутствие доступа к documents.

## 6. Документы

**Есть:** дерево, локальный/WebDAV storage, preview, range streaming, корзина, bulk, замена/версии/restore. **Не утверждать**, что версии нужно написать с нуля. Аннотации есть в schema, но их полный пользовательский flow требует отдельной проверки.

- Список — основной режим для рабочих файлов; breadcrumbs и tree не конкурируют за ширину.
- Upload queue с именем/размером/состоянием каждого файла; partial failure не объявляет весь пакет успешным.
- Конфликт имени: заменить с новой версией / сохранить отдельным именем / пропустить; без тихого overwrite.
- Preview отдельно различает unsupported, loading, corrupted, denied. Всегда есть разрешённое скачивание как fallback.
- Move/rename DB и storage согласованы либо имеют recovery journal; тестировать отказ после каждой фазы.
- Restore из корзины учитывает занятое имя и отсутствующую родительскую папку.
- Версии содержимого и метаданные документов включены в новый backup contract.

**Приёмка:** unicode имена, глубокая папка, 0-byte/unsupported файл, interrupted upload, версия с изменением MIME, повреждённый PDF, missing blob, bulk partial failure.

## 7. Финансы

**Есть:** счета, категории, операции/строки/переводы, бюджеты, recurring, правила, цели, отчёты. В transaction list уже есть limit/offset; не добавлять вторую несовместимую пагинацию без миграции контракта.

- Отдельные вкладки Обзор / Операции / Счета / Бюджеты / Планирование. Прятать редкие настройки в контекстное меню.
- Minor units целые, валюты явно рядом. Разные валюты не складываются без явной FX-модели; v1 показывает итоги по валютам.
- Перевод между счетами не доход и не расход. Split lines суммируются точно, категории проверяются в workspace.
- Итог за период серверный; pagination/фильтр таблицы не меняют баланс счёта по ошибке.
- SavingsGoal, привязанная к балансу, не резервирует деньги: UI прямо это сообщает, несколько целей не должны выглядеть как независимые уже накопленные суммы.
- Импорт CSV — следующий этап: preview, mapping, validation, dedup by source/ref, report accepted/rejected; не обещать banking sync.

**Приёмка:** перевод, split, изменение/удаление операции, закрытый счёт, валюты, повторный recurring tick, 501+ операций, запрет доступа через project/search/export.

## 8. Время

**Есть:** running timer, manual entries, project/task linkage, duration/cost rollups.

- После S06 running timer — личный внутри workspace. Header chip показывает мой таймер, а не чужой.
- Переключение задачи: атомарно остановить старую/начать новую либо понятная двухшаговая операция с восстановлением при сбое; не терять промежуток.
- Member изменяет собственные записи; owner/lead видят отчёты команды по policy. Исправление чужой записи — отдельное действие с причиной/историей, не обычный silent edit.
- Legacy автор неизвестен, отдельная группа. Стоимость неизвестна при null rate, а не ноль.
- Итоги охватывают весь выбранный период. Таймер рассчитывается от server timestamps, UI tick не является источником истины.

## 9. Привычки

Сохранить модель расписания/дней и streak helpers. Не делать привычки задачами. Пространство определяет видимость; в v1 для персональных привычек использовать личный workspace. Переименование не обнуляет историю, archive сохраняет её. Локальный день передаётся явно. Два запроса «отметить выполнено» должны приводить к выполненному состоянию, не к случайному toggle-off; предпочитать idempotent set-state API.

## 10. Списки

Лёгкий checklist без приоритетов/assignees/dependencies по умолчанию. Быстрый ввод следующего пункта Enter, reorder альтернативой клавиатурой, completed визуально спокойно. «Очистить выполненное» сообщает число и обратимость. Не путать архив списка с удалением всех его элементов. Командный shopping/checklist поддержан общим scope workspace, без отдельной mini-task системы.

## 11. Склад

**Есть:** позиции, sku/unit, minStock, immutable движения, отрицательный остаток предотвращается с row lock.

- В первую очередь таблица остатков, поиск SKU/названия, отдельные действия приход/расход/корректировка.
- Ошибку исправлять встречным движением; не редактировать историю задним числом.
- Единицы с текущим integer quantity: не обещать дробные кг/л. Если нужны дроби, отдельная миграция Decimal и новая спецификация точности.
- Себестоимость подписана точным методом; не называть отчёт бухгалтерским балансом.
- Два параллельных расхода не создают отрицательный остаток; существующий lock сохранить.
- Автопроводка в Finance от движения — только будущий plugin с idempotency, а не скрытый side effect.

## 12. Настройки

Группы: Профиль / Пространство / Участники и доступ / Модули / Расширения / Подключения / Уведомления / Внешний вид / Данные и восстановление / Диагностика. Owner-only действия недоступны другим ролям и на API.

Личные preferences отличаются от workspace settings. Изменение темы/плотности применяется к текущему пользователю; отключение модуля — ко всему workspace, с явной подписью. Не показывать неработающий light-theme switch. Light theme — отдельный будущий полный проход, а не переключение одного background.

## Дополнение: офисное редактирование в Документах

Подтверждено владельцем: создание и редактирование DOCX/XLSX во вкладке ORION, привычные офисные инструменты и совместная работа. Это расширяет требования к файловому модулю выше. Основной кандидат — ONLYOFFICE Docs; не строить собственный аналог Word/Excel. Реализация, сохранение, права и приёмка определены в 20-DOCUMENT-EDITORS и 21-OFFICE-IMPLEMENTATION. Остальные preview/annotations/download сценарии сохранить.

## Дополнение: универсальность всех модулей

Карта ответственности и связей текущих Tasks/Projects/Calendar/Notes/Documents/Finance/Time/Habits/Lists/Inventory — в 23-UNIVERSAL-CONNECTED-CORE. Основные модели и предметные инварианты сохранены; контекстные панели не создают вторые копии записей. Финансовый счёт, бюджет и проект — разные понятия. Контакты с заметками/действиями в будущем являются базой CRM-расширения, по воронке движется сделка. Свежая приёмка Documents/Charts — 25-OFFICE-REVIEW, прежние O-статусы не отменяют её дефекты.
