# Модули, расширения и подключения

## Текущая реальность

`packages/shared-types/src/plugins.ts`: единственное расширение `team`, host `tasks`, default off. Это compiled-in расширение, а не загрузка произвольного кода. `pluginOverrides` хранит инверсию default; нельзя трактовать как простой enabled-list. `pluginStates` выключает расширение при выключенном host.

Не путать плагины самого ORION с коннекторами среды Codex/Claude. Установка Gmail/Notion в агенте не создаёт соответствующий модуль ORION.

## Границы

| Вид | Смысл | Пример |
|---|---|---|
| Модуль | Самостоятельные сущности и рабочая поверхность | Документы, Финансы |
| Расширение | Дополнительное поведение существующего host | Команда → Задачи |
| Подключение | Доступ к внешнему источнику | ICS, WebDAV |
| Настройка | Предпочтение отображения/поведения | Плотность, accent |

Не оформлять каждую возможность в плагин. Роли, безопасность, backup correctness, notification delivery и user identity — ядро платформы, их нельзя отключить как расширение.

## Каталог v1

Карточка: название, host module, конкретный результат, состояние, зависимости и последствия выключения. Для текущего team оставить расширение назначения/фильтров задач. Членство, приглашения и base role не должны исчезать при team off.

Различать requestedEnabled и effectiveEnabled в UX: «Включено, но недоступно — модуль Задачи выключен». Не переписывать override автоматически при временном выключении host; вернуть прежний выбор при включении.

Не показывать «Установить» для несуществующего расширения. Roadmap находится в документации, а не в рабочем каталоге с неработающими кнопками.

## Очередь после стабильного v1

| Расширение | Приоритет | Минимальный результат | Условия начала |
|---|---|---|---|
| Импорт операций | Первый кандидат | CSV preview → dedup → report | Корректная Finance policy и export |
| Шаблоны проектов | Второй | Создать проект с вехами/задачами по шаблону | CAS, даты, сохранённый contract |
| Автоматизации | Позже | Один trigger → одно явно выбранное действие | Audit, idempotency, retry, права |
| Связь склада и финансов | Позже | Подтверждаемая операция из прихода | Валюта/стоимость/отмена определены |
| AI-помощь | Эксперимент | Превью предложенных задач из заметки | Явный provider/data consent, budgets |

Эта очередь — продуктовый выбор (coverage gap), а не заявление о спросе пользователей. Не реализовывать всё одновременно.

## Подключения

Для каждого подключения: владелец, workspace, разрешённые операции, последний успех, текущее состояние, retry, отключение без удаления импортированных данных, отзыв секрета. Разделять «тест соединения» и «импортировать данные».

ICS оставить read-only и так подписывать. WebDAV для files и WebDAV для backups — разные назначения; одинаковый провайдер не делает их одной синхронизацией.

Секреты никогда не попадают в DTO, логи, client storage или обычный экспорт. Форма пароля после сохранения показывает «задан», а не возвращает зашифрованное значение как placeholder.

## Если появится автоматизация

Rule содержит trigger, условия, одно действие, enabled, actor/owner и audit. Execution получает уникальный key по rule/event, статус queued/running/succeeded/failed, attempts и next retry. Перед выполнением проверяет **текущие** права. Повтор не создаёт дубликаты; цепочки имеют предел глубины/защиту от циклов. В v1 этого runtime нет — не строить его ради каталога.

Продуктовые правила: `rule/smallest-intervention`, `rule/name-object-scope-consequence`, `rule/cover-reachable-states`.

## Дополнение: расширения над связанным ядром

Typed links, напоминания к сущности, scoped navigation и доступ — общие механизмы 23, а не отдельная реализация в каждом плагине. CRM добавляет сделки/воронки над Контактами, обслуживание — процесс над Имуществом; не заводить собственные несовместимые заметки/задачи. Модуль и расширение настраиваются в workspace, layout — лично. Сначала U01–U07, затем новые предметные расширения по отдельному контракту.
