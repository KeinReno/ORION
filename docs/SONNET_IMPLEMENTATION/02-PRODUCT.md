# Продуктовая спецификация

## Краткий brief

- Пользователь: человек, который ведёт личные дела и/или работает в небольшой команде; оба сценария равноправны, подтверждено владельцем.
- Работа: быстро собрать входящие, выбрать следующий шаг, выполнить его с нужными материалами и понять состояние проекта.
- Текущее поведение: широкий набор модулей, но некоторые общие сущности сохраняют предположение об одном пользователе.
- Результат: в личном пространстве нет обязательного командного шума; в командном действия, ответственность и права конкретны.
- Сигнал успеха: человек проходит сценарии из 13-ACCEPTANCE без подсказки разработчика и без потери контекста/данных.
- Объект: запись внутри явно выбранного пространства; проект — необязательный объединяющий контекст.
- Последствия: создание/изменение меняет общее состояние текущего пространства, если явно не обозначено «личное». Удаление, переключение доступа и восстановление имеют явно описанную область.
- Права: owner/lead/member; запреты enforced сервером и учитываются агрегатами.
- Не цели v1: CRM, бухгалтерский учёт, произвольный runtime плагинов, полноценный offline-first, видеозвонки, собственный мессенджер, AI-agent с автономными действиями.

## Основные сценарии

### Личная работа

Открыть «Сегодня» → записать мысль → обработать входящее → назначить срок/проект → выполнить → сохранить материалы → увидеть итог дня. Не требовать проекта, исполнителя, команды или бюджета для простой задачи.

### Работа команды

Открыть рабочее пространство → посмотреть назначенное мне → открыть проект → понять сроки/блокировки → обновить задачу/добавить материал → записать своё время → уведомить ответственных через продуктовые события. Финансы и склад могут быть скрыты от обычного участника без утечки через сводки.

### Руководитель

Посмотреть проекты с риском сроков → открыть конкретный проект → сверить вехи, задачи и доступные финансовые показатели → изменить приоритет/исполнителя → увидеть историю изменения. Не превращать «Сегодня» каждого участника в административный дашборд.

## Три уровня продукта

1. **Оболочка:** пространства, Сегодня, Входящие, поиск/команды, уведомления, настройки, восстановление.
2. **Предметные модули:** Задачи, Проекты, Календарь, Заметки, Документы, Финансы, Время, Привычки, Списки, Склад.
3. **Расширения и подключения:** дополнительное поведение конкретного модуля и внешние источники данных.

Задачи отвечают «что сделать», календарь — «когда занято время», заметки — «что знать», документы — «какие файлы нужны», проекты — «ради какого результата», входящие — «что ещё не разобрано». Не создавать конкурирующие базы одной сущности.

## Профили нового пространства

Предлагаемые presets, а не разные продукты и не миграция старых пространств:

| Профиль | Включено по умолчанию |
|---|---|
| Личное | Задачи, Календарь, Заметки, Документы, Проекты; остальные можно включить |
| Командное | Те же + Время и существующее расширение Команда |

Финансы/Склад не включать в каждый новый workspace автоматически. Старые настройки сохранить. До реализации presets это предложение, а не описание текущих defaults. Основание: `rule/smallest-intervention`, `rule/value-before-interruption`.

## Что добавлять

В v1: персональное время/уведомления, конфликт-устойчивое редактирование, понятные права, команды навигации, ссылки на сущности, экспорт, восстановление, комментарии и история задач минимального объёма.

После v1: импорт с preview/dedup, шаблоны проектов, простые автоматизации и внешние коннекторы. Добавлять по одному завершённому сценарию, а не по числу карточек каталога.

Не добавлять сейчас: новые декоративные режимы вместо исправления рабочих экранов; marketplace без runtime; AI-кнопки без заданного результата; сводный KPI-экран с числами, по которым невозможно действовать.

## Измеримая готовность

Целевые критерии, не текущие измерения:

- Быстрый захват мысли: одна строка, Enter, запись появляется; ошибка сохраняет ввод.
- Переход поиск → конкретная сущность работает с закрытой и открытой панелью.
- A и B ведут время одновременно; прочтение уведомления A не меняет B.
- Member не получает ограниченные данные ни через один read/export/aggregate путь.
- Восстановление на чистой тестовой среде возвращает все заявленные данные и файлы с совпадающими checksum.
- Ключевые сценарии доступны клавиатурой, на 1280×800 и узком web viewport.
- При недоступном API нет ложного «всё пусто» и ложного «сохранено».

Разделы и их визуальная выразительность подчинены этим критериям. Правила: `rule/one-primary-action`, `rule/cover-reachable-states`, `rule/preserve-user-input`, `rule/keyboard-complete-flow`.

## Уточнение владельца: универсальность и взаимосвязанность

Семья равноправна личной работе и студии. Сферы Дом/Работа — личные группировки, workspace — владелец данных, проекты — контексты результата. Все десять модулей применимы в разных пространствах; одинаковая функциональность не означает общие данные. Целевая модель, включая typed links, общие напоминания и независимые окна, подробно определена в 23-UNIVERSAL-CONNECTED-CORE; исполнение — 24. Этот раздел уточняет прежнее позиционирование «соло-разработчик» и не требует массовой миграции текущих данных.
