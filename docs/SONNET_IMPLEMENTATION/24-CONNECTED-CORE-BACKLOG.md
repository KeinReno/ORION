## Проверки UC

- **UC01:** два пользователя, private/family/work workspace; чужие ref/id и несовпадающий workspace отвергаются; restricted/disabled module скрыт в связях/summary/count/export.
- **UC02:** связь task↔note и document→expense отображается с обоих концов; rename обновляет summary; unlink сохраняет оба объекта; delete/restore учитывает tombstone.
- **UC03:** FK projectId и generic links не дают два разных источника project membership; связанные списки имеют стабильную пагинацию и не дублируют строки.
- **UC04:** конкурентные create-and-link/reminder retry создают ровно один результат. Отзыв прав до доставки прекращает уведомление и скрывает его содержимое.
- **UC05:** окно A=Семья, B=Студия; переключение/перезапуск A не меняет B. Logout очищает чувствительный контекст обоих; другой аккаунт не наследует черновики/layout с данными.
- **UC06:** перетаскивание Финансов меняет расположение, не счёт/workspace данных; меню выполняет тот же сценарий; 200% zoom/клавиатура; ошибка окна не теряет несохранённый ввод.
- **UC07:** семейная Поездка и рабочий Заказ используют одинаковые модули; задача/расход/файл существуют по одному разу; отключение дополнительного модуля имеет понятное состояние.
- **UC08:** −500 ₽ с выбранного счёта уменьшает только его баланс; рабочий контекст не делает операцию доступной коллегам; повторное включение одной записи в обзор не удваивает итог; переводы/валюты корректны.
- **UC09:** grant целого объекта и partial read-only projection имеют отдельные tests; user без membership получает только разрешённое; guessed ids/related objects/export/notifications не расширяют доступ; revoke действует после refresh.
- **UC10:** clean-db migrations, restore со связями, личные сферы не становятся общими; source workspace отдельно восстановлен без выдачи прав на старые чужие refs; web build/static export и реальный desktop smoke.

## Правила исполнения

Не вводить обязательную связь каждого объекта с проектом, не подменять привычки задачами, планы фактом времени, бюджеты счетами. Не ослаблять RLS ради универсального поиска. Ни один generic endpoint не принимает имя произвольной таблицы. Реестр расширяется по одному адаптеру с тестами.

Политика sharing — полноценная миграция модели доступа, не «убрать workspaceId из WHERE». Для U09 сначала зафиксировать threat/permission matrix и допустимые SQL-политики, затем писать код. Предварительно существующие module restrictions сохраняются.

В отчёте: задача, изменённые файлы, миграции, запущенные команды и результат, screenshots для UI, риски, следующий конкретный шаг. Скриншот доказывает вид, не финансовую корректность или права; unit mock не доказывает RLS. Интеграционные данные создавать в изолированной среде, внешнюю доставку подменять.
