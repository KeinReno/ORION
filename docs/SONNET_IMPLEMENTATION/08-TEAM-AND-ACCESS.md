# Командная работа и права

## Принцип

Личный workspace — тот же полноценный workspace с одним участником. Командный — несколько людей, у каждого своя идентичность, своё время, прочитанность и настройки уведомлений. Данные предметных модулей общие, если явно не введён отдельный private contract.

| Действие | Owner | Lead | Member |

| Назначить lead/owner | Да | Нет | Нет |
| Удалить member | Да | Да | Нет |

| Удалить/понизить owner | Да, если останется owner | Нет | Нет |
| Выйти самому | Да, если останется owner | Да | Да |

Это изменение некоторых старых правил, требующее тестов и обновления CLAUDE. Не вводить роль viewer, granular ACL по каждому документу и project-private security в эту итерацию: их нет в данном контракте. Показывать scope существующего доступа честно.

## Restrictions должны действовать везде

Обязательная поверхность проверки: прямые CRUD, search, project detail/list/rollups, entity links, note attachments, notification body/title, exports, backups, frontend cached state, file/version content endpoints. Фильтрация только по disabledModules недостаточна.

Если запрещён target связи, не выдавать его title и содержимое. В общем случае скрыть связь; если продуктово требуется сообщить о пропуске, использовать нейтральное «Некоторые связанные материалы недоступны», без количества/названий, способных раскрыть данные.

## Изменение роли и удаление участника

Проверку «останется владелец» сериализовать по workspace/owners: два owner не должны одновременно удалить/понизить друг друга, оставив workspace без owner. Сейчас count-then-delete требует отдельного concurrency теста.

При удалении участника: новые запросы запрещены, приватные notification deliveries отменены, назначения задач обозначены как бывший участник либо снимаются по явно заданному правилу. Рекомендуемый v1: assignee=null для открытых задач с audit событием; исторические записи сохраняют автора. Все изменения — транзакционные или возобновляемые с журналом.

Удаление учётной записи не является каскадным удалением истории команды. Удаление workspace — отдельное owner-only действие с отдельным spec, не побочный эффект выхода.

## Уведомления

| Событие | Получатель по умолчанию |
|---|---|
| Назначена задача | Новый assignee, если не self-action |
| Срок задачи/напоминание | Assignee; для личной неназначенной задачи owner |
| Ответ/упоминание | Адресат с доступом к сущности |
| Событие календаря | Участники по поддерживаемой модели; не выдумывать attendees без schema |
| Finance/inventory alert | Owner/lead с доступом и включённой категорией |

Для неназначенной задачи командного workspace не рассылать всем автоматически: в v1 оставить в общем «Требует внимания»; owner/lead digest можно добавить отдельно.

Канал in-app независим от внешней доставки. Тихие часы и timezone — пользователя-получателя. Delivery dedup адресный. Если доступ отозван до отправки, сообщение с закрытым контентом не отправляется. Mark-all-read действует только для recipient и явно выбранного workspace.

## Минимальная совместная работа

Комментарии задач и журнал значимых событий добавлять после прав/CAS. Комментарий: author, body, timestamps, revision, принадлежность задаче/workspace, политика редактирования своего комментария. Mention — только существующий участник, без утечки directory наружу. Не делать чат, calls, presence, live cursors и realtime-editor в этой итерации.

Activity log хранит actor, action, entity, time и минимальный безопасный diff; не сохраняет пароли, полный backup или токены. Просмотр журнала также подчинён доступу к entity/domain.

Правила: `rule/name-object-scope-consequence`, `rule/cover-reachable-states`, `rule/destructive-proportional`. Ролевая матрица и backend enforcement — инженерный coverage gap.

## Дополнение: связи и межпространственный доступ

Связь сама не предоставляет права. Оба конца проверяются при resolve/list/count/export/notification. В U01–U07 связи ограничены одним workspace; U08 агрегирует только уже доступное пользователю; U09 добавляет отдельные явные grants. Частичная видимость бюджета реализуется серверной read-only проекцией, не фильтром UI. Проверять косвенные утечки через aggregates/backlinks. Полный контракт — 23 и UC01/UC08/UC09 в 24.
