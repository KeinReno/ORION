# ТЗ-03 — Agent Manager: автономность, предметные права, превью, управление

Зависит от ТЗ-02 (capture/context/link). Развивает [ADR-0007](../adr/ADR-0007-ai-bridge.md); не ломает существующие токены.

## Цель
Пользователь управляет тем, **что агент может делать сам**, что — только предложить, и видит/отзывает всё в одном месте.

## Что уже есть
Scopes (10 штук), журнал вызовов, отзыв токена, `proposals` (подтверждение удаления), черновики финансов, атрибуция `createdByAgent/agentName`, rate-limit. UI «Настройки → ИИ-агенты».

## Пробелы
1. Нет понятия **режима автономности** токена.
2. Подтверждение есть только для удаления задач/заметок; изменения остальных сущностей нельзя «предложить» агенту в режиме помощника.
3. Права плоские: нет явной матрицы «модуль × чтение/запись/предложение».
4. Журнал не показывает «что именно изменилось» и не умеет откатывать.
5. Нет настройки «автофиксировать принятые решения в выбранных проектах».

## Требования

### 3.1 Режимы (поле `AgentToken.mode`, миграция аддитивная, default = `assistant`)
| Режим | Поведение |
| --- | --- |
| `observer` | только `*:read`; любая запись → 403 |
| `assistant` | создание заметок/задач/событий/capture по запросу — сразу; остальные изменения существующих объектов — через **proposal** (человек подтверждает) |
| `manager` | запись сразу в пределах scopes и **лимитов** (число записей/час, список разрешённых проектов); опасное (удаление, финансы, права) — всё равно proposal |
Режим **сужает** scopes, а не расширяет их. Существующие токены мигрируют в режим, эквивалентный их текущему поведению (явно описать в миграции и ADR).

### 3.2 Матрица прав
Заменить плоский выбор на матрицу «модуль × {читать, создавать, менять, предлагать}» поверх существующих scopes (обратная совместимость: старые строки scopes остаются валидными). Ограничение по проектам (`allowedProjectIds`, пусто = все). Отдельный запрет-флаг «никогда: финансы/документы/удаление» — проверка на сервере, не только в UI.

### 3.3 Proposals для изменений
Обобщить `AgentProposal`: тип `*.update` с **дифф-превью** (до/после по разрешённым полям). Подтверждение выполняется под правами человека, один раз (паттерн `pending → approved` через атомарный `updateMany`). Протухание (TTL) и массовое подтверждение/отклонение.

### 3.4 Журнал и откат
- В записи журнала — краткое «что сделал» (тип, объект, поля), не только метод и статус.
- Для созданных агентом заметок/задач — кнопка «Отменить создание» (в корзину, не жёсткое удаление) из журнала.
- Фильтры: токен, модуль, результат, период. Экспорт CSV. Журнал по-прежнему вне бэкапа (`ephemeral-excluded`).

### 3.5 Управление
- «Отозвать все токены» одной кнопкой; индикатор «последняя активность»; предупреждение, если токен без срока.
- Настройка «Автофиксировать явно принятые решения» (список проектов, по умолчанию выкл.): влияет только на то, что агент **может** создать без proposal в режиме `manager`; ORION сам реплики не сохраняет.
- Уведомление владельцу при первом использовании нового токена и при серии отказов.

### 3.6 Удалённый доступ (исследовательская часть, ADR без кода)
Описать варианты для ChatGPT/облачных клиентов (HTTP MCP + OAuth, туннель, собственный клиент внутри ORION): модель аутентификации, поверхность атаки, что запрещено в режиме `local`. Результат — ADR со сравнением и рекомендацией; **реализация — отдельное ТЗ после решения владельца**.

## Не делать
Права агента выше прав человека; хранение секретов в открытом виде; автоматическое выполнение «опасных» операций; доступ к финансовым операциям (кроме черновиков) без отдельного ADR.

## Приёмка
1. Интеграционные тесты по каждому режиму × операция (observer пишет → 403; assistant меняет задачу → proposal, не изменение; manager меняет в лимите → ок, сверх лимита → 429/proposal; проект вне `allowedProjectIds` → 403).
2. Миграция не меняет поведение существующих токенов (тест на снимке старой строки).
3. Proposal подтверждается ровно один раз при гонке двух подтверждений.
4. UI: матрица, превью диффа, журнал с фильтрами, отзыв всех — ручной проход + Playwright.
5. Структурные тесты RLS и реестр снапшотов зелёные (`AgentToken`, `AgentProposal` остаются `secret/ephemeral-excluded`).
