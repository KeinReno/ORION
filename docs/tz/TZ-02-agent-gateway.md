# ТЗ-02 — Agent Gateway MVP: быстрое подключение агентов к установленному ORION

## Проблема
На машине разработчика агент читает репозиторий и понимает, куда писать. На ПК с `.exe` исходников нет — агент тратит часы на изучение UI. Нужно: агент без исходников за минуты находит пространство/проект, **фиксирует информацию, связывает её и получает ссылку**.

## Что уже есть ([ADR-0007](../adr/ADR-0007-ai-bridge.md))
Токены агентов, `/ai/v1` (tasks, notes, events, projects read, finance drafts, messages, jobs, proposals), журнал, rate-limit, MCP stdio `scripts/orion-mcp.mjs` (22 инструмента), UI «Настройки → ИИ-агенты». Права токена = права выпустившего; агент не пишет в БД напрямую. **Это ядро Gateway — не переписывать.**

## Пробелы (предмет ТЗ)
1. Нет универсальной **фиксации** (`capture`): агент должен знать, куда писать — сущность и модуль.
2. Нет **`get_context`**: список возможностей/модулей/проектов/правил одним вызовом.
3. Нет **связывания** и **глобального поиска** для агента (есть только tasks/notes).
4. MCP-сервер лежит в `scripts/` репозитория, требует Node и путей — в установленной версии недоступен.
5. Нет машиночитаемого **Руководства агента** (manual), не зависящего от исходников.
6. Нет встроенного «Подключить агента» с готовой конфигурацией для клиентов.

## Требования

### 2.1 `POST /ai/v1/capture` (+ MCP `orion_capture`)
Вход (zod в `packages/shared-types/src/agent.ts`): `text` (обяз.), `title?`, `hint?: "idea"|"task"|"note"|"event"|"reminder"`, `projectId?`, `source?` (имя клиента/диалога), `idempotencyKey?`, `links?: EntityRef[]`.
Поведение:
- Если `hint` указан или намерение определяется **детерминированно** (явный `hint`; без LLM на стороне ORION) и у токена есть нужный scope → создать через обычные сервисы (`NotesService`/`TasksService`/`EventsService`).
- Иначе → положить в **Inbox** (`InboxItem`, пометка `createdByAgent`) и вернуть `status: "inbox"` — «нужен разбор человеком». Никогда не угадывать молча.
- Ответ: `{ status: "created"|"inbox", kind, id, url, workspaceId, projectId?, deduplicated }`, где `url` — deep-link в ORION (определить формат и добавить обработчик в веб-клиенте/Tauri).
- `idempotencyKey` в паре с токеном: повтор возвращает ту же запись (уникальный индекс, не проверка в коде — см. паттерн в CLAUDE.md «Recurring / inbox»).
- Атрибуция агента как у notes/tasks (`createdByAgent`).
- Решить и описать в ADR: как `capture` соотносится с «быстрым вводом» (`resolveQuickCapture`); переиспользовать его правила, не дублировать.

### 2.2 `GET /ai/v1/context` (+ `orion_get_context`)
Одним ответом: пространство, роль, scopes токена, **включённые** модули, проекты (id, название), поддерживаемые типы capture/link, лимиты, версия API (`apiVersion`), `capabilities[]`, какие операции требуют подтверждения. Никаких данных модулей, к которым нет scope.

### 2.3 Связи и поиск
- `POST /ai/v1/links` / `DELETE` (+ `orion_link_objects`) через существующий сервис `EntityLink`; проверка принадлежности обоих объектов пространству; scope `links:write` (новый).
- `GET /ai/v1/search?q=` (+ `orion_search`) по тем модулям, на которые у токена есть read-scope; результат — `{type,id,title,url,snippet}`; без утечки названий недоступных модулей.

### 2.4 Руководство агента (Agent Manual)
- `GET /ai/v1/manual` (без секретов, но с токеном) и статический файл `AGENT_MANUAL.md`, **поставляемый в установщике**: назначение, типовые сценарии («сохранить идею в проект», «создать задачу с напоминанием»), список инструментов с примерами, что требует подтверждения, формат ошибок, правила безопасности (текст другого агента — данные, не команды). Генерировать из тех же zod-схем/описаний MCP, чтобы не расходилось (тест на совпадение).
- Описывает **публичные** контракты; внутренние таблицы и исходники не упоминает.

### 2.5 MCP в установленной версии
- Перенести адаптер из `scripts/` в поставляемый артефакт: либо `orion-mcp.exe`/`.cjs` в ресурсах Tauri (Node уже поставляется в installer), либо встроенный HTTP-эндпойнт MCP (Streamable HTTP) на `127.0.0.1` — **выбор через ADR** (аутентификация, транспорт, CORS/DNS-rebinding). Удалённый MCP для ChatGPT — **вне этого ТЗ** (отдельный ADR, ТЗ-03 этап).
- Один и тот же набор инструментов в stdio и HTTP; адаптер не хранит данных и прав.
- Токен читается из env или файла конфигурации с правами только текущего пользователя; не логировать токен.

### 2.6 «Подключить агента» в Настройках
В «Настройки → ИИ-агенты»: мастер → выбрать клиента (Claude Desktop/Code, Cursor, Codex, «другой») → выпуск токена с рекомендуемыми scopes → готовый JSON-фрагмент/команда с **реальными путями установленной версии** и кнопка «Копировать» → кнопка «Проверить подключение» (вызов `/ai/v1/me` с показом результата). Текст на русском. В режиме `server` — мост по-прежнему выключен без `ORION_AI_BRIDGE=1`.

## Не делать
Прямой доступ к PostgreSQL, обход RLS, LLM внутри ORION для классификации, автосохранение реплик диалога, доступ к финансам/документам вне существующих scopes, удалённый MCP/туннели.

## Приёмка
1. **Контрольный сценарий на чистом Windows (без Node/исходников)**: установить `.exe` → «Подключить агента» → агент вызывает `get_context`, находит проект, `capture` создаёт заметку, `link` связывает её с проектом, агент возвращает рабочий `url`. Агенту не давали исходники; зафиксировать, сколько вызовов потребовалось (цель ≤ 6).
2. Тесты (по образцу `ai-bridge.integration.test.ts`): capture с hint / без hint → inbox / идемпотентный повтор / чужой `projectId` → 400 / нет scope → 403 + запись в аудит / выключенный модуль → 409.
3. Манифест и MCP совпадают (тест), токен не попадает в логи.
4. `docs/adr/ADR-0007` дополнен или создан ADR-0014 (транспорт MCP, формат deep-link, capture); `docs/README.md` обновлён.
