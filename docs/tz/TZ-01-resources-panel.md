# ТЗ-01 — Контекстная панель ресурсов (MVP)

Базовая концепция: [CONTEXTUAL_RESOURCES_PANEL.md](../CONTEXTUAL_RESOURCES_PANEL.md) (согласована, не реализована). Это ТЗ превращает этап A концепции в исполнимые задачи. Расхождения с концепцией решает концепция.

## Цель
Правая контекстная поверхность с вкладками **Ресурсы / Связи / Свойства**, показывающая файлы и связанные объекты текущего раздела или выбранной сущности — без второго файлового хранилища.

## Что уже есть
- `documents` (дерево, `StorageAdapter`, `FilePreview`, версии), вложения заметок через `Document`.
- `EntityLink` + `EntityLinksSection` — единственный UI связей.
- Правый инспектор по [FRONTEND_WORKSPACE_SPEC.md](../FRONTEND_WORKSPACE_SPEC.md); Workbench (dockview), `panel-bus.ts`, `openEntity`.

## Этап 0 — инвентаризация (обязателен, результат — короткий отчёт в PR)
1. Как сейчас устроен правый инспектор (где живёт, как получает выбранный объект, ширина, режимы).
2. Какие типы сущностей допустимы в `EntityLink.sourceType/targetType` и есть ли тип `document`; как `openEntity` открывает каждый.
3. Кто сегодня привязывает `Document` к чему-либо (только заметки? проекты?).
4. Нужен ли новый typed slot. Если да — `NEW_EXTENSION_POINT_REQUIRED` + ADR **до** кода.

## Требования MVP
**Контракт** (`shared-types` + `apps/web/lib/extensions/contracts.ts`):
- `EntityRef { moduleId, entityType, entityId }` (workspaceId берётся из контекста, межпространственных ссылок нет).
- Провайдер ресурсов (slot): модуль объявляет, какие ресурсы/связи он отдаёт для `EntityRef` или для раздела. Базовые модули **не** импортируют плагин-провайдеры; Documents — провайдер, а не зависимость панели.
- Если `EntityLink` не покрывает связь «документ ↔ любая сущность» — расширить допустимые типы аддитивно (без смены существующих данных); новых таблиц не создавать, пока ADR не докажет необходимость.

**UI** (`apps/web`, компонент в `@orion/ui` — только презентация):
- Вкладка «Ресурсы»: дерево/список, фильтр, превью (через существующий `FilePreview`), «Открыть» (полный редактор — в основной dock-панели), «Связать», «Открепить связь» (с подтверждением; файл не удаляется).
- Вкладка «Связи»: все связанные объекты любых включённых модулей, переход к источнику.
- Вкладка «Свойства»: метаданные выбранного. «История/Доступ» — только если модуль реально её поддерживает, иначе не показывать.
- Заголовок всегда показывает контекст («Финансы → Счёт «Сбер»») и кнопку сброса; **«Закрепить контекст» / «Следовать за объектом»**.
- Панель не открывается пустой по умолчанию; скрытие освобождает ширину; ширина настраивается (старт 280–320 px); на узком viewport — шторка.
- Вся функциональность доступна с клавиатуры и без drag-and-drop.

**Поведение и безопасность**
- Доступ проверяется по **целевому** объекту при каждом открытии; видимость связи не даёт права чтения.
- Смена пространства очищает панель и кэш react-query (закреплённый контекст — сбрасывается с понятным сообщением).
- Выключенный модуль/плагин не ломает панель; не раскрывать имена недоступных объектов.
- Dirty-guard редактора не нарушается сменой контекста панели.
- Локальные внешние файлы (ссылки на путь Windows) — **вне MVP** (этап B), не закладывать абсолютные пути в схему.

## Не делать
Второе хранилище, копирование файлов при связывании, индексирование содержимого финансовых файлов, перенос панели в dockview/Tauri-окно (этап B), переписывание Workbench.

## Приёмка
1. Сценарий **Финансы → счёт → документ → операция → чек** и **Проект → материалы → задача** проходят вручную и в Playwright (default-full и plugins-off).
2. Один документ связан с 2+ объектами, байты не дублируются; «Открепить» не удаляет документ.
3. Documents выключен → Tasks/Finance/Projects работают, панель показывает «недоступно».
4. Интеграционный тест: пользователь B не получает ресурсы пространства A ни через связь, ни через кэш.
5. 320–720 px без горизонтального скролла; фокус виден; loading/error/empty различимы; список из 1000 элементов не подвисает (виртуализация или пагинация).
6. `pnpm quality`, `pnpm test:integration`, `pnpm test:e2e:local` зелёные; обновлены docs (статус концепции → «MVP реализован»).
