# ТЗ-04 — LAN Host/Client и обнаружение устройств

Цель владельца: два компьютера в одной сети (свой и девушки, разные пользователи) работают с общим узлом ORION без облака и интернета. Этап 1 дорожной карты: **один узел-хост, остальные — клиенты**.

## Что есть сейчас
- Установленный ORION = Tauri + локальный API + собственный PostgreSQL. `apps/desktop/runtime/launcher.cjs` запускает API с `ORION_MODE=local`, `HOST=127.0.0.1`, порт 4000; БД на `127.0.0.1:55432`.
- `ORION_MODE=server`: bind `0.0.0.0`, нужен `JWT_SECRET`, отключены picker/PIN, обязателен пароль `passwordScore ≥ 2`, `LoginRateLimitGuard`, SSRF-заслон. Веб-клиент режимы визуально не различает (известный UX-разрыв).
- Tauri-оболочка грузит статический экспорт и ходит на API по адресу (проверить, как он задаётся, и CSP `connect-src`).

## Результат
Три режима в «Настройки → Сеть и устройства»: **Локальный** (по умолчанию, как сейчас) · **Хост LAN** · **Клиент LAN**.

## Этап 0 — исследование (отчёт в PR/ADR до кода)
1. Как задаётся URL API в desktop-клиенте; можно ли переключить на удалённый узел без пересборки; CSP.
2. Можно ли безопасно переключать локальный узел local↔server **без потери данных и повторной регистрации** (JWT secret, режим входа, существующие аккаунты с PIN без пароля).
3. mDNS в Node без нативных зависимостей (кандидаты проверить на Windows 11: чистый JS-реализации; fallback — ручной ввод адреса). Брандмауэр Windows: какие правила нужны и как запрашивать (UAC) — **не открывать порты молча**.
4. Транспорт-безопасность в LAN: самоподписанный сертификат с закреплением отпечатка (TOFU/подтверждение кода) vs HTTP. Рекомендация обязательна, по умолчанию — шифрование.

## Требования

### 4.1 Режим «Хост LAN»
- Включение — явное действие владельца с предупреждением и проверкой: есть ли у всех локальных аккаунтов пароль (иначе — принудительная установка пароля; PIN-вход и picker выключаются).
- API слушает LAN-интерфейс **только API-порт**; PostgreSQL остаётся на `127.0.0.1` (тест на недоступность порта БД с другого хоста).
- Режим применяет те же защиты, что `ORION_MODE=server` (общий код, не копия). Хранить выбор в `local-runtime.json`/настройках узла; перезапуск API лаунчером.
- Имя узла (по умолчанию `ORION-<имя ПК>`), идентификатор узла (стабильный UUID), отпечаток сертификата.

### 4.2 Обнаружение (mDNS / DNS-SD)
- Хост объявляет сервис `_orion._tcp` с TXT: версия протокола, имя узла, `nodeId`, отпечаток. **Без** списка пользователей, названий пространств, любых данных.
- Клиент ищет узлы, показывает «Найден · требуется подключение». Ручной ввод `адрес:порт` — обязателен (роутеры режут multicast).
- Обнаружение ≠ доступ: до авторизации видна только эта карточка.

### 4.3 Доверие устройства
- Подключение клиента: запрос на хосте → **владелец узла подтверждает** (код из 6 цифр на обоих экранах) → клиент получает долговечный device-токен; сверка отпечатка сертификата.
- Список доверенных устройств у владельца: имя, дата, последняя активность, **отозвать** (немедленно рвёт сессии).
- Вход пользователя — отдельный шаг (логин/пароль **на хосте**, аккаунт принадлежит хосту), после чего клиент видит только свои пространства.

### 4.4 Режим «Клиент LAN»
- Desktop переключается на удалённый API выбранного узла; локальный узел при этом **не удаляется и не изменяется** — возврат в «Локальный» одним действием.
- Недоступность хоста: понятное состояние «узел не в сети», без потери ввода; никакой тихой записи в локальную базу вместо удалённой (offline — ТЗ-06).
- Клиент не использует свои локальные пространства под видом общих; в UI всегда видно, к какому узлу подключён.

### 4.5 Установщик и обновления
Установщик по умолчанию ставит «Локальный»; правила брандмауэра создаются только при включении «Хост LAN» с запросом прав. Обновление сохраняет выбранный режим. Не подменять `tauri build` ручными шагами — только `pnpm build:desktop-installer`.

## Не делать
Открывать PostgreSQL, включать LAN автоматически, раскрывать данные до аутентификации, синхронизировать две независимые базы (ТЗ-06), облачные relay.

## Приёмка
1. На двух реальных ПК/ВМ в одной сети: хост включён → клиент находит по mDNS и по ручному адресу → подтверждение кодом → вход → видит общий узел. Без интернета работает.
2. Сканирование с клиента: открыт только API-порт; БД недоступна.
3. Анонимный запрос к узлу (до доверия) не отдаёт ни пользователей, ни пространства (тест).
4. Отзыв устройства обрывает доступ ≤ 5 с; перебор кода подтверждения ограничен.
5. Возврат клиента в «Локальный» не теряет локальные данные; смена режима хоста local→LAN→local сохраняет существующие данные (тест на копии базы).
6. Обновление `docs/WINDOWS_INSTALLER.md`, `SYNC.md`, `DEPLOYMENT_READINESS.md`; в проверку релиза добавлен LAN-сценарий.
