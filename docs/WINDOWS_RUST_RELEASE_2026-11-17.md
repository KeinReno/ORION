# ORION Rust 0.2.2 — проверка Windows-пакета

Дата: 17.11.2026. Основа: `f759e26d` и рабочие изменения нескольких агентов.
Это сборка совокупного рабочего дерева, а не чистого указанного commit.
Состояние приёмки до завершения проверок: **в работе**.

Цель — автономный Windows x64 NSIS-пакет для домашнего ПК, офисного ПК и
ноутбука Вари. Установка не требует исходников, Node.js, Rust или Docker.
Наличие необходимых компонентов проверяется в самом пакете; Windows WebView2
устанавливается средствами NSIS, если его ещё нет.

## Исправления при сведении работ

- `DevelopmentArchitectSnapshot` добавлен в snapshot/restore и таблицу
  миграционной классификации. Локальная привязка к репозиторию не синхронизируется.
- Отдельная миграция `20261117093000_development_architect_snapshots_rls`
  включает ENABLE/FORCE RLS и membership policy для этой таблицы. Исходная
  миграция создания таблицы не переписывалась.
- Общий файловый writer получил уникальные временные файлы и ограниченный
  повтор Windows EPERM/EACCES/EBUSY при атомарной замене. Ошибка постоянного
  доступа сохраняет прежнее состояние; тест проверяет эту границу.
- Из production stage исключаются все `.env`/`.env.*`, в том числе `.env.rust`.
  Добавлен тест исключения профилей среды разработки.
- Руководство агента пересоздано штатным генератором.
- В двух Rust integration test roots подключён новый модуль `timeouts`.
- Windows-тест приватного токена различает DACL и SACL: унаследованная метка
  целостности не считается унаследованным разрешением доступа. Правила выдачи
  доступа к самому токену не ослаблялись.
- Версия оболочки и NSIS повышена до `0.2.2`: переустановка той же версии
  ранее попадала в проблемную ветку NSIS.
- `build.json` теперь сохраняет полный SHA основы и признак dirty tree.
- Оболочка уважает проверенный `ORION_DESKTOP_DATA_DIR` при изолированной
  диагностике. Обычный каталог установленного приложения не меняется.

## Окружение сборки

В этом окружении нативные процессы не могут создавать тестовые файлы в
`B:\Temp`. Для текущей команды задавались `TEMP` и `TMP`, указывающие на
`.tmp-test/rust-temp` внутри репозитория. Системные настройки не менялись.

```powershell
$env:TEMP = (Resolve-Path '.tmp-test/rust-temp').Path
$env:TMP = $env:TEMP
$env:ORION_BUILD_TAG = 'orion-rust-v0.2.2-20261117'
corepack pnpm build:desktop-installer
```

Сборочный хост также требует .NET SDK для автономного Habitat Windows Host.
Обычному пользователю .NET SDK не нужен: host публикуется self-contained.

## Границы проверки

Успешные проверки кода и локальной установки не означают выполненную приёмку
на офисном ПК и ноутбуке Вари. Отдельно проверяются запуск на другой Windows,
первый вход, сохранение после перезапуска и необходимые пользователям модули.
Установки на разных ПК имеют собственные данные. Общие данные и синхронизация
требуют настройки и самостоятельной проверки.

`scripts/preflight-clean-windows.ps1` из исходного рабочего дерева в этом
прогоне не используется: он содержит удаление каталога данных и глобальное
завершение процессов. Его нельзя запускать на пользовательском профиле.

## Проверка кандидата 0.2.2 на домашнем ПК

- NSIS установился с кодом 0. Копия установленных файлов в пути из ASCII
  открыла рабочую область Tauri с локальной PostgreSQL. На отдельном профиле
  прошли регистрация, создание проекта, задачи, заметки и материала базы знаний,
  загрузка и скачивание документа, экспорт и предварительный просмотр восстановления.
  После штатного перезапуска записи и контрольная сумма документа совпали.
- В пути установки с кириллицей подготовка копии PostgreSQL под
  `C:\ProgramData\ORION-Rust` получила Windows error 5. С новым приватным
  каталогом в диагностическом прогоне та же копия дошла до API health.
- Отдельный вылет оболочки зарегистрирован Windows в `GPP64.dll`. После
  выключения GamePP оболочка открыла рабочую область. Отказ `ProgramData`
  повторился независимо от GamePP.
- Прошли typecheck, lint, architecture-check, plugin-contract-check, Rust
  тесты и Windows Job smoke. Из unit-тестов прошли 2165, три проверки esbuild
  завершились с отказом доступа, в том числе после выключения GamePP.
- Первый полный интеграционный прогон дал 792 прохода, 6 ошибок, 4 пропуска
  и отдельный отказ `initdb` в suite setup. После добавления RLS и исправления
  относительного `TEMP` в диагностическом harness прошли 49 тестов RLS,
  snapshot и Tasks. Отдельный прогон Finance дал 2 прохода, а Milestones,
  ORION DEV journey и Tasks дали 10 проходов и 1 пропуск.
