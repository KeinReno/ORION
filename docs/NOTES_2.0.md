# Заметки 2.0 — материалы и визуальные стопки

**Статус:** реализуется в текущем срезе; фактическое состояние сверять с `docs/STATUS.md`.

Заметки остаются владельцем текста и стопок. Файлы хранятся как обычные документы пространства: привязка заметки не копирует бинарные данные, а удаление привязки не удаляет документ.

## Материалы

- Один механизм загрузки принимает несколько файлов и используется в панели вложений и при перетаскивании файлов на редактор заметки.
- Папка, выбранная через системный диалог, передаётся с относительными путями. API создаёт дерево в корневой папке «Вложения заметок» модуля «Документы».
- Изображения, видео, аудио, документы и архивы остаются обычными документами; открытие использует общий `FilePreview`, а где формат не поддержан — доступно скачивание.
- Веб-ссылку можно добавить в поле материалов или перетащить в редактор. Допускаются только `http:` и `https:`; ссылка записывается в Markdown тела заметки.

## Визуальные стопки

- Выбрать две и более заметки и объединить их можно в стопку с названием.
- Стопки сворачиваются в компактную карточку; раскрытие показывает участников.
- Порядок участников сохраняется сервером. Выбранные заметки можно переместить в существующую стопку или объединить в новую.
- Удаление стопки удаляет только `stackId` и `stackTitle` у её заметок. Заметки и их содержимое остаются в списке.
- Поля стопки лежат в строке `Note`, поэтому существующие RLS, резервные копии и репликация заметок сохраняют свои границы доступа.

## API и миграция

- `POST /workspaces/:workspaceId/notes/stacks` создаёт стопку для выбранных активных заметок.
- `POST /workspaces/:workspaceId/notes/stacks/:stackId/members` переносит выбранные заметки в существующую стопку.
- `PATCH /workspaces/:workspaceId/notes/stacks/:stackId/order` сохраняет полный порядок участников.
- `DELETE /workspaces/:workspaceId/notes/stacks/:stackId` разгруппирует участников без удаления заметок.
- Миграция `20261109120000_note_visual_stacks` добавляет nullable-поля стопки и индекс для списка участников.

## Границы

Извлечение файлов из архива не выполняется автоматически: архив загружается и хранится как документ, затем его можно скачать. Ссылки добавляются в Markdown тела заметки и просматриваются штатным рендерером Markdown.

## Версии, ссылки и поиск (задание 07, backend)

- **История версий.** Ревизия — снимок перед явным сохранением/закрытием; автосохранение новых ревизий не плодит. Восстановление версии создаёт **новую** запись истории с содержимым выбранной и полем `restoredFrom` (id исходной версии), поэтому история не теряет точку, из которой откатывались. Хранятся последние 50 ревизий на заметку; ночная чистка идёт фоновой задачей и не трогает пространства с выключенным модулем заметок.
- **Diff.** `GET /workspaces/:workspaceId/notes/:noteId/revisions/:revisionId/diff[?against=<revisionId>]` — построчный список `equal | added | removed` с номерами строк в обеих версиях. Без `against` сравнивается с текущим содержимым. Алгоритм — собственный LCS в `packages/shared-types/src/note-diff.ts`, без сторонних библиотек.
- **Wiki-ссылки.** При сохранении тела сервер разбирает `[[...]]` и полностью перестраивает исходящие `NoteLink`. Цель ищется по заголовку (без учёта регистра), по id и по короткому номеру (`[[N-104]]`, `[[104]]`). Ненайденная цель не выбрасывается: строка остаётся с `broken: true`. Переименование/удаление целевой заметки ставит флаг, возврат заголовка или восстановление из корзины снова разрешает ссылку — запись не пересоздаётся.
- **Ссылки наружу.** `GET .../notes/:noteId/links` — исходящие и входящие ссылки с флагом `broken`; `GET .../notes/links/broken` — все битые ссылки пространства для разбора. Циклы допустимы.
- **Поиск внутри заметки.** `GET .../notes/:noteId/search?q=` — смещения вхождений в теле (UTF-16, как индексы JS-строки), номер строки и её текст. Пустой запрос даёт пустой результат.
- **Связанные заметки.** `GET .../notes/:noteId/related` — прямые wiki-ссылки и обратные (глубина обхода 2), общие связи `EntityLink` через любые сущности и заметки того же проекта; причина указывается в `reasons`.

## Состояние стопок (per-user)

Свёрнутость и порядок стопок — личный выбор участника и лежит в `note_stack_states`, а не в строке заметки:

- `GET .../notes/stacks/state` — все стопки пространства с `collapsed`/`sortOrder` этого пользователя (без личной записи — значения по умолчанию);
- `PATCH .../notes/stacks/:stackId/state` с `{ collapsed }` — свернуть/развернуть;
- `PATCH .../notes/stacks/order` с `{ stackIds }` — полный личный порядок.

Стопки остаются плоскими: вложенные стопки не поддерживаются, `POST .../notes/stacks` с `parentStackId` отвечает 400. Таблица с `workspaceId` защищена ENABLE + FORCE RLS (участник видит только свои строки) и исключена из резервной копии как личное состояние (`identity-excluded`).
