# Android alpha.23 — реальная LAN-приёмка

26.10.2026 · 0.1.22 / code23. Исторический отчёт текущего исправления.
Прямое поручение владельца: самостоятельно настроить через открытый desktop UI.

## Исправленная причина

useLan передаёт выбор пространства с полем workspaceName. RemoteScope содержит
четыре поля идентичности, но TypeScript структурно допускает объект выбора
с дополнительным названием. parseMobileReplica удаляет неизвестные поля scope
при Zod-разборе, затем ошибочно сравнивал все Object.keys входного scope,
включая workspaceName. Корректная копия отклонялась до записи SQLite с ошибкой
«Копия принадлежит другому пространству». ReplicaEngine классифицировал локальное
исключение как offline; пользователь видел ложное «Нет связи», хотя сервер
успешно отвечал200 на mode/replica и201 на регистрацию устройства.

Теперь сравниваются только nodeId/fingerprint/userId/workspaceId и при разборе,
и при подготовке переноса. Проверки подмены этих идентификаторов, сертификата,
принадлежности документов и родительских списков сохранены. Формат хранения,
scope hash, ключи импорта и сетевой протокол не менялись; миграция не нужна.

Регрессионный тест воспроизвёл offline до исправления, после него подтвердил:
загрузка с metadata, очередь/отправка заметки, повторное открытие с переименованным
пространством, строгий отказ чужому userId и подготовку импорта с тем же metadata.

## Что сделано на реальных устройствах

- Через Computer Use выбран открытый desktop ORION, аккаунт Reno, личное Kaiden.
- В установленном desktop путь: «Резервные копии» → «Режим пространства и устройства»
  → «Гибрид (копия на устройстве)». Настройки доверия/паролей/политики входа не менялись.
- Android обновлён поверх alpha.22. Сохранённые доверие и вход использованы повторно;
  выбрано то же Kaiden. Копия загружена, показано «Обмен настроен».
- На OPPO создана единственная синтетическая задача QA LAN phone <timestamp>.
  Автоматическая отправка завершилась пустой очередью; задача найдена через UI ПК.
  Для появления свежего списка в установленном desktop использовалось обновление UI.
- Статус тестовой задачи изменён на ПК; телефон автоматически получил «Завершена».
- После перезагрузки WebView выбор пространства и завершённая задача восстановились
  из SQLite. Тестовая задача удалена через Android UI; узел подтвердил пустую очередь;
  обновлённый desktop показывает только исходную задачу, уведомления теста закрыты.

Это реальная HTTPS LAN192.168.1.x между OPPO Reno8 5G (CPH2481/Android15)
и установленным Windows Orion, не MemoryHost и не синтетический native bridge.
ADB управлял телефоном по Wi-Fi; транспорт данных — штатный pinned OrionLan.

## Проверки и границы доказательства

119 focused tests,11 plugin-contract tests, общий typecheck, scoped lint,
architecture-check и module-docs PASS. Android assembleDebug/assembleRelease/
lintDebug/testDebugUnitTest PASS (10 неизменённых JVM tests UP-TO-DATE).
Повторены settings/foundation/discovery/ui/module-polish browser smoke.

Физически проверен двусторонний сценарий одной задачи, восстановление выбранной
копии и согласованное удаление. Заметки/списки покрыты тестами транспорта/реплик,
но отдельная физическая двусторонняя приёмка каждого из них в этот проход не выполнена.
Потеря сети/retry проверены модульными тестами, не отключением домашней сети.
VPN и два ПК не проверялись. Автоматическая перерисовка всех desktop-модулей
в установленной старой сборке не подтверждена; новый Windows installer не выпускался.

Финансы остаются локальными. Семь исходных задач и одна заметка в разделе
«На телефоне» не импортировались в Kaiden: это отдельные данные, существующий
перенос требует актуальной резервной копии и явного указания назначения.
Изменение режима Kaiden само по себе их не переносит. Телефон оставлен в копии ПК.

## Следующий срез

Обновлённый desktop installer с уже имеющимися source-правками polling и понятным
входом в hybrid-настройки; отдельная LAN-приёмка заметок/списков и восстановления
после реального разрыва связи. Не заявлять «все устройства/все модули синхронизированы»
по зелёному индикатору одного выбранного узла.
