# Android — общий стиль KAIDEN, жесты и голосовой захват

21.10.2026. Основание: владелец требует визуальное единство с desktop и спрашивает
об уместности drag/drop, меню удержания и голосового ввода.

## Реализуемый визуальный срез
Текущая Android alpha.4 имела отдельные цвета/радиусы. Источник visual truth:
packages/ui/src/theme-engine.ts, design-tokens.ts, desktop effective-application-theme.ts.
В desktop есть личные/пространственные темы; неизвестно, какая активна на ПК владельца.
Поэтому Android использует те же public THEME_PRESETS/themeDocumentVariables из @orion/ui:
Precision, Obsidian, Midnight, Emerald, Crimson и Arctic для светлого режима.
Палитра тёмного режима выбирается на телефоне, system/light/dark сохраняется.
Настройки существующих записей дополняются darkTheme=kaiden-precision; записи не меняются.
Размеры касаний остаются не меньше 48 CSS px; desktop радиусы 6/8px и цветовые роли
общие. Меняются темы/геометрия/иерархия, без новой предметной логики.
Автоматического переноса персональной/пространственной темы ПК пока нет.

## Drag and drop — проектное решение, не готовая функция
Применять там, где существует сохраняемый пользовательский порядок: задачи,
в будущем закреплённые заметки/списки. Не применять к журналу расходов по дате
и к выдаче поиска. Сначала проверить public sortOrder и sync semantics.
Начало за handle после удержания; движение до порога остаётся прокруткой.
Видимая цель и placeholder; за границей/Back/pointercancel — отмена, без записи.
Сохранять после drop, при ошибке вернуть предыдущий порядок.
Доступная альтернатива: меню «Переместить выше/ниже». Не назначать одинаковое
удержание строки одновременно на drag и меню (rule/cover-reachable-states).

## Меню удержания («холо»)
Рабочее имя — радиальное/веерное меню, либо marking menu. 3–4 частых действия
у кнопки создания/действий: задача, заметка, расход, голос (голос после реализации).
Удержание ~350–450ms как стартовая гипотеза, тактильное подтверждение; подсветка
иконки и её подписи; отпускание на выделенном пункте запускает действие.
Центральная нейтральная зона/выход из меню/Back/pointercancel отменяет выбор.
У края экрана веер раскрывается внутрь; курсор и подпись не прячутся под пальцем.
Обычное нажатие открывает то же меню с кнопками для обычного выбора/TalkBack.
Удаление и публикацию в общее пространство не выполнять мгновенным жестом.
Пересечения с системными edge gestures и микрофонным lock должны исключаться.
Правила: rule/name-object-scope-consequence, rule/destructive-proportional,
rule/preserve-user-input. Новый жест дополняет доступные действия.

## Голос — следующий отдельный срез, НЕ реализован этим изменением
Цель: быстро сохранить мысль, потом обработать. Два результата:
«Аудиозаметка» и «Текст из речи». При необходимости будущий режим «аудио + текст».
Нажатие микрофона начинает запись; видимые таймер/индикатор/Стоп/Отмена.
Удержание позволяет говорить до отпускания; движение к замку фиксирует запись
без удержания, затем явный Стоп. Нажатие само по себе уже даёт hands-free режим.
Разрешение микрофона — при первом действии, с объяснением. Отказ оставляет текстовый ввод.
Базовый срез записывает только в открытом приложении; блокировка жестом не означает
разрешение бесконечной записи в фоне. Background/lock-screen — отдельная работа.

Аудио сначала писать нативно в приватный файл; durable metadata и восстановление
после interruption, ограничение размера/длительности/свободного места, playback/delete.
Не помещать base64 в JSON snapshot. Действующий JSON backup не содержит файлов:
перед обещанием backup аудио нужен archive + manifest и проверка restore.
Для attachment/domain интеграции сначала проверить public documents/notes contracts.
Если нет мобильного contribution point: NEW_EXTENSION_POINT_REQUIRED — Extension
Proposal для typed capture actions/media contribution; optional voice capability
не должна обрастать скрытыми зависимостями Core на конкретный recognizer.

Для диктовки сначала проверить нативную availability/local Russian model на OPPO.
Android SpeechRecognizer может обращаться к удалённому сервису и не предназначен
для непрерывной диктовки. Наличие локального API не гарантирует нужную модель/язык.
Local-only не переключается молча в cloud. При недоступности распознавания —
сохранить аудио и показать «Расшифровать позже», либо продолжить текстом.
Ошибка распознавания не удаляет исходник, partial text не считается подтверждённым.
Не запускать два конкурирующих microphone consumers; capture+transcribe должен
использовать поддерживаемый pipeline, не произвольный MediaRecorder+SpeechRecognizer.
Итог диктовки — редактируемый draft задачи/заметки; назначение даты/суммы/отправка
в пространство требуют осмысленного подтверждения, без молчаливого создания.

Источники платформенных ограничений:
- https://developer.android.com/reference/android/speech/SpeechRecognizer
- https://developer.android.com/media/platform/mediarecorder
- https://developer.android.com/develop/ui/views/touch-and-input/drag-drop

## Очерёдность
1. Общие темы/геометрия и проверка существующих экранов (этот срез).
2. Доступное меню создания; затем удержание/веер как ускоритель.
3. Аудиозахват с durable файлами и backup; диктовка с явным локальным/cloud статусом.
4. Drag/drop после устойчивого контракта порядка и проверки на телефоне.
Нативные жесты/keyboard/TalkBack/ColorOS и recognition quality требуют OPPO acceptance.
