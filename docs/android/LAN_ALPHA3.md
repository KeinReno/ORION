# Alpha.3: резервный экспорт и LAN

Статус: IMPLEMENTED; физическая LAN-приёмка PENDING. Основание — поручение владельца «Хорошо, делай» 21.10.2026.

## Задача и границы
Телефон сохраняет мысли без сети и обменивается задачами/заметками с выбранным
пространством ПК. Сначала пользователь сохраняет резервную копию, затем
сопрягает устройство и отдельно входит в аккаунт. Локальное пространство
телефона остаётся независимым. Перенос в общее пространство — явное действие:
копии станут доступны его участникам согласно серверным правам.

Источник истины: ADR-0015/0016, shared-types/lan.ts и hybrid-sync.ts,
core ReplicaEngine/ReplicaStorage/SyncTransport, текущий API.
Серверные контракты и схема БД не меняются. Tasks/Notes используют свои
общие DTO, UI — отдельную мобильную поверхность.

## Экспорт
Android ACTION_CREATE_DOCUMENT сохраняет JSON в выбранное человеком место;
разрешение на всё внешнее хранилище не требуется. Успех сообщается только
после завершения записи. Отмена не считается резервной копией.
Portable backup содержит записи и черновик, а не токены, сертификаты,
идентичность sync device или инструкции повторного проигрывания outbox.
Перед импортом требуется экспорт актуальной версии локальных записей.
Формат экспорта документирован и валидируется; восстановление в UI — отдельно.

## Доверие и вход
Нативная TLS-проба получает предъявленный сертификат и прерывает рукопожатие,
не принимая его и не передавая HTTP/учётные данные.
Дальше каждый запрос использует trust anchor только этого сертификата и
точное совпадение leaf DER. Адрес LAN не является идентичностью узла.
Код HMAC-SHA256 совпадает с действующим desktop: orion-pair/v1 + nonce +
наблюдённый fingerprint. Владелец вводит код телефона на ПК.
Никаких trust-all, редиректов и передачи JWT/device token в WebView.

Android Keystore AES-GCM защищает device token, TLS pin и refresh/access tokens
в приватных preferences. Сопряжение не заменяет вход пользователя.
API bridge разрешает только список пространств и контракт hybrid sync.
401 обновляет JWT один раз; device_revoked останавливает запросы.
Смена сервера/аккаунта не смешивает replica scopes.

## Локальная копия и перенос
Отдельная SQLite-таблица по hash(node + user + workspace); миграция DB 1→2
сохраняет прежний snapshot телефона. ReplicaEngine работает с настоящим
snapshot узла, регистрацией устройства и существующими CAS/конфликтами.
Создание/правка/архив/завершение сначала фиксируются локально.
При ошибке локального сохранения engine перечитывает последний durable state.

Импорт копирует поддерживаемые поля в новое пространство. Локальные записи
не удаляются. Детерминированные target IDs и durable ledger предотвращают
дубли при повторе/перезапуске. deviceSeq и HLC берутся из удалённой replica,
а не из локальной очереди. Связи на проекты/исполнителей не переносятся
между workspace. Личные заметки не публикуются через неподдерживаемый offline API.

## Состояния и проверка
Экспорт/отмена/ошибка; TLS/код/ожидание/истечение/отказ; вход/ошибка;
выбор workspace; копия/офлайн/очередь/подтверждение/конфликт/отзыв.
Правила product-design: rule/cover-reachable-states,
rule/name-object-scope-consequence, rule/preserve-user-input,
rule/error-states-recovery, rule/permission-benefit-first.
Основной поток доступен без drag/gesture, с явными названиями действий.

Нужны unit и реальные локальные TLS-тесты (подмена leaf до отправки данных),
Keystore/SAF отдельно на Android, synthetic sync двух клиентов, потерянный
ответ, конфликт заметки, отказ диска, restart и идемпотентный импорт.
OPPO + Windows в одной физической LAN — отдельная ручная приёмка;
mock/browser/JVM результаты её не заменяют.
