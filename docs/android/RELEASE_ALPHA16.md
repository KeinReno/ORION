# Android alpha.16 — чек-листы внутри задач

22.10.2026; 0.1.15/code16. Срез Tasks на существующих публичных контрактах.
Desktop/API/public DTO/identity и схема хранения не менялись.

## Что реализовано
В редакторе сохранённой задачи раскрывается чек-лист. Пункты добавляются,
переименовываются, отмечаются выполненными и удаляются; прогресс виден в
редакторе и в строке корневой задачи. После перезапуска и в авиарежиме
пункты остаются на телефоне, потому что это обычные дочерние задачи с
существующим `parentId`, а не новая сущность и не миграция схемы.

- Добавление: непустое название до 200 символов; новый пункт получает
  следующий `sortOrder` среди соседей.
- Переименование и отметка «готово» идут через существующий offline task
  contract; незавершённые пункты остаются после открытых.
- Удаление показывает встроенное подтверждение и число вложенных пунктов.
  Каскад затрагивает потомков локально, при pull и на сервере.
- Поиск по пункту показывает его корневую задачу; сами пункты не дублируются
  в общем списке задач.
- Если задача ещё не сохранена, чек-лист объясняет, что сначала нужно
  сохранить задачу. Введённое название не теряется при ошибке записи.
- Для удалённой копии операции уходят при синхронизации; локальные — сразу
  сохраняются в SQLite. На desktop дочерние задачи видны как подзадачи.

Синхронизация: `parentId` добавлен в writable task fields существующего
`SyncOp`; проверяются существование, удаление и чужое пространство родителя.
Остальные поля, HLC, expected revisions и durable outbox не менялись.
