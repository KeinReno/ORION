# Android alpha.2: настройки и обновления

Статус: IMPLEMENTING, основание — поручение владельца 21.10.2026.
Владелец сообщил, что alpha.1 работает на OPPO Reno8 5G; это ручная обратная
связь без инструментального подтверждения всех пунктов приёмки.

## Сценарий и последствия
Пользователь хочет получать новые версии без поиска APK в чате.
Настройки устройства: системная/светлая/тёмная тема, автопроверка и необязательная
автозагрузка по Wi-Fi. Проверка не мешает задачам, заметкам и черновику.
Успех: новая версия обнаружена, APK проверен и передан системному установщику;
после обновления прежняя SQLite-база доступна.

Проверять при запуске/возврате в приложение не чаще раза за 6 часов; ручная
проверка доступна всегда. Постоянного фонового сервиса пока нет.
Автопроверка включена по умолчанию; автозагрузка выключена.
Проверяется только Android-канал этого приложения, без Windows-релизов.
Скачивание/установка по кнопке, автоматическое скачивание только по Wi-Fi,
когда пользователь включил соответствующую настройку.
Android показывает системное подтверждение установки. Первое разрешение
установки из этого источника запрашивается только при действии «Установить».

## Источник и доверие
Исходники KeinReno/ORION приватные. Предложен отдельный публичный
KeinReno/ORION-Android-Releases только с APK, описанием и android-update.json.
Владелец явно разрешил 21.10.2026 публиковать только APK и описания;
исходники остаются в приватном ORION. Токен GitHub в приложение не
встраивается. Предыдущая alpha обновляется один раз вручную.

Manifest v1: applicationId, versionCode, versionName, tag, notes, publishedAt,
APK url, size и sha256. Допустим только HTTPS URL релиза фиксированного
репозитория. Загрузка ограничена по размеру и времени, в private cache,
сначала .part, затем атомарное переименование.
До установки проверяются размер, SHA-256, package name, возрастающий
versionCode и совпадение сертификата с установленным приложением.
Редиректы разрешены только на GitHub release CDN, без токенов/произвольных URL.
Данные задач/заметок не передаются при проверке обновлений.

## Состояния
Не проверялось → проверка → актуально / доступно / ошибка сети.
Доступно → скачивание с прогрессом → готово → разрешение Android → установщик.
Отмена установщика оставляет APK готовым к повторному запуску.
Сбой сети/размера/хеша/подписи удаляет незавершённый файл, записи остаются.
Без сети приложение продолжает локальную работу.

Правила product-design: rule/cover-reachable-states,
rule/name-object-scope-consequence, rule/permission-benefit-first,
rule/error-states-recovery, rule/control-matches-cardinality,
rule/preserve-user-input. Область настройки — только этот телефон.

## Проверки и ограничения
Нужны unit-тесты совместимости старого snapshot и валидации manifest,
browser smoke настроек/темы/ошибки сети, сборка/lint APK, одинаковый сертификат
alpha.1/alpha.2. Системный установщик и сохранность при обновлении на OPPO
должны проверяться отдельно от browser smoke и проверки подписи.

## Выпуск следующей версии
Обновить versionCode/versionName в Gradle и соответствующие константы
apps/android/src/updates.ts. Собрать APK тем же ключом, выполнить проверки.
Затем (ANDROID_HOME и JAVA_HOME настроены):

```text
node scripts/android-release.mjs --apk <новый APK> --previous-apk <предыдущий APK> --notes <описание.md> --out <папка выпуска>
```

Скрипт проверит фактические package/version/certificate, создаст APK с
каноническим именем, SHA256SUMS.txt и android-update.json. Сначала загрузить APK
в release фиксированного публичного репозитория, проверить upload/digest;
только затем обновить android-update.json на ветке main источника.
В публичный репозиторий идут только README, manifest, описания, APK и checksum.
Ключи, токены, исходники, тестовые данные и локальные БД туда не копируются.
