# Предварительная дорожная карта ORION: модули и интеграции

> **Обновление статуса 19.10.2026:** это **предварительная дорожная карта 17.10**, не актуальная очередь после Platform 1.0. Pet Care уже имеет образцовую базовую реализацию `pet-care` (не путать с полным целевым ветеринарным модулем). Работы запускать по [PLATFORM](../PLATFORM.md), [STATUS](../STATUS.md) и действующим контрактам; содержание старого плана не разрешает повторно создавать существующие модули.

Дата 17.10.2026. **Предложение**, не утверждённые сроки. Это план развития **после** текущего редизайна и стабилизации. Статусы `proposed / existing-partial / deferred` — из первичного GitHub-аудита; сверять с локальным HEAD перед запуском.

## Принципы порядка
1. Релизная устойчивость, восстановление данных, роли, два реальных ПК и расширяемый интерфейс важнее количества новых модулей.
2. Сначала **доработать уже существующие** Finance, Documents, Markets, Opportunities, Health и Gateway; не клонировать их названия под новым доменом.
3. Одна предметная область → один Base; дополнительные возможности — plugin; независимые домены — Module Bridge. Спорная модель → ADR прежде кода.
4. В roadmap нет обязательных дат: срок зависит от приёмки, нагрузки и решения владельца.

## Этап P0 — завершение текущего продукта (обязательное условие)

**Цель:** закончить первую волну редизайна Grok (темы, проекты, задачи, заметки/документы, календарь), затем общие инспекторы/навигацию/долговременное состояние и остальные экраны; выполнить паритет, безопасность, data migration tests и полный gate Windows/Tauri + межустройственная работа. Руководствоваться `docs/KAIDEN_REDESIGN_CURSOR_5_AGENTS_2026-10-17/07_NEXT_WAVES.md` и `docs/DEPLOYMENT_READINESS.md`.

**Выходные условия:** единство UX, текущий HEAD с качественными тестами; backup/restore и две реальные учётные записи/машины проверены; независимость модулей и плагинов сохранена. Начинать большие интеграции, пока P0 не закрыт, не рекомендовано.

## Этап P1 — «больше пользы от уже сохранённых данных»

1. **Documents AI** — plugin для существующего Documents: OCR (опционально), иерархическая суммаризация файлов/папок, provenance, preview, local-vs-cloud provider consent. Источник — `KeinReno/razrabotka_test`. **Предлагаемый первый кандидат к реализации** (не означает, что уже есть).
2. **Agent Skills / Workflows** — шаблоны решений, карьерного анализа, рабочих обзоров для Agent Gateway, Goals, Notes, Opportunity Hub; источник — `KAIDEN_Home`. Начать с read-only каталога и одного user-approved workflow; личный контекст не публиковать в общем пространстве.
3. **Knowledge Hub** — уже описан в `docs/KNOWLEDGE_HUB.md`, начать с безопасного захвата и обработки ссылок/заметок/документов, без автопубликации. Сопоставить с существующими capture/search.
4. **Integrations Foundation** — реестр внешних connector-capabilities, управление согласиями, безопасный companion interface, offlining, обновление/откат. Это общая инфраструктура **только по отдельному ADR**, не побочный эффект первого плагина.

**Первый релиз P1:** один плагин, один end-to-end пользовательский сценарий, без новых обязательных runtime зависимостей. Не открывать ещё все интеграции.

## Этап P2 — семейная жизнь и коммуникации

1. **Pet Care (Мурчик)** — **новый самостоятельный optional domain module**, не подмодуль человеческого Health: карточка питомца, наблюдения, вес/аппетит/симптомы, лекарства по назначению ветеринара, визиты/вакцинации, вложения и уведомления. Полная концепция — `04_PET_CARE_CONCEPT.md`. Идея пользователя подтверждена, но **реализация сознательно отложена**. Первый срез без медицинских рекомендаций.
2. **Mail Center** — из `KAIDEN-AI-Mail-Filter`: локальный адаптер, review queue, объяснение сигналов, ручные действия, Tasks/Knowledge capture. Только после security review; auto-forward, SMTP и подключение реальной почты отдельными фазами.
3. **Family Operations** — дополнительные домашние сценарии (совместные обязанности, плановые дела, связка Inventory ↔ Expenses, семейные рутины) как plugins/bridges вокруг уже имеющихся Home/Inventory/Finance/Habits. **Не новый Base**, пока нет самостоятельной предметной области.
4. **Household Documents / Reminders** — расширения документов и событий для гарантий, страховок, прививок питомца и техобслуживания; отдельные privacy/ACL и связи без дублирования записей.

**Первый релиз P2:** один питомец, один член семьи, журнал+экспорт+напоминание; потом многопользовательские сценарии. Не выводить «опасное для здоровья» на автоматические советы ИИ.

## Этап P3 — специализированные рабочие пространства

1. **Creative Studio** (Stella Mortis, Prompt Constructor): optional plugin pack — prompt compositions, media assets/галерея, scene drafts, ComfyUI companion, контент-план, publish approvals. Связь с существующими Documents/Knowledge, без копии Finance/Projects. Большие бинарные файлы и чувствительные материалы требуют storage/ACL design.
2. **Investments / Markets** (Compass): довести существующий Markets UI и актуальный план `docs/INTEGRATIONS_COMPASS_FINCONTROL.md`. Шаги: watchlist/read-only quotes → companion chart → backtest/signals → journal; Finance bridge только по явному согласованию, без автоторговли и смешения currencies.
3. **Publishing / Editorial** вокруг Knowledge Hub: очереди ревью, версии материалов, каналы Telegram/сайт по согласованию пользователя, audit, revoke/rollback. Фактическая публикация — подтверждённое внешнее действие.
4. **Worldbuilder / Canvases** (LO_GOLDEN_PAX/GMap, LOS, RSS_vn): отдельный специализированный творческий модуль с картой, хроникой, персонажами и источниками; **не Core** и не обязательная установка для всех. Сначала проверить `docs/adr/ADR-0001-canvases-module.md` и возможный overlap Knowledge Hub.

## Дополнительные идеи (бэклог без приоритета)

- Personal Analytics: пользовательские отчёты из существующих модулей, но через явные read-only capabilities и scoped permissions.
- Education/Research: коллекции материалов, конспекты, карточки повторения, ссылки источников; возможно расширение Knowledge, не отдельный модуль.
- Automation recipes: «событие в модуле A → предлагаемая задача в B» с журналом и пользовательскими policy; без прямого SQL и невидимых финансовых проводок.
- Integration inspector: где хранятся внешние ключи, какие данные передаются, последняя синхронизация, отключение/отзыв.
- Household dashboard «Сегодня дома»: питомцы, дела, покупки, расходы, напоминания, но как **вид**, а не новая база.

## Формальные gates для запуска каждого нового направления

1. Владелец подтверждает ценность и **что не входит в MVP**; назначен сценарий.
2. Сверено, не существует ли уже эквивалент в current HEAD.
3. Выбран Core/Base/plugin/bridge по архитектуре; `MODULE.md`, `AI_CONTEXT.md`, manifest, версии и нужный ADR.
4. Согласованы data ownership, разрешения, видимость между пользователями и пространствами, retention, API/sync/snapshot/backup.
5. Малый функциональный вертикальный срез с тестом отключения/восстановления данных, негативными permission tests, проверкой тем, мобильного UI и keyboard.
6. Release gate: чистая изолированная БД, CI + вручную проверенная десктопная сборка для затронутых функций; rollback и release note.

## Решения, которые владелец может принять позже

- P1: что раньше — AI-конспекты документов или каталог Agent Skills?
- P2: Pet Care в личном, семейном или обоих типах пространств по умолчанию? Кому разрешено видеть ветеринарные документы?
- Mail: есть ли вообще потребность переносить письма внутрь ORION или достаточно ссылок/уведомлений?
- Creative Studio: независимое приложение-компаньон или встроенное редакционное представление?
- Markets: оставить Compass отдельным терминалом с deep links или подключать часть данных в ORION?

До этих решений **не заказывать** кросс-модульные схемы и миграции в production.
