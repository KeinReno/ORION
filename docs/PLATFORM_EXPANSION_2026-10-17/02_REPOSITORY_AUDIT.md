# GitHub-аудит: что имеет смысл подключить к ORION

Срез: 17.10.2026. Проверены доступные репозитории двух подключённых GitHub-аккаунтов, корневые структуры и README/ключевые архитектурные документы. **Это первичный инвентаризационный аудит, НЕ полноценный построчный code/security review**. Возможности из README означают *заявленное* состояние проекта, не пройденную нами живую приёмку.

## Что уже есть в ORION — не дублировать

На момент анализа в `apps/web/panels/` есть `HealthPanel.tsx`, `MarketsPanel.tsx`, `OpportunitiesPanel.tsx`, `DocumentsPanel.tsx`; в `apps/api/src/` — `health/`, `markets/`, `opportunities/`. В `apps/web/plugins/` обнаружены `finance-obligations`, `finance-forecast`, `finance-quick-entry`, `finance-exchange-rates`, `documents-office`, `opportunities-*`, и др. Поэтому **не** заводить заново «новый Finance», «новый Markets», «новую базу профилей» или «новое Human Health».

`docs/INTEGRATIONS_COMPASS_FINCONTROL.md` уже содержит решения:
- Compass → отдельное направление Investments и Finance ↔ Investments bridge, осторожный read-only первый срез; без доступа через чужие cookies и без автоторговли.
- FinControl (не представлен самостоятельным GitHub-репозиторием в текущем списке) → **не второй Finance**; выборочные плагины и перенос данных после проверки локального источника.
- `docs/KNOWLEDGE_HUB.md` уже описывает Knowledge Hub и publishing pipeline; не клонировать под новым названием.
- `docs/HEALTH_MODULE_SPEC.md` содержит концепцию человеческого здоровья, но её начальный статус может устареть: в коде уже есть `health/` и UI. На старых заголовках вывод о текущей готовности не строить.

## Рекомендуемые направления переноса

### А. Почтовый центр из KAIDEN-AI-Mail-Filter
**Первый срез:** просмотр карантинной очереди и решения классификатора, безопасное обозначение причин решения, manual review и связь письма с заметкой/задачей. Защита POP3/SMTP секретов на серверной стороне. Исходники Python лучше оставить отдельным локальным companion с версионированным API, а ORION сделать владельцем настроек доступа и links. Не переносить учётные данные, журналы реальных писем и пользовательскую SQLite в Git.
**Безопасность:** запрет незапрошенной автопересылки, явный approval, антивирус/вложения sandbox, HTML sanitization, SSRF/URL scanning, ограничение LAN expose. Миграция на OAuth/IMAP/других поставщиков — отдельный scope, не имитировать поддержку.

### B. AI-конспекты документов
**Первый срез:** выбрать документы текущего workspace → локально извлечь текст → показать preview и выбор detail → запросить явное согласие, если содержимое уходит во внешний LLM → сохранить **новую** заметку/редакцию только по команде. Источник/версия/hash документа и LLM-provider указываются в результате; исходник неизменяем. OCR как отдельная optional capability. Экспорт приватных документов во внешние провайдеры запрещён по умолчанию.

### C. KAIDEN_Home → agent skill library
**Первый срез:** каталог воспроизводимых шаблонов интервью/анализа решения, привязка к Goals/Notes/Opportunity Hub по существующим scoped actions. Personal reflections остаются личными; члены workspace не получают автоматический доступ. Не переносить внутренние команды Cursor в продукт как системные привилегии.

### D. Compass и Stella Mortis — поздние направления
Здесь высока цена интеграции: Python/React/Tauri companion, media pipelines и отличающиеся модели данных. Перед любой передачей кода зафиксировать source revision, лицензии/авторство, security model, schema mapping и negative tests. Лучше независимый импорт/публикация через API, чем слияние двух больших приложений в один монолит.

## Что требует следующего точечного ревью до выполнения

| Направление | Что проверить в коде |
|---|---|
| Mail | открытые API и секреты, модель очереди/правил, сканирование вложений, audit отправки |
| Documents AI | качество/безопасность extraction, OCR, chunking, prompt injection и provenance |
| KAIDEN skills | форматы, персональные/публичные данные, совместимость с Agent Gateway |
| Investments | фактический Markets Base в ORION, контракт Compass API, licensing market data |
| Creative | формат библиотеки, хранение больших медиа, ComfyUI, публикующие credentials, sandbox |
| Pet Care | **не нужен перенос кода**: проектировать схемы и UX с нуля по выбранным требованиям |

**Вывод:** немедленное «слить все репозитории в ORION» ухудшит архитектуру. Лучший путь — выборочно переносить возможности в существующие домены через plugins/bridges, а самостоятельные новые предметные области оформлять как независимые modules.
