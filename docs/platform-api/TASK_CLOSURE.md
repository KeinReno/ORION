# Синхронное закрытие задачи: Module Bridge

Integration API 1.2.0, Platform API 1.3.0; [ADR-0027](../adr/ADR-0027-task-closure-bridge.md).
Публичный серверный вход: `apps/api/src/tasks/public/task-closure-registry.ts`.

Host и сосед импортируют `TaskClosureRegistryModule`. Он не импортирует TasksModule или TimeModule.
Сосед регистрирует одного обработчика на owner id; повторная регистрация ошибочна.
Владелец задачи проверяет права, workspace и ревизию, изменяет статус и вызывает
`TaskClosureRegistry.closeTx(tx, {workspaceId, taskId})` при переходе открытой задачи в закрытую.
Закрытые статусы определяются существующим `isTaskClosed` (done/canceled).

Каждый обработчик обязан использовать переданный Prisma transaction, сохранять RLS-контекст,
ограничивать свои записи workspaceId, проверять доступность собственного компонента и не выполнять
внешних эффектов. Новые транзакции, переключение ролей и запись чужих таблиц запрещены. Handlers
вызываются последовательно; ошибка прерывает команду и откатывает всё. Пустой registry допустим.

Time регистрирует собственный обработчик остановки первого работающего таймера задачи. Отключённый
или отсутствующий Time не задерживает закрытие задачи и не уничтожает сохранённое время. endedAt
строго позже startedAt; уже остановленная запись не переписывается. Семантика нескольких участников,
которые одновременно считают время одной задачи, этим переносом не меняется.

Асинхронное `tasks.task.closed` остаётся в outbox для уведомлений; этот bridge не добавляет новой
подписки к outbox и не меняет его envelope или версию Event API. Регистрация не выдаёт прав.
