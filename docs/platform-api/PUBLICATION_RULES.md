# Правила публикации Tasks

Контракт: [ADR-0035](../adr/ADR-0035-publication-rules.md). Platform API **1.10.0**,
Integration **1.9.0**, Event API **1.1.0**. Первый backend-срез; интерфейс управления
правилами, согласующие, Family presets, Knowledge rules и Orion Link сюда не входят.

Shared владеет правилами и публикациями. `PublicationRegistry` / `PublicationAdapter`
— существующая публичная точка расширения. Новый необязательный метод
`ruleCandidates(tx, config, sourceId?)` реализован Tasks. Host не читает Task или
Project и не импортирует TasksService. Все фильтры и проекции источника — у адаптера.

## API, JWT владельца источника

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/publication-rules` | Создать остановленное правило |
| GET | `/publication-rules` | Только собственные доступные правила |
| GET | `/publication-rules/:id` | Конфигурация, revision, состояние, до 20 записей истории с сохранением последнего подтверждения |
| GET | `/publication-rules/:id/preview` | Кандидаты, точные проекции, участники, fingerprint |
| PATCH | `/publication-rules/:id` | `{expectedRevision, config}`, только после остановки |
| POST | `/publication-rules/:id/enable` | `{expectedRevision, fingerprint, consentFutureRecords:true}` |
| POST | `/publication-rules/:id/pause` | `{expectedRevision}`; остановить дальнейшие обновления |
| POST | `/publication-rules/:id/run` | `{expectedRevision}`; явно сверить включённое правило |
| DELETE | `/publication-rules/:id` | JSON `{expectedRevision}`; удалить правило и отозвать его активные публикации |

Конфигурация:

```json
{
  "sourceWorkspaceId": "11111111-1111-4111-8111-111111111111",
  "workspaceId": "22222222-2222-4222-8222-222222222222",
  "name": "Задачи для дома",
  "projectIds": [],
  "statuses": ["todo", "in_progress"],
  "includeText": false,
  "includeDueAt": false,
  "allowStatus": false
}
```

`workspaceId` — целевая существующая неперсональная зона; источник и получатель
различаются. Пустой projectIds/statuses означает «любые» в исходном пространстве.
Тип первого среза фиксирован: Tasks. Заголовок и статус передаются всегда; текст,
срок и разрешение менять статус включаются явно. Остальные поля, вложения и связи
не передаются. Ссылки в передаваемом тексте очищаются как в ручных публикациях.
Приватные сведения, написанные обычным текстом, не распознаются автоматически:
владелец отвечает за выбор фильтра и передачу текста будущих задач.

Предпросмотр ограничен **100 кандидатами**; превышение даёт 400 с требованием
сузить фильтр, а не усечённый «успешный» список. `count` — совпавшие задачи,
`publishableCount` — доступные этому правилу, `items[].action`:
`publish` / `update` / `excluded`. Исключённые — tombstone или запись, которой уже
управляет ручная публикация/другое правило. Fingerprint связывает подтверждение с
конфигурацией, ревизиями источников, текущими публикациями и составом участников.
Изменения между просмотром и включением дают 409. Включение и первая публикация
атомарны; согласие на будущие записи и fingerprint записываются в историю.

Общая зона сохраняет обычную модель членства: приглашённые впоследствии участники
могут читать её публикации. Предпросмотр текущих участников не создаёт персональный
неизменный список адресатов.

Источник/получатель правила неизменны; для других пространств создаётся новое
правило. Редактирование работающего правила даёт 409. Пауза сохраняет последний
опубликованный снимок и уже выданное разрешение менять статус; для удаления доступа есть отзыв публикации или удаление
правила. Возобновление требует свежего предпросмотра и согласия.

## Доставка, остановка и история

TasksService создаёт `tasks.task.changed` с payload `{id}` внутри той же транзакции
при создании, обновлении, удалении и создании следующей повторяющейся задачи.
Нет тел/описаний в outbox. Тип id не сужает допустимые прежние id задач до UUID.
Подписчик `tasks.publish-selected-tasks` зарегистрирован в существующем каталоге;
source Tasks disabled → стандартный `skipped_disabled`.

При доставке заново читаются текущее правило, источник и права. Старое событие
не воспроизводит старый текст. Source owner + членство в target + доступность Tasks
проверяются под пользовательской RLS; фоновое системное перечисление не выдаёт
прав на источник. Повтор не создаёт новую публикацию и не повышает её revision,
если разрешённая проекция не изменилась. Сравнение содержимого также ловит изменения
планирования без повышения source revision.

Дополнительная сверка раз в 30 секунд использует существующий BackgroundJobsService:
20 правил за проход, курсор с обходом полного набора. Это покрывает импорт/sync и
изменения вне TasksService. Для большого числа правил задержка увеличивается.
Ошибки доставки попадают в стандартные retries outbox; сверка хранит обобщённую
ошибку в правиле. Данные источника не попадают в сообщение об ошибке.

При потере прав/доступности модуля фоновая проверка останавливает правило и отзывает
его публикации. Обновления асинхронны: мгновенный отзыв на всех клиентах и физическое
стирание офлайн-кеша не заявляются. Правило не включается само после восстановления
прав или включения модуля. При превышении лимита полного прохода фиксируется ошибка;
нужно остановить правило и сузить фильтр.

Выход из фильтра/удаление оригинала отзывает публикацию. Tombstone
`(ruleId,sourceId)` сохраняется и не активируется автоматически при возврате задачи.
Новый ruleId — новое явное решение владельца. Ручные публикации и активные публикации
других правил не перехватываются: сохраняется исключение, чтобы их последующий
отзыв не породил новый автоматический доступ. Независимые копии сохраняются.

## Хранение и восстановление

`PublicationRule`: source workspace, owner, target id, config, enabled, revision,
lastRunAt/lastError и ограниченная история. Последнее явное согласие сохраняется
при ротации записей фоновых проходов. FORCE RLS — только создающий source owner.
Другие участники, включая target owner, не читают конфигурацию и id приватных источников.
Recipient DTO публикации не получил ruleId или другие приватные идентификаторы.

Политика snapshot: правило включено в backup источника, при restore принудительно
останавливается. Restore любой стороны отключает также связанные правила в чужих
невидимых пространствах через узкую существующую definer-функцию отзыва. Публикации
восстанавливаются отозванными. Replica sync правил запрещён (`not-synced/never`).
Миграция схемы требует полного установщика; это не payload для Windows beta24.
