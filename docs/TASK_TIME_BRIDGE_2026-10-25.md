# Tasks → Time: второй перенос межмодульной зависимости

Исходная база: master `b2077d023e713ef9551e15d4cdf7dc4c50ef5e41` (PR #68).
Реализация в `codex/reference-moves-stage2`; решение — [ADR-0027](adr/ADR-0027-task-closure-bridge.md).
Это перенос существующего поведения по утверждённой карте Module Bridges, без изменения UI, schema и прав.
Код переноса зафиксирован в `5ab4c3faa1c0d755dfbf6189547eb4518643dc2a`; последующие изменения —
уточнения браузерного теста и запись результатов.

## Что изменилось

- TasksService.updateTx больше не читает/изменяет TimeEntry. После успешного перехода открытой задачи в
  done/canceled он вызывает публичный [TaskClosureRegistry](../apps/api/src/tasks/public/task-closure-registry.ts).
- Владелец Time регистрирует собственную остановку таймера, проверяет включённость Time и workspaceId.
  Контрактный Nest-модуль не импортирует конкретные Tasks/Time модули; с пустым registry Tasks продолжает работать.
- Handler выполняется в исходной транзакции. Ошибка откатывает запись статуса, таймер и activity; последующая
  ошибка проверки зависимостей откатывает также уже опубликованное событие outbox. Async notifier не меняется.
- Сохраняется прежний выбор первого найденного работающего таймера задачи и защита endedAt > startedAt.
  Новая политика для нескольких участников одной задачи этим переносом не вводится.
- Удалено одно model-исключение: **64 → 63**; файлов исключений остаётся **27**, service-исключений **19**.
  Новое расширение списка не потребовалось. Time-handler имеет `.service.ts`, поэтому проверяется существующим
  architecture-check, а не спрятан в неподконтрольном файле. Пределы checker (raw SQL/произвольные aliases) сохраняются.
- Integration API **1.2.0**, Platform API **1.3.0**: аддитивный контракт. Snapshot и capability map обновлены;
  новый public path/registry виден в карте и защищён unit-проверкой. Остальные версии контрактов не меняются.

## Проверки

Windows / PowerShell, отдельная PostgreSQL 16 на 127.0.0.1:5444, синтетические
`orion_platform_integration` и `orion_platform_browser`. Рабочая БД и пользовательский checkout не изменяются.

Focused: **8 integration passed** (11.42 с). HTTP done/canceled останавливают таймер до ответа; чужому
пользователю отказано, чужой workspace не меняется; будущий startedAt получает endedAt +1 с; остановленная
запись не переписывается; stale revision оставляет таймер; ошибки позднего handler/валидации откатывают всё.
Проверено приложение Nest с физически исключённым TimeModule: Tasks закрывает задачу без Time handler.

Обычный API отключения Time уже возвращает 409 при работающем таймере. Это поведение сохранено и проверено;
отдельная синтетическая persisted off-конфигурация моделирует старый snapshot, при закрытии задачи её запись
таймера не изменяется. Это fixture, не новый пользовательский способ обхода запрета отключения.

Первый focused запуск выявил проблемы тестовой оснастки: decorator на классе в test-каталоге не
трансформировался раннером; заменён эквивалентным вызовом Module(...)(Class). Затем уточнены ожидаемые
существующие ответы 409 при отключении Time и 404 для отсутствующей зависимости. Продуктовые guards не ослаблены.

## Что остаётся

Tasks всё ещё знает Project/Milestone, Time — Project/Task; это следующие отдельные переносы.
Не добавлены общий startup/background compatibility enforcement, горячая установка server modules или новый
Windows installer. Проверка отсутствующего TimeModule доказывает самостоятельность HTTP Tasks в данном составе
Nest, а не готовность менеджера установки произвольных компонентов. Опубликованная beta 21 не обновляется этим PR.
