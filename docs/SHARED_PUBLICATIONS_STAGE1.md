# Общие публикации — первый этап

Дата: 24.10.2026. Класс: implementation report. База: `858cfac`; ветка `codex/shared-publications-stage1`. Точное состояние задаёт commit этого отчёта. Решение: [ADR-0024](adr/ADR-0024-shared-publications.md).

## Что реализовано

В панели «Доступно мне» появился раздел «Общие публикации». Общая зона — существующее неперсональное пространство с его участниками и ролями. Старый список предоставленного доступа сохранён отдельной вкладкой.

1. «Поделиться»: владелец исходного пространства выбирает задачу или Knowledge, целевую зону и поля. Предпросмотр показывает фактически передаваемый текст. Fingerprint связывает подтверждение с просмотренной ревизией; изменение оригинала требует повторного просмотра.
2. «Показывать у меня»: личное закрепление в выбранном пространстве, доступное через одноимённый список панели. Закрепление не расширяет права. Отзыв публикации или потеря членства скрывают её.
3. «Сделать личную копию»: самостоятельный объект в личном пространстве, с отметкой происхождения, без последующей синхронизации. Задача создаётся как новая `todo`, Knowledge — `private/draft`. Копия сохраняется после отзыва.
4. Владелец может разрешить участникам менять статус оригинальной задачи. Изменение статуса, ревизии публикации и журнал операции фиксируются одной транзакцией. Устаревшая ревизия даёт конфликт; одинаковый operationId не применяет изменение дважды. Другие поля и Knowledge остаются только для чтения.
5. «Обновить из оригинала» доступно издателю и требует нового предпросмотра. Публикация не подхватывает новые приватные поля автоматически.
6. До подтверждения статуса клиент хранит локальное намерение отдельно от опубликованного состояния. Namespace включает API-адрес, пользователя и id публикации. После потери ответа или перезагрузки доступна ручная повторная отправка; удаление намерения не выдаётся за отмену уже применённой операции.

## Границы данных и архитектуры

- Shared владеет публикациями, закреплениями и журналом операций. Tasks и Knowledge регистрируют типизированные адаптеры через `PublicationRegistry`; Shared не импортирует конкретные реализации этих модулей.
- В DTO нет sourceWorkspaceId/sourceId/publisherId/sourceRevision. Источники, вложения, категории, исполнители, проект и связи не передаются. Текст выводится как обычный текст, без Markdown/HTML-рендеринга и загрузки внешних ресурсов. Приватные сведения, написанные обычным текстом, проверяет сам издатель в предпросмотре.
- Все три таблицы имеют ENABLE/FORCE RLS, включены в реестр резервных копий, исключены из импорта пространств и обычной replica-синхронизации. Restore целевой зоны восстанавливает публикации только отозванными.
- Restore источника отзывает публикации даже в чужих невидимых зонах. Узкая SQL-функция `revoke_publications_from_source` проверяет текущую роль owner исходного пространства и умеет только отзывать доступ. Это исключает совпадение старой ревизии оригинала после восстановления с ещё действующим разрешением.
- Проверки членства, разрешения изменения и включённых модулей повторяются на сервере при операции. Конфликт Tasks не возвращает получателю приватный DTO оригинала.

## Проверка на Windows

Проверки выполнялись в отдельном managed worktree. PostgreSQL поднят отдельно на `127.0.0.1:5444`; использованы только синтетические базы `orion_shared_publications_test` и `orion_shared_publications_browser`. Пользовательская БД и файлы основного checkout не мигрировались.

| Полный существующий unit-набор | 1 447 passed |
| Новые тесты проекции/входных контрактов | 4 passed |
| Контракты плагинов | 11 passed |
| Классификация синхронизации | 6 passed |

| Architecture / module registry / module docs | passed |
| Production API/web build | passed |
| Chromium E2E | passed, включая локальное ожидание после перезагрузки и экран 390 px |

HTTP-сценарии проверяют изоляцию оригинала и его зависимостей, запрет доступа постороннему, редактирование только по разрешению, повтор операции, одновременные конфликтующие статусы, отзыв, удаление участника, отключение модуля, копию и закрепление, обновление только издателем и восстановление источника в том числе с публикацией другого владельца в невидимой зоне.

Браузерный сценарий проходит предпросмотр → публикацию → сбой сети → перезагрузку → повторную отправку → закрепление → копию → отзыв; проверяет отсутствие горизонтального переполнения на 390 px. Локальные screenshots: `test-results/publications-desktop.png`, `test-results/publications-narrow.png`.

Воспроизведение: `pnpm install --frozen-lockfile`, `pnpm db:generate`; затем интеграционные тесты с DATABASE_URL/APP_DATABASE_URL отдельной тестовой БД. `scripts/e2e-local.mjs e2e/publications.spec.ts` пересоздаёт только БД, указанную в E2E_DATABASE, собирает API/web и запускает браузер. Не направлять этот сценарий на рабочую БД.

## Что не заявляется готовым

- Между независимыми серверами ORION публикации пока не передаются. Клиенты работают с одним авторитетным сервером; выключенный сервер не подтверждает изменение.
- Нет универсальной очереди согласования чужих правок, совместного текстового редактирования и автоматических правил публикации.
- Списки ограничены последними 200 публикациями. Закрепления ещё не встроены в обычные списки Tasks/Knowledge.
- Установщик Windows, работа на двух физических устройствах и Android-паритет не проверены этим этапом. Релиз не опубликован; основной checkout не переключён на эту ветку.
