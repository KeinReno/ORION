# Подключение в домашней сети и браузер — 19.10.2026

Статус: рабочий срез после beta.5, ветка `codex/lan-connect-flow`.
Направление задаёт PLATFORM.md; транспорт и доверие устройств — ADR-0015.

## Краткий brief

- Пользователь: два человека за своими Windows-компьютерами в одной Wi-Fi сети.
- Задача: найти компьютер с ORION и подключиться к разрешённым пространствам.
- Сейчас: поиск запускается вручную; «Выбрать» только заполняет адрес/порт; затем нужна ещё одна кнопка.
- Результат: автоматический поиск при открытии раздела → подключение по имени компьютера → код → вход на хосте.
- Признак успеха: для найденного компьютера не требуется вводить или переносить IP/порт.
- Объект: компьютер с включённым приёмом подключений, а не список чужих пространств.
- Последствие: после подтверждения это окно работает с выбранным хостом; локальные данные остаются на месте.
- Права: публикация хоста остаётся явным действием; код подтверждает владелец, затем действуют обычные права пользователя.
- Вне среза: синхронизация двух независимых баз, обход роутера/брандмауэра, автоматическое открытие портов.

## Решения

- `rule/smallest-intervention`: существующий mDNS-поиск запускается при открытии раздела, найденная карточка сразу подключает.
- `rule/inline-before-modal`: ручной адрес и имя клиентского устройства раскрываются отдельно как запасной путь.
- `rule/cover-reachable-states`, `rule/error-states-recovery`: поиск, пустой результат, ошибка, ожидание кода, отказ, истечение заявки и ошибка активации имеют действие восстановления.
- `rule/name-object-scope-consequence`: обнаружение показывает компьютеры; пространства доступны только после доверия и входа. Включение хоста не становится автоматическим.
- `rule/keyboard-complete-flow`: поля подписаны, подключение доступно с клавиатуры, код получает фокус.

## Браузер: подтверждённое и неизвестное

`apps/web/components/browser-page.tsx` использует sandboxed iframe, не самостоятельную браузерную вкладку WebView2.
В `browser-url.ts` Google/Bing ошибочно описаны как гарантированно поддерживающие встраивание.
Cloudflare документирует невозможность Challenge Pages в cross-origin iframe и ограничения embedded browsers:
https://developers.cloudflare.com/cloudflare-challenges/concepts/how-challenges-work/
https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/

Это объясняет класс возможных сбоев, но не устанавливает провайдера проверки и точную причину на ноутбуке Варвары.
Уточняется, какие поисковики затронуты и воспроизводится ли проблема в обычном браузере на той же машине.
Владелец подтвердил: проблема во всех поисковиках, результат нужен **внутри ORION**.
Решение: отдельный нативный WebView внутри панели desktop; подмена User-Agent не считается исправлением.

Brief браузера: человек ищет информацию и открывает сайты, оставаясь в рабочей среде. Результат — самостоятельный контекст сайта с сохраняемой сессией, адресной строкой и навигацией. Браузерные cookies хранятся отдельно от профиля интерфейса ORION. Сайты не получают его tokens/IPC. Антибот внешнего сайта остаётся решением этого сайта; отсутствие проверок не обещается.

- `rule/smallest-intervention`: сохраняются нынешние вкладки и dock-панели, меняется движок отображения страницы в desktop.
- `rule/cover-reachable-states`: WebView скрывается при скрытии панели и открытии HTML-диалога/меню; закрывается при размонтировании, включая позднее завершение создания. Ошибка создания даёт явный повтор, без бесконечного цикла попыток.
- `rule/preserve-mental-model`: обычные HTTP(S)-адреса, «Назад», «Вперёд», «Обновить»; никакого переноса cookies из сторонних браузеров.

Технически: Tauri child WebView требует feature `unstable` у tauri 2.11.5. Обновления зависимостей должны повторять нативную приёмку. Команды проверяют доверенный origin вызывающего интерфейса, идентификатор дочерней вкладки и HTTP(S)-адрес. Страницам браузера запрещено управление браузером даже при попытке перехода на origin ORION. Прямые локальные адреса приложения не открываются. CSP интерфейса и разрешения capabilities не расширены. Глобальная обработка deep link использует главный WebView, поскольку после добавления child окно перестаёт быть `WebviewWindow` в терминах Tauri.

Ограничения среза: в веб-версии остаётся iframe; popup-ссылки внутри нативного браузера открываются в текущей странице, поэтому сложные OAuth popup-flow отдельно не приняты. После смены IP хоста запасной путь — новый поиск/подключение; бесшовное восстановление привязки по nodeId — следующий отдельный срез.

## Проверка

- Windows, срез ветки после `35e8dd3`: 1336 unit-тестов, typecheck, lint (0 ошибок, 27 предупреждений), architecture-check, plugin-contract-check (10), module registry/docs — passed.
- Cargo native tests: запрет опасных схем, локальных origin приложения и URL со встроенными credentials — passed.
- Три jsdom-теста жизненного цикла: создание/событие навигации/скрытие под диалогом/закрытие, позднее завершение создания после unmount, ошибка без бесконечных попыток — passed.
- Живой браузер, синтетический HTTP API без БД: автопоиск, прямое подключение с адресом и портом из найденной карточки, фокус на коде, отказ и повтор, пустой поиск, ошибка с сохранением ручного ввода, HTML-валидация порта 70000 — passed. Проверены широкая и 390px-панель; это проверка ширины компонента, не физического мобильного экрана.
- Настоящий WebView2, изолированный debug executable (`com.orion.browser-smoke`, скрытое тестовое окно, без пользовательской БД): создание, загрузка example.com, hide/show, переход и событие завершения загрузки Google, reload, close — passed (`BROWSER_SMOKE PASS`). Это нативная интеграционная проверка команд; содержимое выдачи и прохождение антибота она не подтверждает.
- В конце нативного теста Chromium вывел `Failed to unregister class Chrome_WidgetWin_0, Error=1412`; успешные действия и PASS были записаны до завершения процесса. Визуальная приёмка нативного интерфейса отдельно не заявляется.
- Два реальных ПК, роутер пользователя, антибот на ноутбуке Варвары, DPI/мониторы и сложная popup-авторизация — not run.

Повтор native smoke: debug-сборка с отдельным identifier `com.orion.browser-smoke`, origin devUrl в конфигурации, `ORION_BROWSER_SMOKE=1`. `browser_smoke.rs` исключён из release-сборки, требует точного тестового identifier и закрывает своё приложение по окончании. Никогда не направлять тест на данные рабочего профиля.
