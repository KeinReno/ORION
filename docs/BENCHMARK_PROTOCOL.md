# Протокол бенчмарков запуска ORION-R

**Назначение:** воспроизводимые измерения времени запуска приложения, закрывающие реестр #4–7. Любая оптимизация скорости принимается только по этому протоколу: «стало быстрее» = медиана `phase=ready` снизилась относительно базовой линии на том же железе и том же режиме.

## Что измеряется

| Метрика | Кто пишет | Смысл |
|---|---|---|
| `payload-select` | Rust runtime (`[orion-runtime]`) | выбор версии приложения, проверка манифеста |
| `postgres-status` | Rust runtime | опрос существующего кластера |
| `postgres-start` | Rust runtime | запуск postmaster (только warm/первый старт) |
| `postgres-identity+provisioning` | Rust runtime | создание ролей/БД, grants |
| `prisma-migrate` | Rust runtime | миграции схемы |
| `phase=preparing/database/migrations/server` | Tauri-шелл (`[startup]`) | переходы фаз с момента spawn runtime |
| `phase=ready` | Tauri-шелл | API отвечает на health и принадлежит нашему Job — **главная метрика** |
| `supervise-direct-lifetime` | Rust runtime | полное время жизни runtime до штатного выхода |

## Как запускать

```powershell
# Тёплый старт (данные на месте, типичный день пользователя), 5 прогонов:
powershell -ExecutionPolicy Bypass -File scripts\benchmark-startup.ps1 -Runs 5 -Mode warm

# Холодный старт (профиль временно отложен, initdb с нуля), 3 прогона:
powershell -ExecutionPolicy Bypass -File scripts\benchmark-startup.ps1 -Runs 3 -Mode cold
```

Параметры: `-AppPath` (по умолчанию установленный `%LOCALAPPDATA%\ORION-Rust\ORION-Rust.exe`), `-TimeoutSec` (ожидание ready, по умолчанию 120), `-OutDir` (куда писать отчёт, по умолчанию рядом с репозиторием в `benchmark-reports/`).

Скрипт на каждый прогон: убивает остатки процессов → (cold: откладывает каталог данных) → очищает `launcher.log` → запускает приложение → ждёт `phase=ready` → гасит процесс → разбирает лог. В конце считает min/медиану/p95/max по каждой метрике и пишет `benchmark-report-<режим>-<дата>.md` + `.json` в `-OutDir`.

## Правила честного измерения

1. **Одно железо, один режим** — сравнивать только между прогонами одного запуска скрипта или при неизменных условиях (антивирус, нагрузка ОС).
2. **Базовая линия** фиксируется в отчёте; перед каждым крупным релизом прогоняется заново и кладётся в `benchmark-reports/`.
3. **Исключения Defender** (`scripts/defender-exclusions.ps1`) должны быть применены до измерений — иначе цифры измеряют антивирус, а не Орион.
4. Закрытой приложением должно быть окно (шелл считает готовность до показа UI), поэтому `phase=ready` — нижняя граница ощущаемой скорости, UI поверх неё добавляет свой рендер.
5. Холодный режим удаляет созданный за прогон профиль и возвращает исходный — данные пользователя не пострадают; всё равно не запускай cold, пока Орион работает с несохранённым состоянием.
