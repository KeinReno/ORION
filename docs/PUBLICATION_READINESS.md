# Подготовка ORION к публичной публикации
> Чек-лист, не подтверждение безопасности. README не делает исходники безопасными для раскрытия.

## Модель публикации
- Публичная витрина: описание продукта, проверенные скриншоты и выпуски.
- Техническая документация: только то, что владелец согласен раскрыть.
- Внутренние отчёты, инструкции агентов, инфраструктура, логи и рабочие материалы: отдельно в приватном контуре.

## Проверки до изменения видимости
- [ ] Выбрать: публиковать исходники или отдельный showcase. Для закрытых исходников оставить ORION приватным.
- [ ] Проверить всю Git-историю, ветки, теги, PR и release assets на токены, ключи, пароли, приватные адреса и персональные данные.
- [ ] При обнаружении секретов сначала отозвать и заменить их: удаление из текущего коммита не очищает историю.
- [ ] Проверить конфигурации, файлы окружения, базы, дампы, журналы, бэкапы, скриншоты и артефакты.
- [ ] Проверить docs, AGENTS.md, CLAUDE.md, ADR и отчёты на внутреннюю информацию. Отсутствие ссылки в README не скрывает файлы.
- [ ] Проверить права на изображения, лицензии и сторонние материалы.
- [ ] Проверить GitHub Actions, права workflow, environments и публикуемые артефакты.
- [ ] Вручную согласовать список публикуемых материалов и релизов.
- [ ] Отдельно подтвердить изменение visibility; текущий PR его не выполняет.
