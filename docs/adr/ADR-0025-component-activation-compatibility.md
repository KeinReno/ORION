# ADR-0025: совместимость при включении встроенных компонентов

Статус: принято для реализации по поручению владельца 25.10.2026.

Подключаемые модули и плагины уже объявляют version, но производный манифест заменяет её константой; включение не проверяет диапазоны. Сохраняем существующий lifecycle и состав продукта.

Исходный JSON может дополнительно объявлять `requires.platform`, `requires.modules` (id обязательных модулей), `requires.moduleVersions` (диапазоны версий только этих модулей) и `requires.contracts`. Генератор сохраняет исходную версию и требования. При отсутствии requires сохраняются прежние defaults; у плагина модуль-хозяин всегда обязательный. Формат диапазонов остаётся ограниченным: exact, ^, ~, >=; без prerelease и составных выражений.

Сервер проверяет включение внутри транзакции после проверки прав и блокировки workspace, до записи состояния и вызова hooks. Несовместимость платформы, контракта, отсутствующая/выключенная обязательная зависимость, несовместимая версия или цикл дают 409 `component_incompatible` с диагностикой. Проверяются и транзитивные обязательные зависимости. Автоматического включения соседей нет. Выключение доступно даже несовместимому компоненту; данные и overrides зависимых не удаляются. Мягкие зависимости не блокируют включение.

Это проверка встроенных компонентов, а не sandbox permissions и не установка стороннего серверного кода. Внешний extension runtime сохраняет собственные engine/hash approval проверки. Изменение публичного контракта совместимо: новое поле moduleVersions необязательно; контракт модуля повышается минорно.

Снимок host-контрактов учитывает CORE_MODULE_IDS и их permissions; зарегистрированные modules-ext и их операции остаются в полных runtime-каталогах и capability map, но версионируются source metadata. Добавление собственного модуля не требует ручного изменения версии Core только из-за новой записи каталога. Поверхности UI-слотов, host API и семантика permission framework продолжают проверяться снимком. create:module обновляет также карту возможностей.

Приёмка: строгие тесты диапазонов ^0.0.x/^0.x.y/^1.x.y; проверка реальных source metadata; HTTP owner/member, incompatible enable без смены состояния/hooks, выключение без потери данных; default-full/plugins-off parity.
