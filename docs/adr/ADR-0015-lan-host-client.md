# ADR-0015: LAN Host / Client, обнаружение, доверие устройств, шифрование

Статус: принято и реализовано (ТЗ-04, 15 октября 2026). Не проверено на двух физических ПК — см. «Что не проверено».

## Контекст
Два компьютера в одной сети (разные пользователи) должны работать с общим узлом ORION без облака. Этап 1 дорожной карты: один узел-хост, остальные — клиенты. Базы не синхронизируются (это ТЗ-06).

## Результаты этапа 0 (исследование)

1. **URL API в desktop-клиенте.** Задаётся при сборке (`NEXT_PUBLIC_API_URL`, `apps/web/lib/api-base.ts`; installer собирается с `http://localhost:4000`), в рантайме не меняется. Tauri-оболочка (`main.rs`) только поднимает лаунчер и ждёт `127.0.0.1:4000/system/health`. CSP разрешает `connect-src` только loopback + `'self'`. **Решение:** окно всегда говорит с локальным API; в режиме клиента путь получает префикс `/_remote`, и локальный API проксирует запрос на узел. Пересборка, смена CSP и правки Rust не нужны.
2. **Переключение local↔server без потери данных.** Режим процесса — переменная окружения, схема БД и данные от неё не зависят. `server` отключает PIN и picker, требует пароль `passwordScore ≥ 2` при регистрации и запрещает PIN при входе. Поэтому перед включением хоста аккаунты с `unlockKind = pin` **обязаны получить пароль** (владелец задаёт его в диалоге включения; их сессии закрываются). Иных изменений строк нет. `JWT_SECRET` уже постоянный (`local-runtime.json`), токены переживают смену режима. Возврат в `local` ничего не удаляет; аккаунты, у которых PIN заменён паролем, входят по паролю.
3. **mDNS без нативных зависимостей.** `bonjour-service` (→ `multicast-dns`, чистый JS): публикация и поиск `_orion._tcp`. Мультикаст режется многими роутерами и VPN, поэтому ручной ввод `адрес:порт` — равноправный путь. **Брандмауэр:** правила создаются только при включении хоста и только по действию владельца; запись идёт через `Start-Process -Verb RunAs` (системный диалог UAC), правила — профиль `private`, `remoteip=localsubnet`: TCP порт API и UDP 5353 для mDNS. PostgreSQL правилом не затрагивается и слушает только `127.0.0.1`. Отказ в UAC не ломает режим: хост работает, UI показывает «правила не созданы».
4. **Транспорт.** Рекомендация и реализация: **TLS по умолчанию**, самоподписанный ECDSA P-256 сертификат (создаётся без openssl собственным DER-кодировщиком, `self-signed-cert.ts`, 10 лет), **закрепление сертификата** клиентом (pin по полному сертификату, не по имени/адресу). Чистый HTTP по LAN не поддерживается. Доверие при первом подключении — через код сопоставления (ниже), а не «принять и забыть».

## Решение

### Режимы
`local` (по умолчанию) · `host` · `client`. Хранятся в `lan-node.json` рядом с данными (`ORION_NODE_DIR`, лаунчер передаёт папку данных), потому что режим определяет запуск процесса и читается лаунчером до API. Файлы: `lan-node.json` (режим, имя, стабильный `nodeId`, порт, владелец), `lan-devices.json` (sha256 токенов), `lan-client.json` (привязка к хосту, права 0600), `lan-tls/` (сертификат и ключ). Доверие — свойство машины, поэтому оно **не** в БД и не попадает в бэкап/восстановление (и не требует записи в `SNAPSHOT_MODEL_REGISTRY`).

### Хост
`ORION_MODE=server` + `ORION_LAN_HOST=1` — тот же код серверных защит (`assertServerConfig`, проверка роли БД, rate-limit), не копия. Два слушателя одного приложения: HTTP на `127.0.0.1:4000` (окно ORION этого ПК, readiness лаунчера) и HTTPS на `0.0.0.0:<порт, по умолчанию 4443>`. Лаунчер перезапускает API при коде выхода 75 (смена режима) и выставляет `PUBLIC_API_URL`/`WEB_ORIGINS`.

### Доверие и вход
- Без авторизации виден только `GET /lan/info` (протокол, имя, nodeId, отпечаток), `POST /lan/pair/request`, `GET /lan/pair/status/:id`, `/system/health`. Любой другой сетевой запрос без действующего `X-Orion-Device` — 403 (`device_untrusted`); отозванный — 401 (`device_revoked`). Запросы с loopback не затрагиваются. Адрес берётся из сокета, не из `X-Forwarded-For`.
- **Сопоставление:** клиент шлёт заявку (`clientNonce`); хост отвечает `serverNonce`. Обе стороны считают 6-значный код `HMAC(clientNonce|serverNonce|отпечаток сертификата)`. Клиент берёт отпечаток из **увиденного им TLS-сертификата**, хост — из своего. Владелец **вводит на хосте код с экрана клиента**; при посреднике с другим сертификатом коды расходятся. 3 неверных ввода закрывают заявку; заявка живёт 2 минуты, в очереди ≤ 5, ≤ 3 в минуту с адреса; хранится только в памяти.
- После подтверждения клиент один раз получает device-токен (256 бит, на хосте хранится хеш). Опрос статуса защищён секретом `clientNonce`.
- Отзыв: токены проверяются по словарю в памяти хоста при каждом запросе — действует со следующего запроса (требование ≤ 5 с).
- Управление узлом (включение, устройства, заявки) — только loopback + JWT владельца (тот, кто включил режим).
- Вход пользователя — отдельный шаг, учётная запись принадлежит хосту.

### Клиент
`/lan/client/*` на локальном API: поиск (mDNS), проба (читает сертификат и визитку, ничего не отправляет), заявка, опрос, активация. В режиме клиента `/_remote/*` стримится на хост по TLS с закреплённым сертификатом; `node_offline` (503) и `node_cert_changed` (502) — различимые состояния. До `/_remote` не доходят контроллеры, поэтому запись «в локальную базу вместо удалённой» невозможна по построению. Токены входа у каждого узла в своём пространстве имён localStorage; локальные ключи не меняются. Возврат в «Локальный» — `POST /lan/client/deactivate`, локальные данные не затрагиваются.

## Отвергнуто
- Правка Rust/Tauri для пиннинга: Rust недоступен агентской среде, WebView2 не примет самоподписанный сертификат, а прокси на Node решает обе задачи без смены CSP.
- Токены доверия в PostgreSQL: восстановление бэкапа воскрешало бы доверие.
- Подтверждение «сравните коды глазами»: ввод кода на хосте превращает его в ограниченную по попыткам проверку.

## Что не проверено
Реальные два ПК в одной сети; mDNS на реальном роутере; диалог UAC и создание правил (проверена только генерация команд и чтение правил); `pnpm build:desktop-installer`; Tauri-окно; путь «включение хоста с заменой PIN на пароль» через БД (в интеграционном тесте проверен только отказ без паролей, чтобы не менять чужие аккаунты в общей dev-БД).

Покрыто автотестами (`apps/api/src/lan/lan.test.ts`, `apps/api/test/lan.integration.test.ts`, `apps/web/lib/node-mode.test.ts`): сертификат и реальное TLS-рукопожатие, пиннинг, код сопоставления, лимиты и блокировка заявок, хранилище устройств и мгновенный отзыв, middleware доверия (анонимный запрос не получает ничего, кроме визитки), прокси клиента (офлайн, подмена сертификата, не-клиентский режим), конфиг узла, правила брандмауэра.

Известные ограничения: удаление программы не удаляет правила брандмауэра (команды в `WINDOWS_INSTALLER.md`); только IPv4 в объявлении; к хосту подключается desktop-клиент, не обычный браузер; в UI нет кнопки удаления правил при выключении хоста (команды есть в `firewall.ts`).
