# ADR-0018 — Agent Gateway: capture, context, связи, поиск, MCP в установленной версии

Статус: **принято и реализовано** 15.10.2026 ([ТЗ-02](../tz/TZ-02-agent-gateway.md)). Развивает [ADR-0007](ADR-0007-ai-bridge.md); ядро моста (токены, scopes, журнал, rate-limit) не менялось.

## Задача
Агент на ПК с установленным `.exe` не видит исходников. За несколько вызовов он должен найти пространство и проект, **сохранить информацию, связать её и вернуть человеку рабочую ссылку**.

## Решения

### 1. Capture (`POST /ai/v1/capture`, MCP `orion_capture`)
- Назначение задаёт **только вызывающий**: явный `hint` (`idea`/`note` → заметка, `task` → задача, `reminder` → задача со сроком `dueAt`, `event` → событие на 30 минут с началом `dueAt`) либо явная метка в начале текста. Без LLM внутри ORION.
- **Соотношение с быстрым вводом.** Метки без `hint` разбирает та же `resolveQuickCapture` (`/task`, `/note`, `!`) — правила не дублируются. Метка, на которую у токена нет разрешения, — не ошибка, а запись во «Входящие» (мягкий путь); явный `hint` строг: нет scope → 403, модуль выключен → 409, нет `dueAt` там, где он нужен → 400.
- Всё остальное → **Inbox** (`InboxItem.createdByAgent`), ответ `status: "inbox"` с `reason`. Связи (`links`) к записи Inbox не привязать (у неё нет типа в реестре связей) — 400, а не молчаливый пропуск.
- Объекты создаются через обычные `createTx` сервисов в **одной транзакции** с записью идемпотентности и связями: любая ошибка откатывает всё.
- **Идемпотентность:** таблица `agent_captures`, уникальный индекс `(tokenId, idempotencyKey)`, захват `createMany({ skipDuplicates })` до создания объекта (барьер в БД, как в `RecurringChecker`/`InboxService.process`). Гонка параллельных одинаковых вызовов даёт одну запись, проигравший получает `deduplicated: true`. Откат неудачного вызова освобождает и ключ.
- Атрибуция: `Note.createdByAgent`, строка `created` в `TaskActivity`, `InboxItem.createdByAgent`; подпись — имя токена, плюс `source`, если передан: «Claude (чат про ремонт)».

### 2. Context и руководство
- `GET /ai/v1/context` (без scope): пространство, роль, scopes, **только достижимые для токена** включённые модули, проекты (если есть `projects:read`), доступные `hint`, типы связей/поиска, лимиты, правила подтверждения, `capabilities`, формат ссылок.
- `GET /ai/v1/manual` и `docs/AGENT_MANUAL.md` рендерятся одной функцией `renderAgentManual` из **единого каталога инструментов** `AGENT_TOOLS` (`packages/shared-types/src/agent-tools.ts`). Тест сверяет файл с генератором (`UPDATE_AGENT_MANUAL=1` пересоздаёт). Файл ставится установщиком рядом с рантаймом.

### 3. Связи и поиск
- `POST /ai/v1/links`, `DELETE /ai/v1/links/:id` (scope `links:write`) — через `SearchService.createLink/removeLink`: оба объекта проверяются на пространство (404) и модуль (403). Типы ограничены project/task/note/event, и **для обоих** у токена должен быть read- или write-scope; чужой по правам конец связи неотличим от несуществующего (404).
- `GET /ai/v1/search?q=` — тот же поиск, что у человека, суженный до типов, на чтение которых есть scope; в ответе `searched` — что искалось, названия недоступных модулей не раскрываются.

### 4. Транспорт MCP в установленной версии — **stdio через встроенный Node**
Рассмотрены: (а) stdio-адаптер, запускаемый встроенным `node.exe`; (б) Streamable HTTP на `127.0.0.1`.
Выбрано **(а)**: адаптер — `apps/api/src/mcp/orion-mcp.ts`, компилируется вместе с API в `dist/mcp/orion-mcp.js` (уже в установщике, Node поставляется). Причины: нет новой сетевой поверхности (ни DNS-rebinding, ни CORS, ни второй аутентификации); токен остаётся у клиента и уходит только в заголовок `Authorization`; все целевые клиенты (Claude Desktop/Code, Cursor, Codex) умеют stdio. (б) нужен только для удалённых клиентов — отдельный ADR вместе с ТЗ-03.
- Список инструментов **генерируется** из `AGENT_TOOLS`; тест сверяет каталог с маршрутами контроллеров в обе стороны (инструмент без маршрута и маршрут без инструмента — ошибка).
- Токен: `ORION_AGENT_TOKEN` либо `ORION_AGENT_TOKEN_FILE`/`--token-file` (первая строка; на POSIX файл, читаемый другими, отвергается). Токен не пишется в лог/ошибки (`redact`), не попадает в журнал аудита.
- В исходниках `scripts/orion-mcp.mjs` — тонкая обёртка над тем же адаптером.

### 5. Формат ссылок
`orion://open?type=<project|task|note|event|inbox>&id=<id>&workspace=<id>`. Веб-клиент открывает ту же ссылку как `/open?type=…` (статический маршрут, как `/invite`; переключает пространство, если человек в нём состоит, и фокусирует объект через `openEntity`). Десктоп регистрирует схему `orion` (`tauri-plugin-deep-link`, NSIS пишет её при установке) и пересылает ссылку в `/open`; повторный запуск передаёт ссылку уже работающему окну (`tauri-plugin-single-instance`). Ссылка — только навигация: данные панель всё равно грузит через API с проверкой доступа.

### 6. Мастер «Подключить агента»
`GET workspaces/:id/agent-connection` (JWT, участник) отдаёт **реальные** `process.execPath` и путь адаптера работающего API — в установленной версии это именно установленные пути. Клиент (`apps/web/lib/agent-connect.ts`) строит готовые фрагменты для Claude Desktop, Claude Code, Cursor, Codex и «другого» и проверяет подключение вызовом `/ai/v1/me`. В режиме `server` пути не раскрываются, мост по-прежнему включается `ORION_AI_BRIDGE=1`.

## Не сделано / известные границы
- Холодный старт по `orion://` (ссылка запускает приложение): ссылка запоминается и открывается после первой загрузки окна; если человек ещё не вошёл, откроется экран входа, а не объект.
- Работа ссылки в установленной версии, регистрация схемы NSIS и работа на чистом Windows без Node проверены только сборкой Rust (`cargo check`); установщик в этой сессии не собирался и не запускался — контрольный сценарий приёмки ТЗ-02 на чистой машине остаётся ручным.
- Новые эндпоинты Gateway используют собственный вызов-обёртку в `agent-gateway.controller.ts` (scope → сервис → аудит). Режимы автономности и лимиты записи ТЗ-03 должны подключиться и к ней (`capture`, `links`).
- Удалённый MCP (HTTP) — вне ТЗ.
