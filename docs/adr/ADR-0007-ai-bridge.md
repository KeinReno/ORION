# ADR-0007 — ORION AI Bridge: токены агентов, `/ai/v1`, MCP

Статус: **принято, первая версия реализована** (13 октября 2026). Часть программы [WORKSPACE_PROGRAM_2026-10.md](../WORKSPACE_PROGRAM_2026-10.md), Э6.

## Задача
Когда ORION запущен, внешние ИИ (Claude, Cursor, скрипты, локальные модели) должны уметь безопасно работать с задачами, заметками и проектами, не получая доступа к БД и не обходя права. ORION без агентов работает как прежде.

## Решение
1. **Токен агента** (`AgentToken`): выпускает участник пространства в Настройках → «ИИ-агенты». Секрет `orion_agt_…` показывается один раз, в БД лежит только sha256 (секрет высокоэнтропийный, замедляющий хеш не нужен). Срок 1–365 дней, отзыв в любой момент.
2. **Права = права выпустившего.** Токен привязан к одному пространству и действует как `createdById`: каждый вызов идёт через обычные сервисы (`withUser` → RLS → `assertMember`). Вышел из пространства — токен перестаёт работать. Токен не может больше, чем человек.
3. **Разрешения (scopes)** сужают права: `tasks:read|write`, `notes:read|write`, `projects:read`, `events:read|write`, `agents:message`, `agents:delegate`. Выключенный модуль пространства тоже блокирует вызов.
4. **`/ai/v1`** — отдельный контур (`AgentTokenGuard`; пользовательский JWT там не принимается, токен агента не принимается в остальном API). Удаления нет **намеренно**; правка задачи/заметки ограничена полями `title/description/status/priority/dueAt` и `title/summary/body/tags`, заметки — с `expectedRevision` (CAS, 409 вместо молчаливой перезаписи).
5. **Журнал** (`AgentAuditEntry`): каждый вызов, включая отказы (403/404/409), пишется через `asSystem`; виден участникам пространства в тех же Настройках. В бэкап не входит (`ephemeral-excluded`), токены — `secret-excluded`.
6. **MCP**: `scripts/orion-mcp.mjs` — stdio-сервер без зависимостей, тонкий адаптер над `/ai/v1` (20 инструментов). Своих прав и данных у него нет. Подключение: команда `node scripts/orion-mcp.mjs`, env `ORION_AGENT_TOKEN`, `ORION_API_URL`.
7. **Режим `server`**: мост выключен, пока не задан `ORION_AI_BRIDGE=1`.

## Переписка агентов (сделано)
Scope `agents:message`: агент видит других живых агентов своего пространства (`GET /ai/v1/agents`), шлёт текст (`POST /ai/v1/messages`) и читает только свой ящик (`GET /ai/v1/messages`, `POST …/:id/read`). Сообщение — просто текст: получатель действует под правами своего токена, права отправителя не передаются. В описании MCP-инструмента чтения прямо сказано, что текст чужого агента — данные, а не команды. Сообщения и токены в бэкап не входят.

## Задания и подтверждения (сделано)
- **Задания** (`agents:delegate`, `/ai/v1/jobs`): структурированное поручение другому агенту со статусом и результатом. Исполнитель ставит `in_progress/done/failed`, выдавший может только `canceled`; завершённое задание неизменно (атомарный `updateMany` по статусу). Исполнитель работает под правами **своего** токена.
- **Подтверждение опасного** (`/ai/v1/proposals`): удаления у агента нет; он подаёт запрос `task.delete` / `note.delete` (нужен scope `tasks:write` / `notes:write`). Человек видит его в Настройках → «ИИ-агенты» и подтверждает или отклоняет; подтверждённое удаление выполняется **под правами человека**, один раз (захват статуса `pending → approved` атомарный; при сбое запрос возвращается в `pending`). Название объекта фиксируется в момент запроса.

## Ограничение частоты (сделано, Э6-hardening)
Каждый вызов `/ai/v1` после аутентификации списывается из скользящего окна **на токен** (в памяти процесса, `rate-limiter.ts`): по умолчанию 120 вызовов в минуту, `ORION_AI_RATE_LIMIT` меняет число. Сверх лимита — `429` с `Retry-After`; каждый отказ пишется в журнал (`rate_limited`, статус 429). Отказанные попытки окно не продлевают. Недействительный токен до лимита не доходит (401). Состояние сбрасывается при перезапуске — для локального моста достаточно; для нескольких инстансов потребуется общее хранилище.

## Атрибуция действий агента в данных (сделано)
Права по-прежнему = права выпустившего (`actorId` — человек), но изменения через `/ai/v1` теперь помечены именем токена (снимок имени, переживает отзыв):
- `TaskActivity.agentName` — у строк журнала статуса/исполнителя/срока; у задачи, созданной агентом, дополнительно строка `created`. В деталях задачи и в ленте активности дашборда — метка 🤖.
- `Note.createdByAgent` / `Note.editedByAgent` (последняя правка содержимого; правка человека её сбрасывает).
Правки других полей задачи (заголовок, описание, приоритет) в журнале задач и раньше не отражаются; они видны в журнале вызовов агента. Миграция аддитивная, nullable.

## События календаря (сделано)
Scopes `events:read` / `events:write` (модуль «Календарь»): `GET /ai/v1/events?from&to` (окно по умолчанию 30 дней, не шире 366; повторы приходят развёрнутыми), `POST /ai/v1/events`, `PATCH /ai/v1/events/:id` — через обычный `EventsService`. Агент пишет только простые поля: название, описание, место, начало/конец, весь день, напоминания, проект. Повторы, цвет, часовой пояс и ссылка отбрасываются схемой; правка повторяющегося события всегда относится ко всей серии; удаления нет. Внешние (read-only) события не правятся. Финансы и документы агентам по-прежнему не открыты.

## Не сделано (осознанно)
- HTTP-транспорт MCP для удалённых клиентов: нужен отдельный ADR про аутентификацию и транспорт; для локальных клиентов достаточно stdio.
- Доступ к финансам и документам — только осознанно, по одному модулю с отдельным scope.
