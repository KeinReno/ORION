# ADR-0007 — ORION AI Bridge: токены агентов, `/ai/v1`, MCP

Статус: **принято, первая версия реализована** (13 октября 2026). Часть программы [WORKSPACE_PROGRAM_2026-10.md](../WORKSPACE_PROGRAM_2026-10.md), Э6.

## Задача
Когда ORION запущен, внешние ИИ (Claude, Cursor, скрипты, локальные модели) должны уметь безопасно работать с задачами, заметками и проектами, не получая доступа к БД и не обходя права. ORION без агентов работает как прежде.

## Решение
1. **Токен агента** (`AgentToken`): выпускает участник пространства в Настройках → «ИИ-агенты». Секрет `orion_agt_…` показывается один раз, в БД лежит только sha256 (секрет высокоэнтропийный, замедляющий хеш не нужен). Срок 1–365 дней, отзыв в любой момент.
2. **Права = права выпустившего.** Токен привязан к одному пространству и действует как `createdById`: каждый вызов идёт через обычные сервисы (`withUser` → RLS → `assertMember`). Вышел из пространства — токен перестаёт работать. Токен не может больше, чем человек.
3. **Разрешения (scopes)** сужают права: `tasks:read|write`, `notes:read|write`, `projects:read`, `events:read|write`, `agents:message`, `agents:delegate`. Выключенный модуль пространства тоже блокирует вызов.
4. **`/ai/v1`** — отдельный контур (`AgentTokenGuard`; пользовательский JWT там не принимается, токен агента не принимается в остальном API). Удаления нет **намеренно**; правка задачи/заметки ограничена полями `title/description/status/priority/dueAt` и `title/summary/body/tags`, заметки — с `expectedRevision` (CAS, 409 вместо молчаливой перезаписи).
5. **Журнал** (`AgentAuditEntry`): каждый вызов, включая отказы (403/404/409), пишется через `asSystem`; виден участникам пространства в тех же Настройках. В бэкап не входит (`ephemeral-excluded`), токены — `secret-excluded`.
6. **MCP**: stdio-адаптер `apps/api/src/mcp/orion-mcp.ts` (в установленной версии — `dist/mcp/orion-mcp.js` под встроенным Node; в исходниках — обёртка `scripts/orion-mcp.mjs`), тонкий адаптер над `/ai/v1`; список инструментов генерируется из каталога `AGENT_TOOLS`. Своих прав и данных у него нет. Подключение — мастер «Подключить агента» в Настройках, подробности и capture/context/links/search — [ADR-0018](ADR-0018-agent-gateway.md).
7. **Режим `server`**: мост выключен, пока не задан `ORION_AI_BRIDGE=1`.

## Переписка агентов (сделано)
Scope `agents:message`: агент видит других живых агентов своего пространства (`GET /ai/v1/agents`), шлёт текст (`POST /ai/v1/messages`) и читает только свой ящик (`GET /ai/v1/messages`, `POST …/:id/read`). Сообщение — просто текст: получатель действует под правами своего токена, права отправителя не передаются. В описании MCP-инструмента чтения прямо сказано, что текст чужого агента — данные, а не команды. Сообщения и токены в бэкап не входят.

## Задания и подтверждения (сделано)
- **Задания** (`agents:delegate`, `/ai/v1/jobs`): структурированное поручение другому агенту со статусом и результатом. Исполнитель ставит `in_progress/done/failed`, выдавший может только `canceled`; завершённое задание неизменно (атомарный `updateMany` по статусу). Исполнитель работает под правами **своего** токена.
- **Подтверждение опасного** (`/ai/v1/proposals`): удаления у агента нет; он подаёт запрос `task.delete` / `note.delete` (нужен scope `tasks:write` / `notes:write`). Человек видит его в Настройках → «ИИ-агенты» и подтверждает или отклоняет; подтверждённое удаление выполняется **под правами человека**, один раз (захват статуса `pending → approved` атомарный; при сбое запрос возвращается в `pending`). Название объекта фиксируется в момент запроса.

## Ограничение частоты (сделано, Э6-hardening)
Каждый вызов `/ai/v1` после аутентификации списывается из скользящего окна **на токен** (в памяти процесса, `rate-limiter.ts`): по умолчанию 120 вызовов в минуту, `ORION_AI_RATE_LIMIT` меняет число. Сверх лимита — `429` с `Retry-After`; каждый отказ пишется в журнал (`rate_limited`, статус 429). Отказанные попытки окно не продлевают. Недействительный токен до лимита не доходит (401). Состояние сбрасывается при перезапуске — для локального моста достаточно; для нескольких инстансов потребуется общее хранилище.

## Атрибуция действий агента в данных (сделано)
Права по-прежнему = права выпустившего (`actorId` — человек), но изменения через `/ai/v1` теперь помечены именем токена (снимок имени, переживает отзыв):
- `TaskActivity.agentName` — у строк журнала статуса/исполнителя/срока; у задачи, созданной агентом, дополнительно строка `created`. В деталях задачи и в ленте активности дашборда — метка 🤖.
- `Note.createdByAgent` / `Note.editedByAgent` (последняя правка содержимого; правка человека её сбрасывает).
Правки других полей задачи (заголовок, описание, приоритет) в журнале задач и раньше не отражаются; они видны в журнале вызовов агента. Миграция аддитивная, nullable.

## События календаря (сделано)
Scopes `events:read` / `events:write` (модуль «Календарь»): `GET /ai/v1/events?from&to` (окно по умолчанию 30 дней, не шире 366; повторы приходят развёрнутыми), `POST /ai/v1/events`, `PATCH /ai/v1/events/:id` — через обычный `EventsService`. Агент пишет только простые поля: название, описание, место, начало/конец, весь день, напоминания, проект. Повторы, цвет, часовой пояс и ссылка отбрасываются схемой; правка повторяющегося события всегда относится ко всей серии; удаления нет. Внешние (read-only) события не правятся. Финансы и документы агентам по-прежнему не открыты.

## Черновики операций из чеков (сделано, ADR-0013)
Scope `finance:draft` и плагин `finance-ai-drafts`. ORION сам чеки **не распознаёт** — читает агент (у него есть зрение и OCR), а в ORION он присылает результат как **черновик**: `GET /ai/v1/finance/refs` (названия и id счетов и категорий, без остатков и операций) и `POST /ai/v1/finance/drafts` (тип расход/доход, сумма в копейках, дата, магазин, заметка, подсказки счёта и категории, уверенность). Черновик не двигает баланс и не попадает в отчёты. Человек видит блок «ИИ предлагает» над операциями, **правит любое поле и подтверждает** — только тогда обычный `TransactionsService.create` под правами человека записывает операцию, один раз (атомарный захват `pending → approved`, при сбое возвращается в `pending`). Агент не может создать перевод, записать операцию напрямую или увидеть остатки; чужие счёт/категория — 400; повтор того же черновика безопасен; больше 50 неразобранных на токен — 429. Черновики, как и запросы на подтверждение, в бэкап не входят.

## Не сделано (осознанно)
- HTTP-транспорт MCP для удалённых клиентов: нужен отдельный ADR про аутентификацию и транспорт; для локальных клиентов достаточно stdio.
- Доступ к финансам и документам — только осознанно, по одному модулю с отдельным scope.

## Agent Manager: режимы, матрица, предложения, журнал (сделано, ТЗ-03)

- **Режим токена** (`AgentToken.mode`): `observer` — только чтение, любая запись 403; `assistant` — создаёт заметки/задачи/события сразу, **изменение существующего** превращается в proposal (ответ `202 { proposed, proposal }`); `manager` — пишет сразу в пределах разрешений и лимита записей в час (сверх — 429), удаление всё равно proposal. Режим только сужает скоупы. Новые токены — `assistant`.
- **Миграция существующих токенов:** до режимов токен писал сразу (создание и правка), а удалял только через запрос — это ровно `manager` без лимитов, без забора по проектам, без матрицы (`permissions = NULL` → права выводятся из `scopes`). Миграция `…_agent_manager` проставляет `mode='manager'` существующим строкам, а колонке даёт default `assistant` для новых. Поведение старых токенов не меняется (интеграционный тест на строку в форме «после миграции»).
- **Матрица** «модуль × {читать, создавать, менять, предлагать}» (`permissions`) пересекается со скоупами (`effectiveAgentPermissions`); старые скоупы остаются валидными. `allowedProjectIds` (пусто = все; создание без проекта под забором — 403; списки фильтруются), флаги «никогда»: `finance` / `documents` / `delete` — проверяются на сервере (`decideAgentOperation` в `shared-types`, единый источник и для UI).
- **Proposals для изменений:** `task.update`, `note.update`, `event.update` с `patch` и дифф-превью до/после (фиксируется при подаче). TTL 7 дней (`expired` вычисляется), подтверждение — атомарный `updateMany pending→approved` под правами человека, массовое подтверждение/отклонение `POST …/proposals/bulk`. Повторная заявка того же токена на тот же объект заменяет ожидающую.
- **Журнал:** `module`, `summary` («что сделал»), `objectType/objectId`, фильтры токен/модуль/результат/период, CSV на клиенте (с защитой от формул). «Отменить создание» — заметка в корзину, задача → `canceled` (корзины задач в ORION нет); не жёсткое удаление. Журнал по-прежнему `ephemeral-excluded`.
- **Управление:** «Отозвать все токены», смена режима/ограничений на живом токене (`PATCH`, только сужение), предупреждение о токене без срока, уведомление владельцу при первом использовании и при серии отказов (5 за 10 минут).
- **Автофиксация решений** (`autoCommitProjectIds`, по умолчанию пусто): для `manager` заметка с тегом «решение» (или `decision`) сохраняется сразу только в проекте из списка, иначе 403. ORION сам реплики не сохраняет. У `assistant` дополнительной проверки нет — он пишет по запросу пользователя.
- **«Объект изменился после запроса»:** запрос запоминает основу (`baseRevision` задачи/заметки, `baseUpdatedAt` события). Подтверждение при изменившемся объекте (и для `*.update`, и для `*.delete`) — `409 { code: "agent_proposal_stale", currentDiff }`, захват статуса откатывается, запрос остаётся `pending`. Человек выбирает: `POST proposals/:id/refresh` (превью пересчитывается на текущей версии, основа обновляется) или `approve` с `{ force: true }` (применить поверх явно). Без `force` запись идёт с `expectedRevision` (CAS), поэтому гонка между проверкой и записью тоже даёт 409. У события CAS нет — только проверка перед записью; у старых запросов основы нет, они устаревшими не считаются. Массовое подтверждение `force` не принимает: устаревший запрос в нём сообщается ошибкой.
- **Режимы в MCP:** описание каждого инструмента (`tools/list`, руководство) говорит, что он делает в наблюдателе / помощнике / менеджере (`effect` в `AGENT_TOOLS` → `agentToolModeNote`); `GET /ai/v1/me`, `/context` и `initialize`/`tools/list` MCP-адаптера отдают режим самого токена.
- Лимит записей мягкий: считается по журналу, параллельные вызовы могут превысить его на единицы.

Удалённый доступ (п. 3.6 ТЗ) — отдельный документ: [ADR-0017](ADR-0017-agent-remote-access.md).
