# ADR-0024: общие публикации поверх пространств

Статус: implementation decision по поручению владельца 24.10.2026. Основа: обсуждение Shared Data Architecture; не отменяет ADR-0020.

## Первый рабочий этап
Один авторитетный узел, существующее неперсональное Workspace как общая зона. Пользователь публикует отдельную задачу или материал Knowledge из пространства, которым владеет. Существующие grants остаются совместимыми и read-only. Общая публикация — разрешённая текстовая проекция, не ссылка с доступом ко всему исходному workspace. Получатели видят только публичный id, данные проекции, права и ревизию. Source ids и ревизия оригинала не выдаются.

NEW_EXTENSION_POINT_REQUIRED: типизированный серверный PublicationAdapter в shared/publication-contracts.ts. Модули регистрируют чтение проекции, самостоятельную копию и допустимые изменения. Shared владеет публикациями, журналом и закреплениями; Tasks/Knowledge — своими оригиналами. Новых зависимостей Core на конкретные плагины нет.

В этом этапе транспорт соединяет клиентов с одним узлом (включая LAN). Межузловая доставка, Android-паритет публикаций и автоматические правила — следующие этапы; интерфейс не выдаёт их за реализованные. На одном узле изменение статуса и применение к оригиналу атомарны. При несовместимой ревизии возвращается конфликт, без перезаписи. Офлайн клиент хранит ожидающее намерение, а не утверждает, что оно применено. Отзыв и проверка членства выполняются повторно при доставке.

## Продуктовый контракт
- «Поделиться»: предварительный просмотр разрешённой текстовой проекции, зона и участники, разрешение менять статус только для задач. Ссылки, изображения, HTML и wiki-ссылки исключаются из передаваемого текста; источники, вложения, категории, проект, исполнители и связи не копируются. Пользователь подтверждает именно показанный текст (rule/name-object-scope-consequence).
- «Показывать у меня»: личное закрепление публикации в выбранном пространстве; сохраняет её происхождение и права. «Сделать личную копию»: новый объект с новым id, без дальнейшей синхронизации (rule/canonical-verb).
- Ошибки не очищают ввод; операции видимо ожидают ответа, конфликт не считается успехом (rule/preserve-user-input, rule/cover-reachable-states).
- Публикация не изменяется автоматически из-за новых приватных вложений. Обновление содержимого требует повторного предварительного просмотра.
- Отзыв блокирует дальнейшие чтение/изменение и скрывает закрепления. Уже созданная самостоятельная копия сохраняется. Восстановление резервной копии не возобновляет разрешения.

## Приёмка
Два пользователя, личный источник и общая зона; создание/чтение без членства в источнике; статус по разрешению; конфликт; повтор операции; отзыв; исключение участника; private dependency sentinel не попадает в DTO; самостоятельная копия; закрепление не расширяет доступ; отключённые модули; production UI при узкой и широкой панели. Данные тестов — только изолированная БД.

## Границы первого этапа

- Для исходного пространства требуется роль owner; закрытый Knowledge другого автора остаётся закрытым и для owner по существующей RLS.
- Knowledge доступен участникам только для чтения. Делегированное изменение — только статус задачи; текст обновляет издатель через новый предпросмотр.
- При недоступности сервера намерение сменить статус хранится локально с namespace сервера, пользователя и публикации. Повторная доставка ручная, с прежним operationId; нет автоматического разрешения конфликта и фоновой межузловой очереди. При уже подтверждённом отзыве публикация скрывается; локальное намерение не отправляется автоматически.
- Закрепления находятся в «Доступно мне → Общие публикации → Показывать у меня»; это не скрытая копия в обычном списке задач/Knowledge. Самостоятельная копия появляется в соответствующем модуле личного пространства. Новая копия задачи начинается со статуса todo.
- Состав общей зоны определяется существующим членством, в том числе будущими приглашениями. Персональные списки адресатов и модерация чужих правок не входят в этот срез.
- Серверные списки ограничены последними 200 публикациями; полнотекстовая выдача, курсорная пагинация и интеграция закреплений в списки модулей — отдельное продолжение.
