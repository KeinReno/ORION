# ADR-0017 — Удалённый доступ агентов (ChatGPT и облачные клиенты)

Статус: предложение для решения владельца. **Кода нет**; реализация — отдельное ТЗ после выбора варианта.

## Проблема
Локальные клиенты (Claude Desktop/Code, Cursor) ходят в ORION по stdio-MCP или `127.0.0.1`. Облачные клиенты (ChatGPT, веб-версии) находятся вне машины и не могут достучаться до `127.0.0.1`. Нужно решить, как дать им доступ, не сломав модель «токен = права человека, сужаемые режимом» ([ADR-0007](ADR-0007-ai-bridge.md)).

## Варианты

| | A. HTTP-MCP + OAuth на публичном хосте | B. Туннель до локального ORION | C. Собственный клиент внутри ORION |
|---|---|---|---|
| Суть | ORION в режиме `server` с TLS публикует Streamable-HTTP MCP; клиент получает токен через OAuth 2.1 (PKCE, dynamic client registration) | Cloudflare Tunnel / Tailscale Funnel и т.п. выставляет `/ai/v1` наружу | Чат-панель ORION вызывает LLM-API по ключу владельца; внешних клиентов нет |
| Аутентификация | OAuth-токен, привязанный к `AgentToken` (режим, матрица, срок) | Тот же bearer `orion_agt_…` через туннель | Ключ LLM хранится у владельца, входящего доступа нет |
| Поверхность атаки | Публичный OAuth-сервер + MCP; нужен постоянный хост | Весь `/ai/v1` в интернете за сторонним туннелем; утечка токена = доступ к личным данным | Только исходящие вызовы к провайдеру LLM |
| Режим `local` | Запрещён (по умолчанию мост слушает только 127.0.0.1) | Запрещён как «скрытая публикация»: нужно явное включение и предупреждение | Допустим |
| Сложность | Высокая (OAuth, хостинг, CORS/DNS-rebinding, ротация) | Низкая | Средняя (UI чата, хранение ключа) |
| Контроль данных | Данные на сервере владельца | Данные дома, канал у третьей стороны | Контекст уходит провайдеру LLM |

## Что запрещено в режиме `local` (при любом варианте)
- Привязка моста к `0.0.0.0` и публичные адреса без явного `ORION_MODE=server` + `ORION_AI_BRIDGE=1`.
- Токены без срока для удалённых клиентов; режим `manager` по умолчанию; финансы (кроме черновиков) и удаление.
- Передача токена в query-строке или логах.

## Рекомендация
1. **Сейчас не открывать ничего наружу.** Для ChatGPT-подобных клиентов использовать вариант **C** (панель внутри ORION) — не расширяет поверхность атаки.
2. Если удалённые клиенты нужны, идти к **A**: единственный вариант с нормальной моделью доверия (OAuth, короткие токены, отзыв), и только поверх готового `server`-режима и LAN/TLS из ТЗ-04/05. Удалённые токены выпускаются **только** в режимах `observer`/`assistant` с обязательным сроком ≤ 30 дней и `forbidden: ["delete"]`.
3. Вариант **B** — только как временная мера по решению владельца, с токеном `observer`, и не как штатная функция.

## Открытые вопросы владельцу
Нужен ли ChatGPT вообще (или хватает Claude/Cursor локально)? Есть ли постоянный хост для варианта A? Допустим ли уход контекста к провайдеру LLM в варианте C?
