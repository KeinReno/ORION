# ADR-0012: «Здоровье» — приватность по человеку

Статус: принят 15.10.2026 (рекомендации [HEALTH_MODULE_SPEC.md](../HEALTH_MODULE_SPEC.md) утверждены владельцем без изменений).

## Контекст

Все модули ORION изолируют данные по **пространству**: участник видит всё пространства (`workspace_members` в каждой RLS-политике). Для здоровья это неверно: супруг не обязан видеть чужие анализы, у ребёнка нет учётной записи, владелец пространства не должен читать записи участников.

## Решение

1. Единица владения — `HealthSubject` («человек»): либо участник пространства (`userId`), либо иждивенец, которого ведёт опекун (`guardianUserId`). Ровно одно из двух заполнено (CHECK).
2. Видит и правит субъект и всё его содержимое: сам человек / опекун («own»); участник с явным допуском `HealthGrant` уровня `read` или `write`; больше никто. Роль `owner`/`lead` пространства прав не добавляет.
3. Два независимых предохранителя, как везде: проверка в сервисе (`assertSubjectTx`: 404, если субъект недоступен — существование не раскрывается; 403, если уровня не хватает) **и** RLS.
4. RLS читает доступ через функцию `health_subject_access(subjectId, userId)` с `SECURITY DEFINER`: политики субъектов и допусков ссылаются друг на друга, а прямая ссылка дала бы бесконечную рекурсию политик. Функция владеет миграционная роль; она возвращает `own` / `write` / `read` / NULL и требует членства в пространстве (вышедший участник теряет доступ). Политики разделены по командам: `read`-допуск не позволяет менять и удалять.
5. Модуль `health` выключен по умолчанию у новых пространств и принудительно выключается миграцией у существующих.
6. Снимки пространства (`snapshot-registry`) **не включают** health-таблицы (`secret-excluded`): снимок делает любой участник, и он не должен получить чужие данные. Личный экспорт/восстановление «забрать всё» — отдельная работа (этап 5), с проверкой личности.
7. Данные health не попадают в общий поиск, ссылки между сущностями, захваты, ИИ-токены, Telegram и логи. Уведомления о здоровье (этап 2+) — нейтральный текст по умолчанию.

## Последствия

- Негативные тесты (чужой участник, `read`-допуск, вышедший участник, другое пространство) обязательны для каждого нового эндпоинта.
- Структурный тест «ENABLE + FORCE RLS + политика» покрывает новые таблицы автоматически.
- Резервное копирование health пока отсутствует — это осознанный пробел, а не недосмотр.
- Режим `ORION_MODE=server` до отдельной юридической проверки не должен включать модуль для посторонних людей.
