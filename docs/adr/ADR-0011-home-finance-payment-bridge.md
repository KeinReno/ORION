# ADR-0011 — Связь коммунальных начислений с расходом

Статус: принято для реализации 14.10.2026 по запросу владельца; продолжение [ADR-0010](ADR-0010-home-utilities-extension.md).

## Контекст

Подтверждение начисления не является оплатой. Платёж уже должен существовать в «Финансах» с выбранным счётом списания. Одной операцией можно оплатить несколько месяцев, а месяц — несколькими операциями. При выключенных/ограниченных «Финансах» Дом не должен раскрывать их записи.

## Решение

Плагин `home-utilities` хранит только **распределение** суммы существующей операции по месяцу (`HomeUtilityPayment`), не создаёт финансовую проводку. Доступ к операции идёт через публичный серверный порт `FinanceExpenseReader` после проверки доступности модуля. При добавлении распределения SQL блокирует строку операции, чтобы конкурентные назначения не превысили её расход. Сумма распределений не может превысить сумму операции или подтверждённые начисления месяца. Удаление связи не удаляет финансовую операцию. Удаление самой операции каскадно убирает связь, поэтому «оплачено» пересчитывается.

Если операция позже изменена на доход/перевод, её сумма уменьшена или счёт перестал быть рублёвым, связь помечается требующей проверки и **не учитывается** как оплата до исправления. Это защитный расчёт при каждом чтении, а не кэш. Старые начисления при отключении плагина сохраняются.

## Границы

Интерфейс выбирает существующий расход; создание нового — через публичный модуль «Финансы». Нет прямого импорта внутренних сервисов между модулями. В снимок и восстановление распределения входят после месяцев и финансовых операций. Отдельный поставщик пока не является получателем платежа: распределение выполняется на уровне месяца, что достаточно для общей суммы и остатка без ложной детализации.
