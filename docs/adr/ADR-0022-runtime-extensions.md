# ADR-0022 — Расширения без пересборки

Статус: **принято владельцем 20.10.2026** (направление и ответы на вопросы — в конце). Связано с
[PLATFORM.md](../PLATFORM.md) §5 «Менеджер модулей и плагинов» и §7 «Проверка платформы на независимых компонентах».

## Задача

Сценарий владельца: на рабочем компьютере стоит актуальная сборка ORION. Нужно быстро сделать небольшое расширение под
свою специфику (пример — учёт расхода токенов и лимитов ИИ, сейчас отдельное приложение), положить папку в свою установку —
и ORION сразу его видит и включает, **без пересборки и переустановки**. Потом, если расширение прижилось, оно переносится в
репозиторий ORION и становится частью сборки.

Расширение должно уметь не только наполнять существующие места интерфейса, но и **добавлять новые**: свою панель, виджет,
раздел настроек, команды, а также собственные точки расширения, которые наполняют другие расширения.

## Что есть сейчас (на 20.10.2026)

- Модули и плагины основной сборки вкомпилированы в установщик: скомпилированный API, статический экспорт интерфейса,
  сгенерированный Prisma-клиент. Новый код — только через сборку.
- Внешний модуль (`modules-ext`, G5/G10) и плагин интерфейса (`plugins-ext`, коммит f0746e0) подключаются манифестом без
  правки ядра, но тоже при сборке.
- Слоты интерфейса (`SlotContracts`) и реестр вкладов (`lib/extensions/registry.ts`) уже работают **во время выполнения**:
  `contribute(...)` можно вызвать когда угодно. Публичная поверхность для кода плагина — `lib/extensions/host-api.ts`.
- CSP десктопа: `script-src 'self' 'wasm-unsafe-eval'` — скрипт с адреса API сейчас загрузить нельзя.
- `docs/HISTORY.md` дважды (v0.20, v0.23) откладывал рантайм плагинов как преждевременный. Это решение владельцем
  пересмотрено: Platform 1.0 обязана проверяться независимыми компонентами (PLATFORM.md §7).

## Решение

### 1. Два слоя, один формат

| | Основная сборка | Расширения |
|---|---|---|
| Где лежит | репозиторий: ядро, `apps/web/plugins`, `plugins-ext`, `modules-ext` | папка расширений на компьютере |
| Как попадает | сборка и установщик | положить папку → подтвердить |
| Код | исходники TypeScript | собранный `web.js` (ES-модуль) |
| Свои таблицы БД | да (миграции, RLS) | нет — общее хранилище расширений |
| Серверный код | да | нет на первых этапах (см. §7) |

Манифест у расширения и у плагина `plugins-ext` — один формат (`id`, `version`, `extends`, `catalog`, `contributes`, плюс
`permissions` и `engines.orion`). Поэтому расширение переносится в репозиторий без переписывания: исходники из `src/` кладутся
в `plugins-ext/<id>/`, импорты `@orion/sdk` (планируется (G24), пакета пока нет) разрешаются на хост при сборке.

### 2. Пакет расширения

```
<папка расширений>/ai-tokens/
  orion.extension.json   манифест
  web.js                 собранный интерфейс (ES-модуль, без React внутри)
  README.md              необязательно
```

Собирает его `orion-ext build` (тонкая обёртка над esbuild из шаблона `orion-ext init`): `react`, `react/jsx-runtime` и
`@orion/sdk` (планируется (G24)) помечаются внешними и берутся из хоста. Исходники (`src/`) в установку класть не нужно.

### 3. Обнаружение, доверие, включение

- API следит за папкой расширений (`fs.watch` + повторное сканирование при старте). Новое или изменённое расширение
  проверяется: манифест, `engines.orion` против `PLATFORM_API_VERSION`, sha-256 файлов.
- Расширение появляется в «Настройки → Расширения» как **«найдено, ждёт подтверждения»** со списком запрошенных разрешений.
  Подтверждает владелец установки, один раз. Запоминаются `id`, версия и хеш: изменился хеш — снова «ждёт подтверждения».
- **Режим разработчика** (переключатель у конкретного расширения): изменения файлов применяются сразу, без повторного
  подтверждения, интерфейс перезагружает расширение. Это и есть цикл «правлю — вижу».
- После подтверждения расширение включается/выключается по пространствам, как плагин (`pluginOverrides` → отдельная
  колонка для расширений), и выключается вместе с модулем из `extends`, если он указан.
- Сбой расширения изолирован: границы ошибок вокруг каждого вклада (как `slot-boundary`), «Диагностика» показывает ошибку и
  позволяет выключить.

### 4. Загрузка в интерфейс

- API отдаёт `GET /extensions/:id/web.js` только для подтверждённых расширений, сверяя хеш.
- Интерфейс делает `import(url)`. CSP десктопа получает `http://127.0.0.1:*` в `script-src` (только локальный API; в режиме
  сервера расширения выключены, см. §8).
- Хост кладёт в `globalThis.__ORION_SDK__` React, jsx-runtime и `@orion/sdk` (планируется (G24)): компоненты `@orion/ui`, хуки данных
  `@orion/core-react`, функции `host-api` и API регистрации вкладов. Расширение экспортирует `activate(ctx)`; `ctx` знает
  id расширения и даёт регистрацию с автоматической отпиской при выключении.

### 5. Места, которые расширение может добавить

Ядро один раз получает универсальные «места», после чего расширения добавляют свои без правки ядра:

| Вклад | Что появляется | Что нужно в ядре (один раз) |
|---|---|---|
| `panels` | своя панель дока, пункт в меню (группа из манифеста, по умолчанию «Расширения»), окно и плавающее окно | хост-панель `ExtensionPanel` и динамические записи в реестре панелей |
| `widgets` | карточка на дашборде | хост виджетов дашборда |
| `settings` | раздел в «Настройки → Расширения → <имя>» | хост раздела настроек и запись в каталоге настроек |
| `commands` | команды в Ctrl+K | регистрация команд палитры |
| `slots` (ядра) | вклад в существующий слот (`habits.insights`…) | уже есть |
| `provides.slots` | **собственная точка расширения**, например `ai-tokens.provider-cards`, которую наполняют другие расширения | компонент `<ExtensionSlot name>` в SDK и проверка, что имя начинается с id расширения |

Слоты ядра типизированы (`SlotContracts`); слоты расширений описываются в манифесте (имя, описание пропсов, нужен ли `meta`),
типизация — через `.d.ts`, который `orion-ext` генерирует для зависимых расширений.

### 6. Данные, секреты, сеть

Новые таблицы в работающей базе расширение не создаёт. Вместо этого ядро получает общие сервисы:

- **Хранилище расширений** — одна таблица `extension_records` (`workspaceId`, `extensionId`, `collection`, `key`, `data jsonb`,
  `createdBy`, `privateToUserId`, время) с RLS по членству и личными записями как в ADR-0021. API
  `workspaces/:id/ext/:extId/collections/:name`, лимиты на размер. Входит в резервную копию; синхронизация — позже.
  Удаление расширения данные не удаляет (как выключение модуля); удалить данные — отдельное действие.
- **Секреты** — зашифрованные значения (тот же механизм, что ключ ассистента), только запись и использование на сервере;
  интерфейс расширения ключ не видит.
- **Сеть** — `POST workspaces/:id/ext/:extId/fetch`: запрос к хосту из `permissions.network` манифеста через SSRF-защиту
  (`remote-url-guard`), секрет подставляется на сервере по ссылке. CORS внешних сервисов перестаёт быть проблемой.
- **Данные ORION** — через `@orion/core-react` с правами пользователя (как сейчас у любого кода интерфейса).

### 7. Серверный код — не на первых этапах

Расширение не исполняет свой код на сервере в этапах E1–E4. Фоновые задачи (например, раз в час забирать расход токенов)
появятся как декларативные **расписания**: манифест описывает запрос через сервис «Сеть» и коллекцию для результата, ядро
выполняет. Произвольный `server.js` — отдельное решение (E6), только локально и с отдельным подтверждением.

### 8. Безопасность и режимы

- Модель доверия как в Obsidian: подтверждённое расширение в интерфейсе работает с правами пользователя. Разрешения
  манифеста (`network`, `secrets`, `data`, `orion`) обязательны и **принудительно проверяются на сервере** для сети, секретов
  и хранилища; для данных ORION они пока декларация, показываемая при подтверждении.
- `ORION_MODE=server`: расширения выключены (флаг `ORION_EXTENSIONS=on` — осознанное включение). LAN-клиент: расширения хоста
  не загружаются; позже — явное «поделиться расширением».
- Каталог в GitHub (индекс со ссылками, версиями и хешами) и подписи — после E4.

## Этапы

| Этап | Результат |
|---|---|
| E0 | ✅ плагины интерфейса по манифесту при сборке (`plugins-ext`) |
| E1 | универсальные места в ядре: динамические панели, виджеты дашборда, разделы настроек, команды; работают и для `plugins-ext` |
| E2 | загрузчик: папка, наблюдение, подтверждение, `GET /extensions/:id/web.js`, SDK в `globalThis`, CSP, режим разработчика; `orion-ext init/build` и шаблон |
| E3 | хранилище расширений (таблица, RLS, API, бэкап), секреты, сетевой прокси с разрешениями |
| E4 | пилот — «Расход токенов ИИ» как расширение: панель, виджет, настройки, расписание опроса |
| E5 | собственные слоты расширений (`provides.slots`), декларативные расписания |
| E6 | каталог в GitHub, подписи; решение о серверном коде |

Критерий готовности E4: на установленной сборке без пересборки папка расширения подхватывается, после подтверждения
появляются панель, виджет и раздел настроек; правка файла в режиме разработчика видна без перезапуска; выключение
расширения убирает всё, данные остаются.

## Решения владельца (20.10.2026)

1. **Папка расширений** — `Документы\ORION\Расширения`, кнопка «Открыть папку» в настройках; путь можно сменить.
2. **Подтверждает** любой локальный пользователь установки, владеющий хотя бы одним пространством; подтверждение действует
   на всю установку.
3. **LAN-клиенты** расширения хоста не загружают. В будущем — возможность **поделиться** расширением с клиентом (явное
   действие, не автоматическая загрузка).
