# ADR-0041 — Agent Hub reported runtime registry (PROPOSED)

**Date:** 2026-10-29  
**Status:** F3c code in a stacked draft branch; tests written, not run. Depends on F0/F1/F2 and Habitat F3/F3b.

## Decision

Use a new Agent Hub-owned `AgentHubRuntimeSession` table to store **short-lived presence reports** from separately authenticated Agent Gateway tokens. This is not a trusted OS runtime registry and does not grant a shell/CLI launch capability.

- A session is a UUID generated by the local process and bound by the server to its actual `AgentContext.tokenId` and `workspaceId`. IDs are never accepted as authority.
- The initial only admissible kind is `habitat_observer` with exact capabilities `canStart=false`, `canCancel=false`, `canObserve=true`, `canResume=false`. Zod validates the schema before registration.
- `POST /ai/v1/agent-hub/runtime-sessions` registers an active session with server time, 5-minute TTL and revision 0. Replaying an identical session ID with the same token is idempotent while unexpired; another token cannot steal it. At most four unexpired sessions per token.
- `POST /:sessionId/pulse` and `POST /:sessionId/close` check token ownership, workspace, active unexpired state and expected revision (CAS). Post-expiry resurrection is rejected: restart must use a new UUID.
- `GET /workspaces/:id/agent-hub/runtime-sessions` returns capped per-workspace reported inventory. The label `recent` means only that the server received a valid scoped bearer token within TTL, **not** that a model or Windows process remains running. A revoked token may temporarily remain `recent` until its TTL expires; future attestation needs immediate invalidation.
- RLS ENABLE + FORCE on the table, workspace cascade, module-enabled guard, token scopes/mode/modulePermissions and audit from AgentModuleToolsService. Untrusted provider/model names never become privileged fields.
- Transient runtime sessions are `ephemeral-excluded` from `.orion` snapshots. Restored ORION must not resurrect online presence from old backups.
- Pulse/close are modeled as `create` tools to reuse the existing strict Agent Gateway authorization and audit policy. This consumes the token's hourly write budget; operator configuration must account for intended heartbeat cadence.

## Threats not yet solved

No device-bound identity, secure enrollment, OS process attestation, nonce challenge, cryptographic provenance, automatic dispatch, Windows Job Object supervision, token revocation fan-out, role-specific runtime permissions, server-side background reconciliation, data-retention purge or verified artifacts. Do not enable unattended execution based on this table.

## Required integration acceptance

Migrate PostgreSQL, verify forced RLS under non-superuser, check generated registries and agent manual; test two tokens, duplicate registration, revision conflicts, expiry, module disable, revoked token, snapshot exclusion and concurrent registrations. Run Windows Habitat-to-ORION smoke with no privileged CLI launch. This branch only contains draft source and test code.
