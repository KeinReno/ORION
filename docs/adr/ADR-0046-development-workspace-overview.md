# ADR-0046: ORION DEV — обзор разработки

Статус: реализовано по запросу владельца от 02.11.2026.

Служебный план импорта после наполнения пространства не отвечает на вопросы «что разрабатывается» и «какую задачу открыть». Модуль orion-dev 1.1.0 получает рабочий обзор поверх существующих Project/Task, доступный той же роли owner/lead. Импорт остаётся отдельным явно выбранным разделом со всеми подтверждениями ADR-0045. Данные не создаются при просмотре.

Сопоставления читаются из already_mapped/candidateId существующего preview, не из совпадений названий. Канонические сущности поступают через публичные useProjects/useTasks, переходы — через panel-bus. Включён архив проектов. Неполное наполнение и недоступные объекты показываются явно. Ошибка загрузки скрывает счётчики, чтобы не утверждать нулевой прогресс. Статусы done и canceled не смешиваются; ни один из них не означает независимую приёмку.

Клиентская zod-проекция preview дополнительно сохраняет optional catalog.projects (id/title/phase), уже возвращаемый существующим сервером. Wire format, входы consent/apply и контрольные суммы не меняются. Старый payload без metadata остаётся валидным; такие проекты доступны во «Все этапы» и через задачи соответствующего этапа. Нового endpoint, записи, миграции, SDK или extension point нет.

Фиксированные русские подписи — только presentation. При ручном переименовании отображается каноническое значение. Импорт сохраняет исходный каталог и пользовательские поля. Фазы — навигация, а не автоматически принятые gates. Числа относятся к связанным задачам каталога, а не к выдуманным результатам разработки.

Сценарии, состояния и evidence: [UI brief](../../development/ORION_DEV_UI_2026-11-02.md).

Навигация обзора вне dock использует существующий panelWindowUrl с instance/workspaceId и canonical object panel. Импорт не меняет маршрут: открытие совпадений/результатов предлагается в основном окне, в отдельной панели команды отключены с объяснением. Это сохраняет текущие подтверждения при проверке плана.
