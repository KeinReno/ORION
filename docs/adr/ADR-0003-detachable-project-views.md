# ADR-0003 — Открепляемые виды проекта: идентичность панели и контракт видов

Статус: **предложено, не принято**. Дата: 2026-10-10. Источник: `FRONTEND_WORKSPACE_SPEC.md` §2 «Открепляемые части модулей» (UI-06).
Этот ADR описывает **что менять и в каком порядке**; реализация начинается после проверки осуществимости на desktop (Tauri) — её нельзя сделать «вслепую» в браузере.

## Что есть сейчас (проверено по коду)

- Проект открывается панелью-экземпляром `project:<id>` (`instanced: true` в `panel-registry.ts`), окно открепления — `/panel/project?instance=<id>` (`panelWindowUrl`).
- Подвиды проекта (Обзор, Задачи, План, Материалы, Сроки и деньги, Доступ) — **внутренние вкладки** `ProjectTab` внутри `ProjectWorkspacePanel`. У них нет собственной идентичности панели, поэтому «План» нельзя ни докировать рядом, ни открыть на втором мониторе отдельно.
- Открепление целых панелей уже работает: Tauri `WebviewWindow` и `window.open` в браузере (`detachPanelToWindow` в `layout.tsx`); новое окно получает пространство через `?workspaceId=` (сделано для оболочки в этом цикле).

## Решение (предлагаемое), в порядке реализации

1. **Идентичность вида.** Панель-экземпляр получает составной id `projectview:<projectId>:<viewId>` (`viewId` ∈ `plan`, `materials`, …). Реестр знает `kind = projectview`, параметры хранятся в `params`/`instance`. Старый `project:<id>` остаётся «целым проектом» и открывает вид по умолчанию. Права и доступность модуля **перепроверяются при открытии**; сохранённый id панели не является правом доступа.
2. **Один источник правды для содержимого вида.** `ProjectWorkspacePanel` не дублирует код: вкладки «План» и «Материалы» выделяются в самостоятельные компоненты `ProjectPlanView({projectId})`, `ProjectMaterialsView({projectId})`, которые одинаково рендерятся и во вкладке, и в отдельной панели. Данные — через те же хуки и API; **копирования локального состояния между окнами нет**, изменения синхронизируются через исходный API (react-query).
3. **Контракт видов (Extension Proposal `projects.views`).** Вместо жёсткого списка `ProjectTab` — реестр `{ id, label, icon, moduleId, component(projectId), detachable }`. Базовые виды регистрируются самим проектом; плагины (`canvases` из ADR-0001, аналитика из ADR-0002) добавляют свои без правки Base. Выключенный модуль не оставляет пустых вкладок.
4. **Жесты (после 1–3).** `Ctrl` + перетаскивание **за заголовок вида** → зоны «вкладкой / рядом / снизу» внутри Workbench (dockview уже поддерживает sidebar drag; нужен только источник перетаскивания из заголовка вида). Не начинать перенос из текстового поля, таблицы, события календаря и при обычном клике; стандартное `Ctrl+click` сохранить.
5. **Обязательная доступная альтернатива жесту:** в меню вида — «Открыть рядом», «Открыть в новом окне», «Вернуть в основное окно». Клавиатура и видимый focus — наравне с мышью.
6. **Состояние вида на уровне окна** (фильтр, масштаб Ганта, позиция): ключ `viewstate:<windowId>:<projectId>:<viewId>` в `sessionStorage`/`localStorage` по тому же принципу, что `dockLayoutStorageKey`.

## Что нельзя обещать без прототипа

Перенос панели **жестом за границу окна на другой монитор** — поведение ОС/Tauri, не гарантированное одинаково: в Tauri v2 `window.open` по умолчанию открывает системный браузер, а не нативное окно (см. «Осознанные упрощения» в `CLAUDE.md`). Поэтому жест «за край» остаётся отдельной проверкой осуществимости; **кнопка «Открыть в новом окне» — обязательный путь**.

## Порядок проверки (по шагам, каждый — отдельный коммит)

| Шаг | Проверка |
|---|---|
| 1–2 | Вид «План» открывается и во вкладке, и отдельной панелью; правка в одном видна в другом; выключенный модуль → вида нет |
| 3 | Вид, зарегистрированный тестовым плагином, появляется без правки `ProjectWorkspacePanel` |
| 4–5 | Ctrl+drag на web; меню «Открыть рядом/в окне/вернуть» на web **и** desktop; клавиатурный путь |
| 6 | Перезагрузка окна сохраняет масштаб и позицию |

## Что реализовано на 10 октября 2026

Шаги 1, 2 и часть 5 — **в виде меню «⋯» проекта** (пункты «План панелью / окном», «Материалы панелью / окном»), без жестов. Проверено в браузере: панель появляется вкладкой дока, отдельное окно открывается по `/panel/projectplan?instance=<id>&workspaceId=<id>`, данные те же (один API).

| Шаг | Состояние |
|---|---|
| 1. Идентичность вида | Сделано в форме, совместимой с реестром: виды-экземпляры `projectplan:<projectId>`, `projectmaterials:<projectId>` (а не составной `projectview:<id>:<view>` — формат `вид:экземпляр` уже понимают реестр, окно и сохранение раскладки). Модуль `projects` проверяется при открытии |

| 6. Состояние вида на уровне окна | **Не сделано** |
