# ORION для Windows: автономная установка

Сборка `ORION_0.1.0_x64-setup.exe` содержит интерфейс Tauri, скомпилированный API, Node.js и PostgreSQL 16. Для обычного запуска **не требуются** Docker, Node.js, pnpm, Rust или исходники. Это локальная установка для одного компьютера; синхронизация между домашним и офисным ПК требует отдельной настройки WebDAV в ORION.

## Для пользователя

1. Скачайте `.exe` из GitHub Releases проекта ORION, запустите и завершите установку для текущего пользователя Windows.
2. Откройте ORION через ярлык. Первый запуск создаёт базу и применяет миграции, поэтому может занять несколько минут. Окно откроется после готовности API.
3. Создайте локальную учётную запись в приложении. Данные сохраняются в `%LOCALAPPDATA%\com.orion.desktop`: `postgres` (база), `documents` (файлы), `local-runtime.json` (локальные ключи и пароли), `runtime.log` и `postgres.log` (диагностика). **Не удаляйте эту папку при обновлении или переустановке.**
4. Если запуск не состоялся, окно покажет путь к `launcher.log`; приложите также `runtime.log` и `postgres.log` из указанной папки. Перед передачей журналов проверьте их на личные данные. Порты `127.0.0.1:4000` (API) и `127.0.0.1:55432` (база) должны быть свободны.

Windows WebView2 нужен Tauri; NSIS может скачать его при установке, если он отсутствует. Этот выпуск не подписан сертификатом издателя, поэтому Windows может показать предупреждение SmartScreen.

Закрытие окна не останавливает локальный API и PostgreSQL: повторный запуск подключается к уже запущенному узлу. Перед **обновлением** завершите сеанс Windows или перезагрузите ПК, чтобы старые процессы освободили файлы приложения. Установка поверх старой версии сохраняет пользовательские данные в `%LOCALAPPDATA%`.

Перед переносом данных на другой компьютер делайте согласованную резервную копию узла (см. `DEPLOYMENT_READINESS.md`); простое копирование работающей базы не является надёжным бэкапом. `local-runtime.json` храните вместе с копией: без него локальная база не откроется.

## Для сборки релиза

На Windows x64 с Node/pnpm, Rust/MSVC и Tauri prerequisites:

```powershell
corepack pnpm install --frozen-lockfile
corepack pnpm build:desktop-installer
```

Готовый NSIS лежит в `apps/desktop/src-tauri/target/release/bundle/nsis/`. Команда собирает API, статический desktop export, создаёт временный `apps/desktop/src-tauri/resources/runtime/` через `pnpm deploy`, запускает Prisma Client generate внутри пакета и добавляет Node/PostgreSQL как Tauri resources. Временный каталог игнорируется Git; он не должен содержать `.env`, пользовательскую базу или документы. Инсталлятор **нельзя** собирать просто `tauri build`: без подготовленных ресурсов он не будет автономным.

Минимальная проверка перед публикацией: установить пакет на чистую Windows x64 без Node/Docker, пройти создание учётной записи, перезапустить приложение, проверить основные модули, загрузить и скачать документ, выполнить backup/restore на отдельной копии, проверить обновление и повторный запуск. Локальный smoke на машине сборки подтверждает только запуск API и миграции; он не заменяет эту проверку.

Проверено 12 октября 2026 года на машине сборки: NSIS установился в отдельную папку без ошибок; установленный `orion-desktop.exe` поднял собственный PostgreSQL и production API; `/system/health` вернул `status=ok, database=ok`, окно WebView загрузило страницу входа и запросило список аккаунтов. На отдельном тестовом каталоге данных прошли все 80 миграций, регистрация, вход по PIN и чтение первого пространства. Повторный запуск подтвердил отсутствие ожидающих миграций. `typecheck`, `lint` (2 прежних предупреждения), 509 unit-тестов, `architecture-check` и `plugin-contract-check` прошли. **Чистая офисная машина, обновление поверх опубликованной версии и восстановление backup не проверены**; эти проверки остаются перед стабильным выпуском.
