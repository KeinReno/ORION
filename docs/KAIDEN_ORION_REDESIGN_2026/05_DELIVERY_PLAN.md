# 05. План выполнения, gates, rollback

## Нулевой этап — обследование (обязателен)
- Зафиксировать ревизию, собрать дерево релевантных файлов, прочитать `AGENTS.md`, `ORION_CONSTITUTION.md`, `docs/FRONTEND_WORKSPACE_SPEC.md`, `docs/AI_REFACTOR_MIGRATION_MAP.md`, `docs/UI_AUDIT_2026-10-11.md`.
- Инвентаризировать действующие shell/sidebar/theme implementation, routes, Dockview, WebviewWindow, инспектор, компоненты `packages/ui` и типизированные слоты расширений.
- Снять screenshot-baseline реальных экранов в web/desktop, включая узкое окно, смену workspace, проекты, задачи, заметки, календарь и плагины; зафиксировать известные недоработки отдельно от редизайна.
- Составить матрицу «сохранить / переработать / удалить после parity» с владельцами компонентов и зависимостями.
- Замерить time-to-interactive, ключевые сценарии и визуальные регрессии; проверить текущие тесты и CI.
**Gate 0:** подписан scope изменений и rollback; нельзя заменять рабочие функции по макету.

## Фаза 1 — фундамент Design System
Ввести версионированные семантические tokens и ThemeProvider/adapter поверх действующего стека. Реализовать KAIDEN Precision как **опцию**, не форсировать у прежних пользователей; выделить компоненты (button, tab, panel, item, inspector). Мигрировать 1–2 безопасных компонента; screenshot parity.
**Gate:** модули со старым UI продолжают работать; нет конфликта CSS/SDK.

## Фаза 2 — Theme Engine
Предустановленные light/dark темы, глобальный выбор, сохранение пользовательских настроек, редактор custom theme, preview/undo, import/export с валидацией, per-space overrides. Раздельная плотность. Кросс-оконное распространение предпочтений через легальный канал приложения.
**Gate:** светлая/тёмная/кастомная темы, смешанные пространства, плагины, Tauri; тест контраста.

## Фаза 3 — оболочка и навигация
Рефактор существующего shell без замены Dockview; единый каталог ObjectRef/ViewRef, навигация global/space/object, command palette, контекстный inspector, clear provenance для видов из разных пространств, восстановление layout.
**Gate:** все базовые пути доступны мышью/клавиатурой; нет утечек workspace при переходе.

## Фаза 4 — оконная модель и рабочие виды
Регистрируемые подвиды проектов; «открыть рядом/в новой вкладке/в отдельном окне», восстановление состояния, fallback при удалённом объекте или отключённом модуле. Поддержка разных мониторов без синхронизации координат между устройствами.
**Gate:** recovery после перезапуска; тесты Tauri/web; работа с двумя пространствами в окнах.

## Фаза 5 — поэтапная визуальная миграция модулей
Проекты → задачи → заметки/документы → календарь → остальные модули/плагины, **по одному вертикальному срезу**. Сначала интерфейс, затем отдельные ADR при изменении модели данных.
**Gate:** functional parity и визуальные diff; existing data untouched.

## Фаза 6 — необязательные расширения (отдельные PR/ADR)
Смешанные рабочие сессии, межпространственные операции и связи, Atlas views, Command/agent dashboard, дополнительная аналитика. **Не обещать** готовность отсутствующих API, real-time sync или сетевых устройств только из-за концепта.
**Gate:** оформленные контракты, сценарии ACL, ADR где требуется.

## Обязательные проверки для каждого среза
`pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm architecture-check`, `pnpm plugin-contract-check`, E2E/screenshot smoke, `pnpm build:desktop-export` при соответствующих изменениях; учесть DB-dependent integration и проверить их при доступной БД. Не писать «прошло», пока команды не запущены.

## Выпуск и откат
- Новая shell/theme логика вводится под версионированным feature flag, желательно поэтапно; исходные пользовательские настройки не терять.
- Миграция preference schema имеет backward-compatible чтение и стратегию отката.
- Перед релизом — backup, data integrity smoke, профиль `default-full` и сравнение с baseline.
- Не удалять старые компоненты до подтверждённого покрытия эквивалентной функции и прохождения parity.

## Результат каждого этапа
PR с коротким changelog, список изменённых файлов/контрактов, тест-результаты и известные ограничения; обновлённые screenshots и чеклист ручной проверки. Одна проблемная область на PR. Не смешивать extract-to-plugin и UX redesign.
