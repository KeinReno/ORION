# 09. Precision: рабочая оболочка, контекст пространства и проекта

Дата: 2026-10-16. Это первый видимый срез **основного приложения**, а не образец в настройках.
Ветка: `redesign/kaiden-foundation-20261015`. PR: https://github.com/KeinReno/ORION/pull/1 (draft).

## Как включить и откатить

Настройки → Внешний вид → Оформление Orion → **KAIDEN Precision — новая оболочка**.
Выбор сохраняется существующим `PATCH /settings/preferences` в учётной записи и переживает перезапуск.
Он применяется в основном и отдельных окнах через общий провайдер и действующий `CrossWindowSync`.
Прежний интерфейс возвращается выбором «Прежний интерфейс». Акцент, фон, прозрачность, папки,
порядок модулей, плотность, положение меню и раскладки не переписываются при включении Precision.
Временно неприменимые настройки фона/акцента скрыты в Precision; при возврате они доступны снова.

Использован существующий строковый столбец `UserPreference.theme`: добавлено валидируемое значение
`kaiden-precision`. SQL-миграции, новые таблицы, зависимости и изменения доменных данных не требуются.
Старые `system` / `dark` / `light` сохраняют прежнее поведение. Автоматического включения у существующих
пользователей нет. На этом переходном этапе одна явная опция включает новую оболочку и её палитру;
это не завершённая независимая система выбора всех тем и вариантов оболочки.

## Соответствие исходному замыслу

| Требование | Реальный результат этого среза |
|---|---|
| Глобальный rail | Реестр действующих модулей, существующие порядок/группы/действия. В свёрнутом Precision-rail папки не поглощают иконки модулей. Позиции меню и подписи по закреплению сохранены. |
| Контекст пространства | Отдельная панель: текущий workspace, предыдущий/следующий при наличии, поисковый список даже для одного workspace, реальные проекты, поиск, закрепления и существующие папки разделов. |
| Работа с объектами | Проект открывается через существующий `openEntity`; доступные обзор/задачи/материалы/план/доступ — через зарегистрированные виды. Меню проекта предлагает открытие рядом и в отдельном окне. |
| Контекст объекта | По запросу справа — реальные свойства активного проекта: владелец-пространство, описание, статус, счётчики задач, срок, контекстная заметка и переходы к доступным представлениям. По умолчанию закрыт. |
| Precision в самом продукте | Семантические переменные применены к существующим поверхностям, тексту, границам, акцентам, общим компонентам и Dockview. Активная вкладка обозначена спокойной поверхностью и золотой линией. |
| Узкое окно | Контекст пространства открывается отдельной доступной панелью с Escape/focus trap. На широком экране свойства стоят рядом, на меньшем — раскрываются по запросу. Нового overlay-редактора задач нет. |
| Данные и черновики | Сохраняются существующие guards workspace-switch и close-tab. Дополнительно закрыт обход guards при навигации в режиме «Заменять текущую» и на узком экране: переход останавливается до сохранения черновика. |

Это развитие существующего Dockview/Workbench, а не замена движка. Переход на Precision не перемонтирует
Workbench и его панели. Одна сущность не копируется при открытии представления. Если такой вид уже открыт,
действует прежнее правило focus-or-create; команда «рядом» не дублирует уже открытую вкладку.

## Контракты и ограничения

- Проекты читаются публичными `useProjects` / `useProject`; конкретные внутренности модулей или плагинов не импортируются.
- Каталог представлений фильтруется существующими `isPanelAvailable` и состоянием Tasks. План отсутствует при выключенном planning-плагине.
- Workspace-switch использует прежний `requestWorkspaceSwitch`, API авторизует каждый запрос. Инспектор получает текущий workspace и не наследует данные прежнего объекта как fallback.
- Закрепления проектов — личная метаинформация **на устройстве**, отдельно по пользователю и пространству. В хранилище только ID, подписи и доступность берутся из текущего разрешённого ответа API. Отключение модуля/ошибка сети не чистит закрепления.
- Повреждённый JSON закреплений игнорируется; ошибка записи показана пользователю. Это не синхронизация закреплений между устройствами.
- В инспектор не добавлены фиктивные «История», «Связи», «Доступ» с отсутствующими данными. Доступ и материалы открывают реальные существующие представления.
- Инспектор этого среза работает для проектов и их зарегистрированных подвидов. Задачи, заметки и документы сохраняют существующий редактор/контекст; общий инспектор всех типов ещё не готов.
- Нет workspace override темы, сохранения произвольной импортированной палитры как глобальной темы, полной библиотеки из шести тем или редактора радиусов. Предпросмотр/import/export из предыдущего среза остаётся отдельным образцом.
- Модель mixed-space sessions, единый ObjectRef/ViewRef registry, device-aware window recovery и полная миграция модулей остаются в плане. Не считаем фазы 2–4 целиком завершёнными.

## Проверки

- Unit: **800 passed / 102 files** (включая 4 проверки границ контекста, изоляции/валидации закреплений и совместимости значений theme).
- PostgreSQL integration: **11 passed / 3 files** — личные скрытые модули, сферы/избранное пространств, plugin gates; отдельная БД на `127.0.0.1:5547`.
- Архитектурная проверка и **10 plugin contract tests** прошли.
- Lint: 0 ошибок; прежние 2 предупреждения hooks в CalendarPanel и DocumentsPanel.
- Полная проверка типов прошла.
- Production browser suite: **53 passed**; после последней правки позиционирования меню отдельно повторены **2 сценария оболочки — passed** на production-сервере.
- Финальные production web build и desktop export с последней правкой меню **прошли**.
- Полный backend integration suite не завершён: заявленные 11 проверок относятся только к трём указанным файлам.

Браузерные сценарии новой оболочки проверяют реальный saved preference, включение без потери черновика,
reload, закрепления, свёрнутую папку при видимых иконках, смену workspace и возврат, отдельное окно
с правильным workspace и синхронизацией темы, rollback без перезаписи прочих настроек, ширину 390px,
выключенные плагины, доступные/недоступные подвиды, остановку перехода при несохранённом вводе и поиск.
Дополнительно: отмена локального Arctic-preview возвращает текущую Precision-тему, проверена ширина 768px,
после меню закрепления нет горизонтального сдвига содержимого контекста.

Нативный запуск Tauri, установщик, несколько физических мониторов и production TTI в этом срезе
не проверены. Web/desktop export не выдаём за их приёмку. Главный checkout на Desktop и его данные
не изменялись. В открытой демонстрации — специально созданные тестовые проекты и задачи.

## Следующий законченный срез

1. Расширить контекст объектов на задачи/заметки по существующим публичным контрактам, сохранив side-by-side и autosave задач.
2. Довести Theme Engine: безопасное сохранение пользовательской палитры, полный выбор тем и workspace overrides с отдельной приёмкой светлой темы всех модулей.
3. Закончить ObjectRef/ViewRef и восстановление подвидов/окон; проверить реальные Tauri-окна и два пространства на нескольких мониторах.
4. Последовательно переработать рабочие панели проектов → задач → заметок/документов → календаря. Текущий срез меняет оболочку и общую палитру, а не все внутренние экраны.
