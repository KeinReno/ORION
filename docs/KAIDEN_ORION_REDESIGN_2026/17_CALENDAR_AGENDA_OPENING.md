# 17. Открытие исходных объектов из календарного списка

Дата: 2026-10-16. Основа: `7a2d115`. Продолжение [15](15_LINKED_OBJECT_OPENING.md)–[16](16_SEARCH_AND_PROJECT_OPENING.md), ограниченное видом календаря **«Список»**.

## Пользовательский путь

Календарь → Список → «⋯» у задачи или заметки → новая вкладка / рядом / отдельное окно. Используется общее ObjectOpenMenu и прежние самостоятельные редакторы над теми же ID. Обычное нажатие на строку по-прежнему вызывает старое открытие исходной записи; нативное событие открывает существующий редактор события.

При открытии рядом календарь остаётся на месте. Возврат к его существующей вкладке сохраняет выбранный вид «Список» и введённый фильтр в текущем запуске. Это не добавление истории переходов или восстановления после перезапуска. Черновик задачи после ошибки autosave остаётся в её панели при открытии заметки из календаря и может быть сохранён повторно.

Меню относится к задаче/заметке, а не к копии Event. Оно не меняет dueAt/eventAt, время события, принадлежность пространству или права. Неподдерживаемые виды (события, платежи, дни рождения) не получают фиктивных команд самостоятельного открытия; их прежние действия сохраняются.

## Контракт и реализация

- Optional `CalendarProps.renderAgendaItemActions(item)` — типизированный callback представления в общей UI-библиотеке. Он рисует соседние действия строки Agenda, отдельно от основной кнопки, без вложенных интерактивных элементов. В UI-пакете нет доменных API/навигации.
- CalendarPanel предоставляет ObjectOpenMenu только для включённых источников tasks/notes. ViewRef содержит workspaceId текущего пространства, тип и исходный ID. При исполнении действуют проверки workspace/module/plugin и guards из этапа 15; редактор обращается к прежнему авторизуемому API.
- Глобальные клавиши календаря больше не перехватывают Enter/стрелки у кнопок, ссылок, меню и переключателей. Навигация по выбранной записи и её перенос остаются доступны при фокусе на календарном контейнере.
- Сетки месяц/неделя/день и их drag/resize не переработаны. Другие потребители Calendar без нового callback не получают доменных меню.
- Новых зависимостей, миграций, бизнес-операций, хранилищ предпочтений или прямых импортов плагинов нет. Основной checkout Desktop/ORION и его БД не менялись.

## Проверка

809 unit-тестов / 105 файлов, 10 plugin contract tests, typecheck, architecture, lint (0 ошибок, 2 прежних предупреждения), pnpm build (API/web) и desktop static export прошли. Общий browser regression: 64 passed / 1 fixture failure; отдельный повтор обоих календарных сценариев на той же сборке без изменений кода: 2 passed / 0 failed. Общие 65 после сбоя целиком повторно не запускались.

Итоговые значения: [validation.json](evidence/calendar-object-opening/validation.json). Снимки: [default-full](evidence/calendar-object-opening/calendar-objects-default-full.png), [plugins-off](evidence/calendar-object-opening/calendar-objects-plugins-off.png).

Новые browser-сценарии идут в обоих профилях и используют реальные API/БД на изолированных web 3110 / API 4100 / PostgreSQL 5547 с синтетическими аккаунтами. Проверены: задача рядом с календарём через Enter; сохранение вида и фильтра; ошибка autosave, заметка в отдельном окне и вкладке; отсутствие второго редактора задачи из-за перехвата клавиши; правильные workspace/ID окна; возврат в календарь; retry; точное количество сущностей и неизменные dueAt/eventAt/startAt/endAt; прежнее открытие нативного события и закрытие без записи.

Клавиатурные команды и точные даты/ID проверены на реальных записях. Native Tauri, физические мониторы, drag/resize на физическом устройстве и полная доступность всех состояний этим тестом не подтверждаются.

В первом общем production-прогоне подготовка plugins-off аккаунта завершилась HTTP 500 до открытия календаря: при отключении finance-transfer-match транзакция Prisma превысила лимит 5000 ms (8650 ms). Причина задержки не установлена. Результат этого прогона и отдельного повтора записан в validation.json; код API и таймауты не менялись ради прохождения проверки.

## Что остаётся

Команды открытия в сетках месяц/неделя/день требуют отдельного решения по компактной геометрии, меню и жестам. Далее остаются самостоятельный вид документа, другие точки входа, полный каталог объектов/видов, история назад/вперёд и сериализуемое состояние видов/окон. Внутренняя визуальная миграция модулей, Theme Engine/overrides и native recovery остаются в общем плане.

Откат — возврат к прежнему коду, без миграции и удаления пользовательских записей.
