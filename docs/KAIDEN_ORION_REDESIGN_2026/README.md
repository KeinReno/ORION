# KAIDEN Orion — Workspace & Visual Redesign
Дата: 2026-10-15. Статус: продуктовые требования утверждены по направлению; реализация не начата этим документом.

## Цель
Развить текущий Orion в единую гибкую рабочую среду с общим визуальным языком, настраиваемыми темами, многооконностью и безопасной работой в нескольких пространствах — **не теряя существующих функций и данных**.

## Канонические документы и приоритет
1. `../../AGENTS.md` и `../../ORION_CONSTITUTION.md` — обязательные архитектурные правила.
2. `../AI_REFACTOR_MIGRATION_MAP.md` — существующее распределение Core / Base / Plugin; изменения через ADR.
3. `../FRONTEND_WORKSPACE_SPEC.md` — ранее согласованные детали UX, применяются при отсутствии более позднего прямого решения.
4. Этот пакет — отдельный **продуктовый редизайн**, не заменяет и не подменяет архитектурную экстракцию плагинов.

## Обязательный принцип
Не удалять пользовательские возможности, данные или работающие механизмы ради макета. Визуальные изображения — **иллюстрации**, не перечень реализованных функций и не точные требования к статистике/датам/агентам. Все изменения — маленькими вертикальными срезами с проверками и обратимым внедрением.

## Что уже известно по репозиторию (без запуска приложения)
Монорепозиторий: Next.js (`apps/web`), NestJS (`apps/api`), Tauri (`apps/desktop`), общий UI (`packages/ui`). README указывает Dockview, Tauri WebviewWindow и глобальный поиск; `FRONTEND_WORKSPACE_SPEC.md` подтверждает, что Dockview и открепление целых панелей уже имеются, а подвиды проекта пока необходимо оформить самостоятельными регистрируемыми панелями. Не разрабатывать второй оконный движок. Полноценная двусторонняя синхронизация между устройствами **не подтверждена**; WebDAV — механизм backup/restore, см. `../SYNC.md`.

## Стартовый шлюз
Прежде чем менять фронтенд, провести воспроизводимый аудит актуального UI и кода: маршруты и навигация, существующие токены/темы, Dockview, инспектор, плагины, режимы Tauri/web, данные и пользовательские сценарии. Составить screenshot-baseline и parity checklist. Каждый реализуемый пункт соотнести с этим пакетом и действующими ADR.
