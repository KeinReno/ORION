# Theme Engine: безопасный формат и пользовательский предпросмотр

Дата: 2026-10-16. Основа: `264b8dd`, продолжение PR №1.
Срез завершает миграцию полей/подсказок/уведомлений и начинает фазу 2.
Это рабочий предпросмотр в настройках, не глобальное включение новой темы.

## Что доступно пользователю

Ветка добавляет **Настройки → Внешний вид → Предпросмотр тем**:

- KAIDEN Precision и светлая Arctic на настоящих Input, Textarea, Select,
  Button, Modal, Tooltip и Toast.
- Создание одной редактируемой копии; выбор четырёх основных цветов.
  Изменение акцента согласует hover, foreground и focus. Предустановки не мутируются.
- Импорт и экспорт JSON, сброс образца, включение и отмена предпросмотра.
- Показ отношения контраста основного текста к поверхности; предупреждение ниже 4.5:1.
- Черновик внутри открытого диалога остаётся на месте при отмене темы.

Редактируемая копия живёт до выхода из раздела «Внешний вид»; это явно написано
в интерфейсе. Для её сохранения уже доступен
экспорт. Переключение между предустановкой и копией сохраняет копию в текущем
сеансе компонента. Импорт заменяет образец только после успешной валидации.
Создание другой копии явно называется «Заменить копию», если своя копия уже есть.
Поздний ответ чтения файла не переопределяет более поздний выбор/сброс пользователя.

Предпросмотр **не** пишет UserPreference, localStorage или БД. Не изменяет
плотность, фон и прозрачность основного приложения. Существующий `theme` enum
не переинтерпретируется как новый формат и не мигрируется без отдельного контракта.
Фирменная эмблема, данные, права, маршруты и модули не менялись.

## Формат темы и публичный SDK

`packages/ui/src/theme-engine.ts`, экспорт через `@orion/ui`:

- `ThemeDocument`: `schemaVersion: 1`, безопасный `id`, имя, `baseMode`, именованные цвета.
- `parseThemeDocument`: JSON/объект, ограничение 16 КиБ, строгий список полей,
  только `#RRGGBB`; недостающие известные цвета заполняются из dark/light основы.
- Неизвестная версия отклоняется без перезаписи состояния. Это первый формат,
  поэтому не изобретается миграция из никогда не выпускавшейся схемы v0.
- CSS, JS, URL, произвольные имена variables и prototype keys не принимаются.
  Компилятор выдаёт только разрешённые RGB-токены и существующие component aliases.
- `resolveThemeDocument`: `preview > workspace > user > application`.
  Невалидный более высокий слой не уничтожает валидный нижний.
  Пока это проверенный публичный контракт; Settings preview использует только
  ephemeral слой. User/workspace backend integration ещё не подключена.
- `exportThemeDocument`, `themeDocumentVariables`, `withThemeColor`, `themeTextContrast`.

`ThemeProvider` получил необязательный `definition`; точный флаг
`kaiden-theme-v1` обязателен и для JSON-тем. Невалидная definition оставляет
выбранную built-in/legacy fallback. `useTheme().theme` теперь строковый ID,
так как пользовательские документы имеют собственные ID. `color-scheme` задаётся
только внутри области и переносится в её portals, не на `html`.

Новых зависимостей нет. Публичный формат находится в Design System;
перед подключением к API его хранение/валидация должны стать согласованным
серверным контрактом, без дублирования другой схемы в backend.
Data-only контракт при этом следует вынести в shared-types с совместимым
re-export из UI: backend не должен импортировать React/UI runtime.

## Завершённая миграция общих компонентов

- Input / Textarea / Select: semantic text, placeholder, border, tint, focus;
  native options наследуют палитру. Legacy значения совпадают с прежними.
- IconButton и остальные варианты Button: semantic foreground/tint/status/focus.
- Tooltip: scope темы и `color-scheme` проходят через portal.
- Toast: scope фиксируется в момент вызова **у вызывающей области**, а не у
  глобального ToastProvider. Два сообщения из разных областей сохраняют
  независимое оформление. Уже созданный toast остаётся в теме события до закрытия.
- `useToast()` сохраняет стабильность объекта/функций при смене темы; текущий
  scope читается при вызове. Это предотвращает повторные эффекты у существующих
  потребителей, использующих toast callback в dependencies.

Таймеры, жест закрытия, действия сообщений, логика форм, отмена и API не переписаны.
Card, Sidebar, Dockview chrome, календарь и оставшиеся domain styles ещё не
мигрированы целиком. Светлая тема всего приложения этим срезом не объявляется готовой.

## Проверки и доказательства

- Unit: проверка формата, defaults, export/import roundtrip, неизвестных версий,
  вредоносных цветов/полей, размеров, приоритетов и контраста редактируемого акцента.
- Реальные React components в jsdom: opt-in для definition, fallback,
  scoped color-scheme, tooltip portal, два toast scope и стабильный toast API.
- Browser: настоящий Settings route на 1280 и 390 px; светлая палитра, focus,
  tooltip/toast/dialog, cancel, сохранение введённого, отсутствие overflow.
- Browser сравнивает сохранённые preferences до/после и проверяет **ноль PATCH/POST/PUT/DELETE**
  к `/settings/preferences` в ходе предпросмотра.
- При plugins-off проверены копирование, редактор цвета, экспорт JSON,
  отказ от unsafe import с сохранением предыдущей палитры, валидный import и reset.

Runtime baseline: по 16 снимков до/после на синтетическом workspace, отдельные
web/API/Postgres 3110/4100/5547. Page errors и failed HTTP — 0 в обоих проходах.
11 пар совпали попиксельно; остальные различия — динамические timestamps/shell,
не используются как golden acceptance. В исходных snapshot inventories действий
этот срез ничего не обновляет.

## Откат и следующие работы

Срез обратим Git revert, без обратной миграции БД или preferences. Основной
Desktop/ORION не переключался и не изменялся. PR остаётся draft.

Следующий самостоятельный срез фазы 2: версия сохранённых theme preferences,
серверная валидация/хранение, global/user/workspace scope и доставка изменений
через штатный межоконный канал; явное применение/отмена и восстановление после
перезапуска. Не заменять это самодельной синхронизацией localStorage.

После этого — остальные предустановки, полная матрица контраста/компонентов и
native Tauri, multi-monitor, workspace-switch drafts, production TTI gates.
Навигация трёх уровней остаётся фазой 3, Dockview сохраняется.
