# 13. Сохранённая пользовательская палитра

Дата: 2026-10-16. Основа: be58261. Ветка `redesign/kaiden-foundation-20261015`, [draft PR #1](https://github.com/KeinReno/ORION/pull/1).

## Пользовательский путь

Настройки → Внешний вид → Предпросмотр тем → выбрать основу → Создать копию → название/цвета → **Сохранить и применить**. До этой кнопки preview остаётся локальным. Применение явно включает Precision и сохраняет палитру в личных настройках учётной записи через существующий API. Она восстанавливается после перезагрузки, в новой браузерной сессии и в отдельном окне приложения.

**Загрузить сохранённую** возвращает записанные цвета в редактор. **Вернуть стандартную палитру** выключает применение и сохраняет саму палитру для повторного использования. Переключение на прежний интерфейс также сохраняет запись: custom-палитра применяется только при Precision. Прежние акцент/фон/плотность/эффекты не переписываются. В этом срезе хранится одна личная палитра, не библиотека нескольких тем.

При ошибке записи остаются текущие цвета приложения и редактируемый образец; пользователь может повторить. На время записи элементы редактора отключаются, чтобы подтверждение относилось к отправленной версии. Сообщение об успехе показывается только после подтверждения сервером содержимого и применения. Изменение образца снимает прежнее сообщение об успешном сохранении. Тёмная и светлая основы поддерживаются форматом; полная приёмка всех внутренних экранов на светлой/пользовательских темах остаётся отдельным gate.

## Контракты и данные

- Публичный themeDocumentSchema в shared-types: версия 1, ограниченные ID/имя, dark/light и полный фиксированный набор HEX-цветов. Неизвестные поля/версии, CSS, URL и произвольные ключи не принимаются. Совместимость с публичным UI-форматом проверяется тестом на обоих пресетах. UI-пакет сохраняет независимость от доменного API.
- UserPreference дополнен optional-полями customTheme / customThemeEnabled для совместимости чтения прежних ответов. PATCH остаётся частичным: старые изменения настроек не сбрасывают палитру.
- Включение требует передать документ и флаг вместе, одной записью. Удаление документа через null одновременно выключает применение. Повреждённое/неподдерживаемое содержимое при чтении даёт безопасный fallback, не переписывая исходную запись.
- Миграция `20261016110000_user_custom_theme`: nullable JSONB и boolean default false в user_preferences. Прежние пользователи и данные не преобразуются автоматически.
- Место хранения — личные настройки, не workspace. Права определяет текущий пользователь JWT. Палитра не выдаётся другому пользователю и не переносится через workspace backup: UserPreference уже исключён как identity-scoped модель.
- Изменения передаются между окнами существующим механизмом инвалидирования query cache; новые способы синхронизации/localStorage не добавлены.
- Глобальный ThemeProvider и html-токены получают одно эффективное значение. Активная панель/пространство не меняет персональную тему всего приложения. Workspace overrides этим срезом не вводятся.

## Проверка

Результаты: [validation.json](evidence/saved-user-theme/validation.json).

- 806 unit-тестов / 104 файла, включая совместимость UI/public schema, старые/повреждённые preferences и атомарную активацию.
- 8 API/DB-тестов / 2 файла: custom-theme и прежние personal hidden modules; отдельная БД на 5547. Проверены round-trip, другое изменение preferences, выключение без удаления, очистка, изоляция пользователя, 401 и отказ некорректным документам без порчи записи.
- Browser-сценарии dark/light: preview без глобального применения; ошибка 503 и повтор; реальные цвета кнопки/фона и color-scheme; перезагрузка; новая сессия без копирования palette cache; отдельное окно; возврат стандартной палитры с сохранением записи и прежних настроек.
- Общий browser regression: 59/59 до финального исправления валидации экспорта. После исправления повторены desktop export, web production build и пять тематических browser-сценариев: 5/5, включая пустое имя при экспорте. Полный набор из 59 после этой последней правки повторно не запускался. Typecheck/lint, architecture и API build прошли; lint содержит два прежних предупреждения. Нативный Tauri/установщик и физические мониторы не проверялись.

## Развёртывание и откат

Применить миграции к целевой БД, сгенерировать Prisma client и собрать/перезапустить API до обновления web. В текущей работе изменена только изолированная тестовая БД 127.0.0.1:5547; основной checkout Desktop/ORION и его БД не менялись.

Для локальной проверки соблюдён порядок: остановить dev → desktop export → web build с API 4100 → production start 3110 → E2E. Desktop export этой версии Next использует .next как промежуточный каталог, поэтому параллельная работа со сборкой preview недопустима.

Пользовательский откат — выключить свою палитру либо выбрать прежнее оформление. Откат к прежнему коду не требует удаления колонок: новые nullable/default-поля могут остаться в БД, а цвета — сохраниться для возврата на новую версию. Не выполнять DROP/обратное уничтожение пользовательских палитр ради отката UI. Перед реальным релизом остаётся штатная проверка backup/выпуска; она не подменяется локальной миграцией.
