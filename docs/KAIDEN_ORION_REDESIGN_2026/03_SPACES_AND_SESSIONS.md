# 03. Пространства, рабочие конфигурации и безопасность

## Чёткое разделение
- **User:** субъект прав доступа.
- **Space / Workspace (пространство данных):** владелец записей, участники, политики и модульные настройки.
- **Layout / рабочая конфигурация:** UI-представления и окна, ссылки на объекты, фильтры, масштабы. Это **не** контейнер данных и не отдельный уровень прав.
- **Session / временная рабочая сессия:** временный сохранённый или несохранённый набор видов из доступных пространств. Отложенный функциональный срез, не новый workspace в БД.

## Смена пространства
Сохранять выбранные вкладки, вид, фильтры и состояние скролла там, где применимо. На переходе отключить показ данных прежнего пространства до загрузки нового. Несохранённые данные явно сохранить, оставить черновик либо запросить действие. Повторное открытие проверяет права и включённые модули.

## Смешанная рабочая область
Две панели из разных пространств могут одновременно отображаться в одном window layout. У каждой вкладки/панели есть чёткий provenance badge (название/значок пространства). Глобальный фильтр рабочего пространства не должен незаметно переопределять пространство уже открытой панели. Команды записи всегда адресуются `ObjectRef.workspaceId`.

## Межпространственные операции
- **Копировать:** независимый объект с новым ID и явной фиксацией происхождения.
- **Переместить:** отдельная разрешённая транзакция; проверить ссылки, доступ, перенос связанных ресурсов и аудит, иначе отказ.
- **Связать:** link-reference, не повышение прав и не копия.
- **Предоставить доступ:** отдельная авторизуемая операция по существующей модели membership/sharing; ссылка сама по себе доступ не даёт.
- **Создать связанную задачу:** новая задача в выбранном пространстве со ссылкой на исходный разрешённый объект.

Права проверяются и при выдаче результатов поиска/превью, и при последующем открытии. Для чужого объекта не раскрывать заголовки, внутренние ID, описания. Cross-space linkage до implementation требует отдельного анализа действующих контрактов / Module Bridge; если отсутствует типизированный slot/контракт: `NEW_EXTENSION_POINT_REQUIRED` + proposal.

## Несколько пользователей и устройств
Для общего «Дома» на двух ПК пользователь остаётся субъектом доступа, LAN discovery не заменяет авторизацию. По данным `../PRODUCT_DIRECTION.md` и `../SYNC.md`, WebDAV — encrypted backup/restore, **не** доказанная live sync. Общий авторитетный API — отдельное решение; без принятого протокола не заявлять offline conflict-free editing. Агентам выдавать ограниченные разрешения и журнал операций, не прямой доступ к БД. Действия переноса/раскрытия между пространствами — с подтверждением.

## Порядок внедрения
Сначала восстановление layout для одного workspace, потом многоконность, затем mixed-space views при готовых ACL контрактах, и лишь затем перенос/связи/временные сессии. Не вводить фальшивую синхронизацию через localStorage или WebDAV snapshots.
