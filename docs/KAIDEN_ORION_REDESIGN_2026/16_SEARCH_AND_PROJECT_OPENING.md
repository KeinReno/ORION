# 16. Общие команды открытия в поиске и материалах проекта

Дата: 2026-10-16. Основа: `9b47ed5`. Продолжение объектной навигации из [15](15_LINKED_OBJECT_OPENING.md) и первого приоритета [14](14_FULL_SCOPE_RECHECK.md).

## Пользовательский результат

- **Ctrl+K / Поиск и команды:** у поддерживаемого результата задачи, заметки, проекта или списка есть отдельная кнопка «⋯» с командами новой вкладки, открытия рядом и отдельного окна. Выбор команды закрывает палитру; обычное нажатие по результату и Enter в поисковой строке сохраняют прежний переход.
- **Проект → Материалы:** такие же команды доступны у заметок и в ленте, и в колонках. Привязка к проекту остаётся прежней; открывается существующая заметка с исходным ID.
- **Связанные записи:** используют тот же компонент ObjectOpenMenu, без отдельной копии набора действий.

Открытие из поиска может оставить редактор задачи рядом с заметкой, включая неудачно сохранённый ввод. Повторное открытие переводит фокус на уже существующую панель согласно прежней политике Dockview. Возврат в материалы через дерево пространства открывает прежнюю панель. Это явная навигация по существующим вкладкам, не новая история «назад/вперёд» и не восстановление после перезапуска.

## Устойчивость и границы

Строка результата поиска ключуется по entityKey, а не по источнику результата: когда серверный результат заменяет локальный для того же объекта, меню не размонтируется. Проверка специально удерживает серверный ответ до открытия меню, затем меняет подпись результата в синтетическом ответе и проверяет сохранность меню.

Команды используют публичный ViewRef/openObject этапа 15 и существующий placePanel. Workspace/module/plugin checks и guards читаются при исполнении. Неподдерживаемый самостоятельный вид не получает фиктивных команд: документы/события/операции в материалах и поиске сохраняют прежнее открытие. В одиночных detached-окнах без Workbench-host меню компоновки скрыто.

Меню находится рядом с основной кнопкой записи, не вложено в неё. Новый компонент не меняет бизнес-логику, поиск API, сортировку результатов, порядок материалов, ownership, данные или preferences. Новых зависимостей/миграций нет. Основной checkout Desktop/ORION и его БД не менялись.

## Проверка

Финальные проверки: 809 unit-тестов / 105 файлов, 10 plugin contract tests, 63 browser-сценария / 0 ошибок, typecheck, architecture, lint (0 ошибок и 2 прежних предупреждения), pnpm build (API/web) и desktop static export прошли.

Итоговые значения: [validation.json](evidence/object-entry-points/validation.json). Снимки: [default-full](evidence/object-entry-points/object-entries-default-full.png), [plugins-off](evidence/object-entry-points/object-entries-plugins-off.png).

Новые сценарии проверяют оба профиля: серверное обновление открытого меню; поиск задачи → самостоятельная вкладка; ошибка autosave → Ctrl+K → заметка справа с сохранённым черновиком задачи; открытие той же заметки из материалов без второго редактора; возврат к материалам и переключение на колонки; отдельное окно с теми же workspace/ID; retry сохранения исходной задачи; точные количества сущностей без новых копий.

Применяются реальные API/БД в изолированной среде web 3110 / API 4100 / PostgreSQL 5547 и синтетические аккаунты. В проверке замены локального результата серверным модифицируется только тестовый ответ поиска, не запись в БД. Сценарии этапа 15 также остаются в общем browser regression. Native Tauri и физические мониторы не проверялись.

## Оставшееся

Календарь, другие точки входа и самостоятельный вид документа; полная композиция каталога объектов/видов; история переходов; сериализуемое view state с фильтрами/масштабом/скроллом и recovery окон. Общая внутренняя визуальная миграция и темы/overrides остаются отдельными этапами. Этот срез не закрывает весь маршрут работы с объектами.
