# 15. Связанные объекты: вкладка, рядом, отдельное окно

Дата: 2026-10-16. Основа: `49d4442`. Первый исполнимый срез приоритета 1 из [полной сверки](14_FULL_SCOPE_RECHECK.md), не завершение общей объектной среды.

## Что доступно

В основном Workbench у связанной задачи, заметки, проекта или списка появилось меню «⋯»: **Открыть в новой вкладке / Открыть рядом / Открыть в отдельном окне**. Например: Задачи → выбрать задачу → Связи → «⋯» у связанной заметки → Открыть рядом. Обычное нажатие на название сохраняет прежний переход через openEntity.

Открываются существующие самостоятельные панели над теми же записями. Повторный запрос вкладки/открытия рядом фокусирует уже открытую панель; не создаёт копию объекта и не переносит существующую панель в другую группу. Отдельное окно — отдельный экземпляр вида, над тем же API и ID.

На узком экране применяется существующий однопанельный режим. Если переход закроет панель с несохранённым вводом, он останавливается с объяснением. На широком экране источник остаётся на месте, включая текст после неудачного autosave. Кнопки и меню больше не теряют Enter из-за глобальных горячих клавиш списка задач.

## Контракт и безопасность

- `@orion/shared-types`: строгие objectRefSchema / viewRefSchema и типы ObjectRef, ViewRef, ObjectOpenMode. Адрес содержит workspaceId, entityType, entityId и viewId. ID записей — UUID; название используется только как подсказка заголовка.
- Текущий адаптер поддерживает detail для task/note/project/list и существующие виды проекта tasks/materials/plan/access. Неизвестные виды и объекты другого workspace отклоняются; автоматического перехода в чужое пространство нет. Документы и прочие типы сохраняют прежний путь без обещания неподдерживаемой самостоятельной панели.
- Команда openObject добавлена совместимо к panel-bus и разрешённому публичному host-api. Она использует прежний Dockview placePanel, модульные/plugin gates и guards черновиков. Реестр не знает бизнес-логики объектов или конкретных плагинов.
- Доступность проверяется повторно при выполнении команды, по текущим значениям workspace/capabilities, а не по захваченным при старте. API редакторов по-прежнему авторизует чтение и запись.
- Отдельное окно получает workspace/instance через существующий panelWindowUrl. Новые меню компоновки скрыты в одиночном detached-окне без Workbench-host: не показываем команды, которые там не исполнятся. Старые сценарии этого окна не переработаны данным срезом.
- Хранилище, бизнес-операции, схема БД, зависимости и сохранённые пользовательские настройки не менялись. Основной Desktop/ORION и его БД не затронуты.

## Границы и продолжение

Это начало общего object/view contract. Пока нет сериализованного PanelInstance/Layout с view state, истории контекстов «назад/вперёд», восстановления фильтров/скролла/набора окон, mixed-space или общей миграции всех точек открытия. Общая команда ещё не заменяет навигацию из календаря, поиска и проектов. Полная цепочка проект → задача → документ/заметка → возврат остаётся следующим продолжением, с опорой на этот адрес/команду и существующие панели.

Следующий срез должен подключать согласованные точки входа, затем описать и реализовать сохранение состояния вида и историю контекстов. Не сохранять несохранённый текст редактора в новое хранилище без отдельного контракта. Визуальная миграция внутренних экранов, темы/overrides и native recovery остаются в карте этапов 11/14.
