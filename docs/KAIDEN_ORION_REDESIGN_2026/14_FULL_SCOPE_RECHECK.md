## Главный незавершённый результат

Orion должен стать рабочей средой объектов: проект → задача → связанный документ/заметка → возврат к прежнему состоянию; несколько связанных представлений рядом, понятный контекст и восстановление после перезапуска. Новая палитра, rail, метаданные заголовка и существующий Dockview дают основу, но сами по себе этот результат не закрывают. Продолжение не должно сводиться к библиотеке тем.

## Предложения исходного обсуждения, которые нельзя потерять

История перемещения по объектам и контекстам; настраиваемые группы/закрепления объектов; плавный переход от одной основной области к расширенной компоновке; режим фокуса; полезные конфигурации «Разработка / Планирование / Исследование»; несколько плотностей представления проектов с акцентом на следующий шаг и блокировки. Они требуют явного сопоставления с существующими возможностями и отдельного описания приёмки, а не автоматической реализации всей идеи.

Precision — визуальная основа. Command и Atlas в исходном тексте — направления для насыщенной работы и навигации по связям, а не ещё две цветовые темы. Карты зависимостей, аналитика, agent dashboard, автоматическое предложение окружения и структурные действия агента остаются отдельными контрактами/ADR/фазой 6 там, где нет готового API. Существующие графы/агентские функции сохраняются; отсутствие нового редизайна не означает отсутствие функций в продукте.

## Проверенные опорные места кода

- `apps/web/lib/panel-bus.ts`: openEntity отправляет task/note/document в соответствующие focus channels; проекты открывает собственными instance-панелями. Это навигационные сигналы, не сохранённый каталог ViewRef.
- `apps/web/lib/panel-registry.ts`: самостоятельные task/note и виды проекта уже зарегистрированы. Их наличие нужно использовать и проверять, а не объявлять будущей функцией целиком.
- `packages/core-react/src/object-context-store.ts`: window-local Map с метаданными текущего редактора и saveState. Здесь нет сериализованной модели вида с фильтрами/скроллом.
- `apps/web/lib/dock-layout-key.ts`, `named-layouts.ts`, `app/(app)/layout.tsx`: есть локальная геометрия/именованные layout, ключ по user/workspace/purpose; это не полное device/window recovery объектов.
- `apps/web/components/workspace-context.tsx`: дерево проектов/видов, локальные pins проектов; не универсальный редактор навигационного дерева.
- `apps/web/lib/command-center.tsx`: Ctrl+K уже существует, поиск получает текущий workspace. Его нельзя записывать как полностью отсутствующую возможность.

## Скорректированный порядок продолжения

1. **Основной сквозной сценарий оболочки:** адрес объекта/вида и единые команды открытия на уже существующих панелях, затем проект → задача → связанная заметка/документ → возврат. Критерии: тот же ID/владелец, открытие рядом и с клавиатуры, отсутствие потери ввода, работа без необязательных плагинов.
2. **Восстановление одного пространства:** выбранный объект/вид и применимое view state, история контекстов как отдельный описанный срез, безопасные deleted/denied/disabled состояния. Не сохранять несохранённый текст неоговорённым способом.
3. **Эталонный рабочий экран и миграция модулей:** довести единую композицию навигации, содержимого и инспектора; проекты → задачи → заметки/документы → календарь. Сравнивать с исходным визуальным направлением и functional baseline, а не только считать тесты.
4. **Оконная модель и Theme Engine:** завершать отдельными срезами с их gates; независимость window/device, native/multi-monitor, полная библиотека/overrides/контраст. Библиотека палитр не должна вытеснить работу над объектной средой.
5. **Поздние расширения:** mixed-space, операции между пространствами, временные сессии, Atlas/Command/agent-инструменты — после контрактов/ACL и нужных ADR.
